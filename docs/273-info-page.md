# #273 資訊頁分類與更新紀錄

## 定稿依據
K 2026-10-17 完成訪談與示意確認；本票承接原「分析頁整理」。底部四格與視窗顯示方式已確認，保持不動。本次不另開整理票。

## 問題與目標
原分析頁把不同使用時機的統計、名冊與資料檢查擠在長頁。改為「資訊分類首頁 → 子頁」，供志工平常看整體狀況，以及整理資料時查離所與缺漏。

## What to build
### 資訊首頁
依序提供五個入口，每類以名稱與少量摘要呈現，詳細圖表與名單留在子頁：
1. **在所統計**：在所數、在所時間分布、在所最久、各區及公母在所時間比較。
2. **離所紀錄**：沿用年度摘要、原因、離所名冊及其搜尋／年份／原因篩選；進頁時名冊預設展開，可收起（#446）。
3. **活動紀錄**：串接 #270；每場以日期與活動類型作標題，標題下直接並列出席的狗，不再點進場次才看名單。
4. **資料檢查**：沿用缺照片、缺介紹等既有缺資料項目與對應狗名單。
5. **更新紀錄**：分「網站更新／資料編輯」。

保留已確認的底部四格與視窗模式，子頁能回資訊。首頁摘要用真實可讀取的數字；未載入、讀取失敗或沒有資料須明確區分，不把失敗顯示成零。數值、排版細節依既有設計規範處理，不將示意數字寫死。

### 拿掉的內容
資訊不提供「溜狗狀況」分類、每日遛狗圖表、本月遛狗統計或久未溜數字／跳轉。先前這些示意與 Q5 討論已被 K 的最新決定覆蓋。不刪遛狗紀錄、不更動既有遛狗表的登記或查看能力。

### 活動：手機與桌機都可操作
- 手機可新增活動、修改活動及出席名單、刪除活動；桌機也可操作。
- 活動日期、類型（動保小小兵／認養會）、出席狗永久 ID／待對應名字與舊名單匯入沿用 #270 與 ADR 0002。
- 編輯前選好身分，不加通關碼；新增／修改／刪除留下操作紀錄，沿用 ADR 0004。
- 不另建一套活動資料或編輯紀錄；不寫試算表。正式舊資料匯入仍是另外明確執行的動作，不在部署或同步時自動執行。
- 本次覆蓋舊版「活動只在桌機、獨立於分析」的介面限制；不變更狗卡上不顯示活動資訊的既有約束。

### 更新紀錄
- **網站更新**：每次正式改版上線後新增一則，顯示日期與志工看得懂的新增功能、介面調整或修正。與正式版本一起提供；未上線內容不得當作已發布，不能直接公開原始 commit、內部開發筆記或敏感資料。不因本需求建立定時排程。
- **資料編輯**：沿用既有 edits.html／edits.js／GET /api/edits，顯示操作者、時間、改了什麼與改前／改後，包含沒有對應狗的既有操作種類；溜狗打卡不混入。不另建紀錄來源。
- 更新紀錄兩類需能清楚區分，不將網站改版塞進資料編輯事件冒充某隻狗的修改。

## 範圍與分工
- 本票負責資訊架構、入口、子頁呈現與更新紀錄整合；活動核心與資料／API 契約仍由既有 #270 承接，不新增票或重複後端。
- 常遛狗群的照片／位置／批次勾選登記是另一段已提出需求，不混入本票。
- 守 docs/DESIGN_GUIDE.md：安靜實用、既有視覺、44×44px 以上點擊區、底部安全區、名稱不被裁切。
- 不更換資料來源或擴大試算表寫入範圍，不授權合併、部署、正式資料匯入。
- 開發前重新核對當時分支與原始碼，保留其他未提交工作；先前示意不是正式環境。

## Acceptance criteria
- [ ] 資訊首頁有上述五類與少量摘要，沒有「溜狗狀況」或該類圖表。
- [ ] 每個入口可開正確內容並返回資訊；已確認的主導覽與視窗模式保持一致。
- [ ] 在所統計、離所紀錄與資料檢查保留各自既有內容與操作，沒有因分類遺漏既有資訊。
- [ ] 每場活動標題下直接看得到出席狗，手機與桌機可新增／修改／刪除；身分、錯誤與操作紀錄遵循既有規則。
- [ ] 更新紀錄清楚分網站更新／資料編輯，後者沿用既有編輯資料且包含改前／改後。
- [ ] 每次正式改版有對應的日期與使用者可理解的更新，不顯示未上線變更。
- [ ] 載入、空資料、讀取／寫入失敗都能辨識，沒有把失敗當零或誤報成功。
- [ ] 手機 320px／390px 與桌機回歸，操作區、文字與安全區符合設計規範。
- [ ] AGENTS.md 的 Node 與網頁測試全過；用 mock 驗證活動與資料編輯整合，正式寫入另需明確授權。

## Blocked by
- #270 的活動資料與 API 能力。資訊架構可先開發，但活動完整驗收及本票完成須等活動整合通過。
