# 狗資料編輯（#566）

此文件記錄程式契約及待核准的正式步驟，不表示正式環境已套用或部署。

> 2026-10-26 現況：「待 K 核准的正式步驟」第 1–3 步已完成：PR #580 合併，migration 0009 套用（Actions run 40208410962），志工站與管理站已部署。K 登入後的寫入驗收還沒做（記在 #562）。

## 操作與來源

經 Access 驗證的管理者在狗表按「編輯」，右側抽屜一次列出介紹、休養、固定照顧、性別、出入所紀錄、照片（#624；#639 起編號併進出入所紀錄）。介紹、休養、固定照顧、性別改完直接可存，行內標改前→改後；出入所紀錄、照片要先預覽。一次改多欄時依序送出，每欄仍是一筆交易，帶上一筆回應的 revision；中途失敗或 409 就停下，已存的照常生效、還沒存的草稿保留。狗名、目前編號、籠位、試算表備註及離所判讀只讀。目前編號不能移除，舊編號不能搶其他狗的歸屬；補登紀錄不改離所模型。

介紹只寫狗自己的個性、狀況，入所、退回、離所的經過寫在出入所紀錄的原因（ADR 0022）。逐次入所事件（#285，`v3_intake_events`）#667 起不再讀寫，舊網頁存介紹時送的 `events` 收下不理；表等下一張 PR 才 DROP。休養沿用有效日期、今天至 180 天、原因 40 字；介紹最多 1000 字。性別只限 Access 管理者，以永久 dog_id 定位，支援無編號狗。

v3_dogs.sex 是目前性別的唯一維護來源。承接 #575 已接受的舊複本核對與單一來源決策；0004 已從 schema 移除試算表性別副本，本票不重新造一份舊值，也不把空白蓋到有效值。管理者以目前正本逐隻確認，不依名字猜測。主清單、離所目前資訊及圖鑑取正本，離所 last_sex 快照保持原值。GAS 更新、換號、再入所不寫狗正本性別。

## 出入所紀錄（#639，ADR 0021）

一個編號就是一筆出入所紀錄，查不到編號的那次編號空著。管理網站抽屜與志工網站詳細資訊編輯時都是同一張表：編號（可空）、入所日、入所原因、出所日、離所原因。入所原因一律手填；離所原因有離所紀錄就照它，沒有就手填（K 2026-10-26）。志工網站閱讀時一行一件事（日期、入所／離所、原因），介紹裡的逐次事件也排進來（`detail-stays.js` 的 `stayLines`）。程式在 `worker/src/stays.js`。

- 存法：`v3_stays` 一隻狗一列，只存手填的部分：沒編號的 `{ number: '', in, out, reason, outReason? }`；有編號、手填過出所日、入所原因或離所原因的同樣子（`outReason` 有填才帶；有離所紀錄時 `out` 存空的、不存 `outReason`；`in` 就是編號日期，讓還沒部署的舊版程式讀到仍是完整的一筆）。編號仍在 `v3_dog_numbers`（主清單、離所、溜狗紀錄都用它找狗）。
- 讀法（`stayTable`）：這隻狗每個編號一列，入所日是編號前 8 碼（看不出日期就空著）；那個編號有離所紀錄時出所日照離所紀錄（`departed: true`，畫面唯讀），離所原因放 `departure`；沒有的手填離所原因放 `outReason`；入所原因（`reason`）每列都用手填的，有離所紀錄的那列也能填、會存。再加上沒編號的手填紀錄，照入所日排、看不出日期的排最後。
- 舊資料：舊格式（沒有 `number` 鍵，#639 以前或還沒重新部署的管理網站寫的）、入所日跟這隻狗某個編號日期一樣的手填紀錄，讀的時候接到那個編號（測試庫只有納卡西 2026-04-21 對 2026042101）。新格式的沒編號紀錄就算同一天也維持沒編號。不搬資料、不寫 migration；之後有人存這隻狗的出入所表時才寫成新格式。
- 寫法：欄位 `stays` 整張表一筆交易：補編號就是加一列（寫 `v3_dog_numbers`）、刪那一列就是刪那個編號；目前編號、有離所紀錄的編號不能刪（409）；新編號要 10 碼有效日期、不能晚於目前編號、不能是別隻的（409）。跟看到的一樣就不寫。修改紀錄 kind 仍是 `stays`，改前／改後存整張表。
- 志工 `PUT /stays/編號` 帶打開時看到的表（`before`），跟 D1 現在的比（只比編號、日期、原因），不同就 409。舊版網頁的 `POST|DELETE /former/編號` 還收（跟出入所紀錄同一個開關），畫面上已經沒有入口。
- 資料包：在所的狗只有手填過或有離所紀錄時才帶 `stays`（整張表），只有編號的狗前端用編號排出來（`BQDates.stayRows`）；離所的狗一定帶。離所紀錄一改，既有的 `dog_edit_v3_dog_departures_*` 讓 revision 加 1，`packs_v3_dog_edit_state_UPDATE` 就讓 small 與這隻狗每一年的離所資料包失效，不用新觸發器。

## 一致性與紀錄

每隻狗有 v3_dog_edit_state.revision。管理者與志工都帶讀取時版本；志工草稿另外保留開啟時版本，背景重新讀取不會偷偷升級既有草稿。交易先以版本取得 token，欄位修改及 v3_edit_log、v3_dog_edit_actors 在同一 D1 batch 提交。紀錄失敗整筆回復；舊版請求缺版本請重新讀取，不退回無保護寫入。無差異不改資料或新增紀錄。

GAS 的身分敏感寫入在交易內驗證已讀版本；人工修改先提交時，GAS 不 ack，保留待送內容重試。既有當日登記、復原、寫回及活動 API 不換成狗編輯服務。志工七項 gate 仍在原路由驗證，管理者只由 Access 入口取得能力，公開 host 不相信 email、JWT 或 admin 宣稱。

公開紀錄只顯示「管理者」與來源 access；經驗證的 subject、email 存於受保護的 v3_dog_edit_actors。志工來源是 volunteer，舊紀錄標為 legacy，不假稱自行選名是已驗證登入。後續紀錄查詢介面由 #567 處理。

## 照片與復原

兩個前端共用 Canvas JPEG／短邊 300px 縮圖模組，縮圖失敗可只送原圖；原圖 2 MB、縮圖 512 KB。不自動呼叫 GitHub Actions，人工補圖 workflow 保留。照片缺 R2 時拒絕寫入，避免退回無法和 D1 紀錄一致的 GitHub 寫入。

原圖／縮圖使用同一個不可覆寫的新版本鍵。先備份舊照片與縮圖到既有垃圾桶，再存新物件，最後以 CAS 提交 D1 引用和紀錄。任何中途失敗都保留舊引用；已儲存但未被引用的新物件保留 dogId、stagedAt、operation metadata 供人工追查，不新增掃描排程。重送舊版本回 409，不重複提交。

資料包帶主照片版本，舊照片網址依版本找到對應原圖／縮圖，不把不同替換的版本混配。垃圾桶預覽與復原受 Access 保護且核對 dog_id；復原也產生新版本，不消耗原備份。舊版本沿用 30 天垃圾桶窗口；既有每月清理只在過期且不再是主照片時刪其不可覆寫版本物件，不清舊固定路徑，不新增 Cron。失敗暫存物件需要人工核對後處理。

## 成本與界線

單狗讀取是一個帶 dog_id 主鍵條件的快照 SELECT；子查詢只讀該狗的編號、事件、休養、介紹與主照片。主清單的 revision／性別／照片版本併入既有資料包讀取，不逐列請求。搜尋、篩選、排序仍在已載入清單處理。照片 HTTP 讀取為舊網址查一次索引引用；不可覆寫版本可使用既有 Cache API。

以固定照顧為代表的 API 測試比較 10／100 隻無關狗，SQL 計畫走主鍵／索引，讀寫量相同；含測試用戶端讀版本共回傳 6 列，實際 API 5 列。一次有差異修改在隔離 SQLite 計 8 次列變更：狗資料 1、CAS／revision 2、來源與 revision 的 small 失效 3、公開與私人來源紀錄 2。無差異 0 寫。其他欄位依實際變動筆數及既有 pack 觸發器計；編號只增刪差異，事件只有志工明確修改時才寫。

照片替換多 1–2 次新物件寫入，舊圖存在時另有 1–2 次垃圾桶備份；D1 引用及紀錄一起提交。既有每月清理對過期不可覆寫版本增加一個主鍵引用檢查。上述是隔離測試及程式邊界，不是正式 D1／R2 計費 meta；索引維護、實際掃描及儲存費用以 Cloudflare 為準。沒有量到精確美元成本。

## 待 K 核准的正式步驟

1. 審查草稿 PR 與驗收證據，再決定轉正式／合併。
2. 核對當時主線 migration，使用既有手動 workflow 套 0009_dog_edit.sql；先備份及記 Time Travel 書籤。它新增 CAS／guard／私人來源及照片引用表、觸發器，為既有狗建立狀態並讓舊資料包失效，不改性別內容。
3. 部署志工及管理 Worker。使用已驗證 Access 設定，確認替代網址仍拒絕未授權存取；不新增機器金鑰至管理前端。
4. 正式驗收另經授權執行，不能用正式資料做開發測試。確認舊頁請求會提示重讀，前後紀錄可追查、性別一致、登記／復原／GAS 正常。

回復優先回部署並保留新增資料；舊版部署無法提供本票的一致性保證，需暫停人用狗編輯直到補修。不要 DROP 或整庫覆寫；Time Travel 會影響之後的正式寫入，只作 K 決定的災難回復。

## 合併重複的狗（K 2026-10-26）

試算表改編號或先打名字後補編號時，同步會多建一隻狗、舊的留著（#621）。K 選擇先手動合併；合併後刪掉被併的那筆、留完整快照可還原。程式在 `worker/src/dog-merge.js`。
「自動認改編號之後再說」已由 ADR 0025 重新開放（#768）：試算表上不見的列先當候選、約 10～20 分鐘後確認移出主清單（#771），舊的那隻變成待核對，就能在這裡合併。同籠位自動合併已實作（#773）：同一個籠位要新建狗、剛好只有一個不在表上的列，系統建新狗後把舊列移出主清單、併到新狗，修改紀錄記「系統自動合併」（操作者「系統自動判斷」），跟管理者合併一樣可以取消合併。規則見 ADR 0025「後面的票」。「可能是同一隻」的配對是後面的票。

- 入口：管理網站狗資料編輯抽屜「合併重複的狗」；待補清單「可能重複」列出同名、一隻在所一隻不在所的配對。只有 Access 管理者，志工網站沒有入口。
- 誰留下：主清單上的狗由試算表管，只能當留下的那隻；兩隻都在主清單不能合併。兩隻都不在主清單時，留下在抽屜下拉選的那隻。
- 搬什麼：編號（變舊編號）、溜狗紀錄、介紹、休養、出入所紀錄、照片、離所紀錄、活動出席、常溜、開卡、今日溜狗狀態的 dog_id。溜狗紀錄不丟：同一天兩邊都有時，被併那隻那天的志工接在後面（`position` 往後排），同一天同一位志工只記一次。只能留一份的（介紹、休養、同一位志工的常溜／開卡、同一個編號的離所紀錄）留「留下那隻」的，被併的值只在快照裡，預覽會列出不採用的介紹、休養內容。出入所紀錄（ADR 0021，#639）兩邊全部接在一起：編號跟著搬過去、各自是一列，兩邊手填的紀錄併成留下那隻的一列；留下那隻原本那列存在 merge 紀錄的 after.replaced，取消合併時放回去。合併後留下那隻又改過出入所表的話，保留改過的，但拿掉被併那隻的手填紀錄與牠編號的那幾筆（`withoutStays`），兩隻不會重複。照片只當一般照片搬過去，不蓋掉留下那隻的主照片（可能在舊固定路徑）。入所事件不搬（#667）：被併那隻還留著的列直接刪掉，免得外鍵擋住刪狗；#667 以前的合併紀錄快照裡有入所事件的，取消合併時跳過、不插回。沒編號時溜的紀錄補成留下那隻的目前編號；被併那隻離所過、留下那隻在所時，離所紀錄記用哪個編號回來（同再入所）。
- 一致性：預覽回兩隻的 revision，合併時兩隻的版本都放進有條件 batch（`worker/src/conditional-batch.js`，#745）擋；寫入是一個 D1 batch，每張表固定 1–2 句（整批列用 `json_each` 帶入），不隨列數變多。讀完後被併那隻又多了列，刪狗會被外鍵擋下、整批不寫。合併後留下那隻 revision 再加 1（溜狗紀錄沒有 revision 觸發器），開著的草稿會 409。
- 紀錄：`v3_edit_log` 一筆 `merge`，dog_id＝留下那隻；before 存被併那隻的 v3_dogs 與每張表的原始列（snapshot），after 存搬過去後的列（rows）與筆數。登入帳號照舊存 `v3_dog_edit_actors`。公開的 `/api/edits` 只回摘要，拿掉 snapshot、rows。
- 取消合併：修改紀錄頁的合併狗、系統自動合併列按兩次「取消合併」。照快照重建被併那隻、插回原始列；搬過去的列只有「每一欄都跟合併時一樣」才刪，留下那隻後來改過的列不動。插不回去（例如編號後來給了別隻）整批不寫、回 409。同一隻之後又合併或取消過，只能從最新一筆處理。
- 快取：各表既有 packs／walkpack／版本觸發器讓資料包失效，不新增 migration。
- D1 讀寫量：讀寫都先用 dog_id 篩、走索引；`v3_photos`、`v3_volunteer_favorites`、`v3_volunteer_cards`、`v3_card_opened`、`v3_walk_state` 沒有 dog_id 開頭的索引，會整張掃（列在 `dog-merge.js` 的 `SCAN_OK`，附理由）。合併是管理者偶爾按的操作、這幾張表都小，不為它加索引（加索引每次寫入多一列）。`dog-merge.test.mjs` 用查詢計畫確認其他表都走索引，並量每張表都有資料時合併與取消合併都在免費方案每次呼叫 50 句以內。

公開資料包包含 editRevision，因此 revision 的每次實際變更也會失效該狗在所／離所資料包，不能只看儲存 token。保留既有來源觸發器，版本號可能同時由來源與 CAS／revision 各增加；它是不可解讀的失效版本，不是編輯次數。這些成本已納入量測；未變更欄位的 SQL UPDATE 不額外增加狗 revision。不可覆寫照片版本直接按主鍵解析，不依賴可刪除的舊編號映射。
