# 0023 分享網站：正式網址不進 repo，分享次數只記每天總數

狀態：已確認，日期：2026-10-28，K 在需求訪談中逐題回答（研究見 `docs/research/2026-10-28-share-button-url-and-web-share.md`）。

起因：K 想讓志工從手機版直接把網站分享給其他志工，拉更多人來溜狗。這裡分享的是**網站本身**，不是某一隻狗；ADR 0022 提到的「分享狗的介紹」是另一件事，還沒開始。

- **按鈕在手機版資訊頁**：資訊頁首頁多一張「分享網站連結」，跟「使用說明」放一起；電腦版不放。
- **怎麼分享**：先用手機的分享選單（`navigator.share`），不支援就複製連結並顯示「已複製」，都不行就把網址顯示出來讓志工長按複製。文字是「來去板橋動物之家遛狗吧 🐕」加網址（全站「溜／遛」統一另開票）。
- **網址由 Worker 給**：`shareUrl = env.SHARE_URL || 請求本身的 origin`，跟功能開關一起在載入時拿好（分享和複製都要在點擊當下呼叫，不能先等網路）。正式網址不寫進公開 repo（#493）：正式站不設 `SHARE_URL`，回自己的網址；測試網站和 PR 預覽部署時用 `--var` 從 GitHub Secret `WORKERS_SUBDOMAIN` 組出正式網址，跟管理網站的 `SITE_URL` 同一種做法。測試站按分享傳出去的也是正式網址。
- **功能開關 `showShare`**：管理網站「志工網站設定」可以開關，預設關閉，K 實機測過再打開。D1 那列設定沒有這個鍵時，Worker 讀的時候補成關閉（`ADDED_DEFAULTS`），管理網站第一次存設定就寫進去；不用 migration 改那一列（改了會觸發設定紀錄，也要動版本號）。
- **分享次數只記每天總數和方式**：方式分「分享」（分享選單回報成功）和「複製」（複製成功）；取消（`AbortError`）不算。不記名字、不記代號。存 D1 兩張小表：每天一列（日期、方式、次數）和總數一列（方式、次數），`POST /api/share` 兩列各加 1，一天最多幾筆寫入，不影響 ADR 0008 的寫入預算。管理網站「志工網站設定」頁，在「分享網站連結」開關下面顯示總數和最近 30 天每天的次數（原本說放首頁；首頁其實是狗資料表，K 2026-10-28 改成放開關旁）。開關關著時 `POST /api/share` 回 403；預覽版本來就不能寫。

## 「分享成功」的意思

分享選單回報成功只代表志工**選了分享對象**（Android 選了 App 就算），不代表在 LINE 裡按了送出，網頁無從得知（研究檔第 4 節）。所以分享次數是「有人想分享」的指標，不是「有人收到」；iPhone 和 Android 的數字也不能直接比。

## 考慮過的做法

- **前端用 `location.origin`**：最簡單，但測試站和 PR 預覽按分享會傳出測試網址。K 不選。
- **Worker 回應 HTML 時插入網址**：正式網頁現在是靜態檔、不經過 Worker；改成經過 Worker，每次開頁都算 Worker 請求，免費額度用完整頁回 429。不選。
- **記誰分享的**：可以看出誰拉了人進來，但需求只是看功能有沒有人用；少存個人資料。K 不選。
- **只要按了按鈕就記**：會把開了又取消的也算進去。K 不選。

## 後果

- LINE 內建瀏覽器有沒有分享選單、能不能複製，查不到官方資料，要 K 用 iPhone 和 Android 在 LINE 裡實機測；不行就走顯示網址那條路。
- 測試網站、PR 預覽的部署設定多一個 `--var`；正式部署不變。
