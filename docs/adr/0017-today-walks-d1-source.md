# 0017 今日溜狗以 D1 為正本，背景寫回試算表

狀態：產品決策已確認；本技術修訂提案待 K 確認，尚未實作或合併。2026-10-21，#441；承接 PR #439 的同名草稿。

今日狀態原先由試算表、D1 暫時消息與手機紀錄合併，容易互相覆蓋。K 已決定以 D1 保存網站唯一可讀的有效狀態，試算表保留人工修正入口；網站操作先可靠存入 D1，再背景寫回。這改變成功承諾與同步方向，不能只替換讀取來源。

## 已確認的產品決策

- D1 接受登記、名單修改或復原後，操作手機才反映成功；其他手機下一次讀取更新。前景每分鐘檢查版本，切回前景距上次讀取超過 30 秒立即讀；不增加 SSE、WebSocket、Durable Object。
- **每隻狗只呈現最新一次**（K 本輪確認）：網站最新狀態與試算表主清單使用同一份最新有效日期／名單。昨晚甲的寫回尚未完成，今天乙已登記，就顯示今天乙；昨日工作不能把它改回昨天甲。「最新」指 D1 目前接受的版本，不是最後抵達的網路請求，也不是一律選最大的日期。人工改成較早日期或復原仍有效。同狗同日多人名單規則不變；本次沒有刪除既有歷史資料或新增歷史展示需求。
- 寫回未完成顯示安靜小字「試算表同步中」；失敗顯示「試算表尚未同步，會自動重試」。D1 已接受的操作不因寫回失敗退回，不要求重按。
- 人工刪名、清空及改日期有效，先納入 D1，再供手機讀取；不以名單無條件聯集復活被刪的名字。兩人同狗同日登記則保留兩名，名字中間空白沿用拆成兩人的規則。
- ADR 0016 的復原權限、只限今天、找回前次日期及名單、被別人改過即停止與編輯紀錄均保留。
- 試算表不加保護、不新增控制欄；寫入只限 ADR 0006 範圍。以編號對狗，無編號才用狗名，遇到重複或不明對應即停止該狗寫入。

## 工程方案提案

1. **狀態和待寫回工作一起提交。** 以狗為序列化單位，操作日期另外保存。有效狀態、單調版本、請求識別及結果、編輯紀錄（適用時）、待寫回目標與讀取投影在同一個 D1 原子交易接受。重送同一請求回原結果，不重複寫入；同名重按未改狀態時不製造新工作。復原／改名單帶預期版本，衝突回目前狀態，不自動重放。
2. **寫回整個日期與名單，不做追加。** 每隻狗只派送一個有效版本；新版本使舊待寫回工作失效。派送前檢查版本，Apps Script 比對預期日期／名單才替換，回傳直接讀到的結果；D1 回收工作時再核對版本。逾時表示結果未知，先查明現況，不能直接假定未寫入。
3. **用確認狀態取代固定秒數寬限期。** 保存上次雙方確認一致值、目前 D1 值、待寫回目標及已取得的寫入回執。未確認期間，gviz 舊快照不能撤銷 D1 新操作；直接讀值／寫入回執與後續讀回才能推進一致基準。8.004 秒樣本不是延遲上界，不訂「等八秒後覆蓋」。
4. **人工修改採三方比較。** 沒有待寫回時，確認的新試算表值經 D1 接受成為新版本。有待寫回時，比較一致基準、D1 變更與直接讀到的試算表變更：不同名字的增刪可合併，同一名字的明確人工刪除不得被舊工作加回；日期變更與整格清空視為整筆人工修正，取代之前尚未完成的目標。不能區分舊快照與人工操作時保留工作、重新直接讀取，不靠時間猜。直接編輯與寫回之間的競爭限制見下節。
5. **通知立即比對，Cron 補漏及重試。** 通知驗證後啟動精簡主清單比對，不只記旗標等 GitHub。提案每分鐘 Cron，一輪最多派送 10 隻狗，超出留待下輪；失敗依每筆 next-attempt 排程，1、2、4、8、15 分鐘後重試，之後維持 15 分鐘，不能永久丟棄。重複通知合併，無變化不更新資料或游標；不以降低頻率掩蓋單次 CPU 超限。
6. **冷讀不逐狗掃描。** 今日有效狀態及必要的上次溜覆寫資料，在接受變更時同步維護版本化 D1 資料包；請求只讀版本與所需分段，不能每次 miss 重掃 200 隻。分段沿用 ADR 0009 上限。資料包版本須與內容一致；不同日期不能共用同一份快取。
7. **同一欄位只留一個寫入責任。** 新路徑負責今日狀態、待寫回、人工修正及跨日交接；舊同步不能再用試算表舊快照覆蓋這些欄位。狗清單、照片等既有同步照舊，歷史資料依 ADR 0010／0013 保存。跨日不刪未完成工作，不把昨天的操作日期改成今天。

## 尚未驗證的限制與啟用門檻

工程提案補充：接收端在 script lock 內重新向 D1 取得最新目標，避免直接重放延遲請求內的舊整格值；最新有效狀態帶原操作日期持久保存，午夜只換今天判定，不搬移或清空最新狀態。今天已有較新登記時，昨天未完成工作不能把主清單改回昨天。詳見規格「派送順序、人工衝突與跨日」；最新一次的可見行為已確認，接收端協定尚未實作／驗證，且不能解決人工改格在最後讀寫間隙內被覆蓋的限制。

Apps Script 的 script lock 只序列化程式請求，不能鎖住人工編輯；「讀格子→寫格子」也不是對人工修改的原子比較交換。D1 版本檢查只能避免舊回應改壞 D1，不能自行阻止已送出的舊請求晚到改壞試算表。正式實作必須處理同狗派送互斥、逾時未決及延遲舊請求，並提出人工改格與寫入間競爭的具體保全方式。**目前不能宣稱任意同時手改都不遺失；這是實作前阻擋項，不是重問既定產品決策。** 無法保全時停止該筆自動覆寫並保留可追查現況，不能無限重送整格值。

資料包是減少冷讀列數的設計，尚非正式 CPU 合格證據。既有原型最大分組 P99 10.591 ms，200 列全 miss 的手機輪詢推估 5,427,000 列／日，皆不能當通過免費方案驗收。Cron 頻率、分批與資料包方案為本次提案；啟用前須證明完整管線、帳號共用讀寫／請求預算及觸發器成本符合門檻。新增 D1 寫入遵守 ADR 0008，先預算、只寫差異，超預算保留待處理狀態，不以重試繞過限制。

本輪不追加實測、不部署、不拆票。測試服務保持停用；後續若需補證據，先提出單一問題、最少樣本與停止條件，再取得授權。
