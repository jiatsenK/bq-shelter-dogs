# 0011 沒有舊編號時，可以補登舊入所日

日期：2026-10-16（K 決定，重開 ADR 0005）

ADR 0005 規定入所日只看編號，「不另存一個人工入所日」。實際上，轉所或退養前的舊編號大多已經查不到（例如墨西哥：現在的編號是 2017090508，介紹寫 2015/8/18 入所），只看編號的話，入所多久會一直算錯。K 決定**沒有舊編號的狗，可以直接補登舊入所日**。以後再有轉所或退養回來的狗，還是照 ADR 0005 補舊編號。

取代 ADR 0005 中「也不另存一個人工入所日」這句；0005 其他規定照舊。

- **入所日**改成：現在的編號、舊編號的前 8 碼、補登的舊入所日，三者裡最早的那天。
- 補登的舊入所日存在 D1，指到狗的永久 ID（跟舊編號、ADR 0001 用同一個 ID），不寫試算表（ADR 0006）。
- 一隻狗只存一個舊入所日，要改就直接覆蓋。
- 跟舊編號一樣，**任何人都能補、都能刪**；照 ADR 0004 要先選好名字，每次補、刪都記進編輯紀錄。
- 補登日期不能是未來的日子，也必須早於現在編號的日期，否則擋下來。
- 還是**不從入所介紹的文字自動抓日期**：介紹裡的日期不一定是入所日，年份也可能打錯（百吉、土撥鼠剛好差 365 天）。
- 網站上所有顯示入所日或入所多久的地方（詳細資訊、分析頁、圖鑑）都用同一套算法。

## 後果

- #289 列出的 21 隻（入所介紹的日期比編號早），可以照介紹或收容所資料補登，不用再等找到舊編號。
- 有人補錯的話，排名會跟著錯；要靠編輯紀錄找回原本的值，或直接刪掉重補。
- 多了一張 D1 表，同步前要寫進 `db/compact-schema.sql`；`/api/dogs` 會讀到這張表，所以寫入後要更新版本號（ADR 0009），其他手機才看得到。
