# 0011 每次出入所都可以補登，入所日取最早那次

> 2026-10-26 已由 [ADR 0021](0021-stays-carry-number.md) 修訂：出入所紀錄每筆帶編號（查不到才空著），有編號的那筆入所日就是編號日期；合併重複的狗時兩邊的出入所紀錄合在一起。

日期：2026-10-16（K 決定，重開 ADR 0005）

ADR 0005 規定入所日只看編號，「不另存一個人工入所日」。實際上，轉所或退養前的舊編號大多已經查不到（例如墨西哥：現在的編號是 2017090508，介紹寫 2015/8/18 入所），只看編號的話，入所多久會一直算錯。K 決定改成**每次出入所都可以補登一筆紀錄**；查得到舊編號時，還是照 ADR 0005 補舊編號。

取代 ADR 0005 中「也不另存一個人工入所日」這句；0005 其他規定照舊。

- **出入所紀錄**：每次在所記一筆，內容是入所日、出所日（還在所就留空）、原因（例如流浪、迷路、退養、轉所、整修暫住）。一隻狗可以有好幾筆。
- 存在 D1，指到狗的永久 ID（跟舊編號、ADR 0001 用同一個 ID），不寫試算表（ADR 0006）。為了少讀 D1 列數，**一隻狗只佔一列**，每一次出入所都存在這一列的 JSON 陣列裡；只有補過紀錄的狗才有這一列。
- **入所日**＝現在的編號、舊編號的前 8 碼、出入所紀錄的入所日，三者裡最早的那天。「入所多久」從這天算到今天，中間出所的那段也算進去。
- 跟舊編號一樣，**任何人都能補、改、刪**；照 ADR 0004 要先選好名字，每次都記進編輯紀錄。
- 日期不能是未來的日子；出所日不能早於入所日。
- 詳細資訊會照時間列出每一次出入所。
- 不從入所介紹的文字自動抓日期：介紹裡的日期不一定是入所日，年份也可能打錯（百吉、土撥鼠剛好差 365 天）。
- 網站上所有顯示入所日或入所多久的地方（詳細資訊、分析頁、圖鑑）都用同一套算法。

## 後果

- #289 列出的 21 隻（入所介紹的日期比編號早），可以照介紹或收容所資料補登，不用再等找到舊編號。
- 入所多久不扣出所期間；以後如果要算「實際在所天數」，資料裡已經有出所日，可以再加。
- 有人補錯的話，排名會跟著錯；要靠編輯紀錄找回原本的值，或直接改掉。
- 多了一張 D1 表，同步前要寫進 `db/compact-schema.sql`；`/api/dogs` 會讀到這張表，所以寫入後要更新版本號（ADR 0009），其他手機才看得到。
