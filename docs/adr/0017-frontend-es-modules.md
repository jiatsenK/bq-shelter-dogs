# 0017 前端分段整理，最後改成 ES module

日期：2026-10-22（K 已確認，#471；本 ADR 由 #476 記錄）

前端大檔與其他頁面靠全域名稱、載入順序連接，也有重複的共用邏輯。最終改用 ES module 的 `import`／`export` 明確表達依賴；先分段拆檔，再統一切換載入方式，讓每張 PR 維持小範圍，容易確認網站行為與找出問題。

## 決定

- #471 的第 1～7 項整理期間維持一般 `<script>` 載入。每支新拆出的 JS 檔只在全域公開一個名稱，例如 `BQApi`、`BQDates`、`BQStore`；函式與內部狀態收在該模組內，其他檔透過這個名稱使用它。過渡期仍須維持正確的 script 載入順序。
- 模組介面設計成之後只需改一兩行就能換成 `export` 的形狀，避免再增加散落的全域函式。這是過渡方式，最終目標仍是 ES module。
- 最後一張票再統一改成 `import`／`export`，並確認原本直接讀取主頁大檔的後端匯入腳本仍能運作；那張票可以調整該腳本讀取前端程式的方式。
- 每拆出一支檔案，在 `public/js/README.md` 補一行責任、依賴與載入頁面，並在 AGENTS.md 加一行指向該說明；隨拆檔票更新。

## 整理邊界

整理期間志工看到、操作到的網站行為維持不變，包括畫面、文字、按鍵、後端呼叫內容與手機資料的鍵名、格式。發現網站問題先問 K；K 同意的行為修改留在同一 PR 的獨立 commit，PR 說明列出手機要檢查哪裡；K 決定之後處理的問題另開票。

本決定不包含換框架或新增打包工具。本票只記錄決策，不進行拆檔、切換載入方式或資料改名；其他模組與測試範圍依 #471 及各子票執行。
