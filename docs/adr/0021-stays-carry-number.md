# 0021 一個編號就是一筆出入所紀錄

狀態：已確認，日期：2026-10-26，K 選方向並回答四個邊界問題；還沒實作，實作見 #639。

一個**編號**代表一次**入所**，所以每個編號都是一筆**出入所紀錄**。ADR 0005、0011 把它們分成兩種資料：編號只存號碼，出入所紀錄另外補登、不帶編號。結果同一次在所分在三個地方（編號、離所、出入所紀錄），合併重複的狗時，被併那隻的編號變成只有號碼的舊編號，牠的出入所紀錄還會因為「只留一份」被丟掉（#621 方案乙）。K 決定把兩者當成同一件事：**出入所紀錄每筆帶編號，查不到編號的那次才空著**。

修訂 ADR 0011 的「出入所紀錄」與「入所日」兩條，以及 ADR 0005 的「畫面上只列舊編號和最早入所日」。0005、0011 其他規定照舊。

- **有編號的那筆**：入所日固定是編號前 8 碼，不能另外改。出所日和原因有**離所**紀錄就自動帶，沒有（例如追蹤離所以前的舊編號）才由人手填。
- **沒有編號的那筆**：入所日、出所日、原因都手填，跟現在的出入所紀錄一樣。例如墨西哥 2015-08-18 到 2017-09-05「整修移所」，那次查不到編號。
- **補編號就是補一筆出入所紀錄**，刪編號就是刪那一筆。目前編號仍不能刪（主清單由試算表管）。
- **入所日**＝這隻狗所有出入所紀錄裡最早的入所日。有編號的那筆用編號日期，所以算出來跟 0011 的「三者取最早」一樣。
- **合併重複的狗**：兩邊的出入所紀錄全部合在一起，每個編號各是一筆，不再「留下那隻有就丟被併那隻的」。
- **管理網站與志工網站一起改**：編輯抽屜、詳細資訊都只列一張出入所表，每列是編號（可空）、入所日、出所日、原因；不再分「編號」和「出入所紀錄」兩塊。狗資料表的編號欄照舊。
- **舊資料**：出入所紀錄的入所日跟這隻狗某個編號的日期一樣，就當成同一次，接到那個編號，保留手填的出所日與原因（2026-10-26 測試庫只有納卡西一筆：2026-04-21 對 2026042101）。其他筆維持沒有編號。

## 考慮過的做法

- **結構不動，只修合併**：合併時把兩邊的出入所紀錄合起來，每個編號再補一筆出入所紀錄。改動小，但同一次在所又多存一份，日後補編號、改離所時兩邊會對不上。K 不選。

## 後果

- 「這個編號屬於哪隻狗」仍需要一個地方記（主清單、離所、溜狗紀錄都用編號找狗），出入所紀錄指到它，不另存一份號碼。
- 搬資料要寫 migration，照「先加後刪」分兩張 PR（`docs/agents/data-changes.md`）。
- ADR 0020 的志工編輯開關「出入所紀錄」與「舊編號」合成一個，叫「出入所紀錄」，管整張出入所表（K 2026-10-26）。
- 志工網站的補、刪舊編號入口改成在出入所表新增、刪除有編號的那一列。
