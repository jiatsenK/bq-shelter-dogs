# 0012 同步改成「有改才同步＋每天保險一次」

日期：2026-10-16（K 決定，#305）

> 原本編號 0008，和 `0008-diff-sync-and-write-budget.md` 撞號，2026-10-17 改成 0012。「保險同步做全量」已由 ADR 0010 改成不做全量。

## 背景

同步試算表每次都叫 GitHub Action，每次至少算 1 分鐘。2026-10 前半月同步跑了 622 次，大部分是 Worker 鬧鐘每 30 分鐘一次，不管試算表有沒有改。志工常按「更新」，是因為網站上按溜了／復原後畫面沒跟著變（0007 要解決的事）。

## 決定

- **每天一次保險同步**：Worker 鬧鐘改成台灣時間早上 6:30 一次全量同步，取代 7–22 點每 30 分鐘。GitHub 自己的排程拿掉。
- **有改才同步**：試算表用 Apps Script 觸發器，有人在試算表畫面手動修改時通知 Worker；Worker 記下「有改」，每 10 分鐘看一次，有改才叫 GitHub。10 分鐘內多次修改只同步一次。網站或程式寫進試算表的內容不觸發（本來就已經在 D1）。
- **一天最多 12 次**（原本 30 次，#329 因 Actions 分鐘數不夠調低）：超過後只靠「更新」和隔天早上的保險同步。
- **「更新」按鈕**：先看試算表有沒有變，沒變就不叫 GitHub。
- **推同步相關程式到 main** 照樣同步。
- **通知密碼**：Apps Script 用一組只能說「試算表有改」的專用密碼，不用 `WALKER_KEY`；K 自己設定，不給別人。
- **先做 0007**：網站上按的東西馬上進 D1 之後，「更新」和同步只剩處理直接改試算表的情況。

## 沒選的做法

- **Worker 自己同步、不叫 GitHub**（#301）：免費方案每次 CPU 10 ms 不夠（實測 64–152 ms），要每月 5 美元的付費方案。K 不考慮付費。
- **Apps Script 直接叫 GitHub**：GitHub 金鑰要放進試算表，也不好合併多次修改。

## 後果

- 直接改試算表，網站最慢約 10 分鐘出現；很忙的日子超過 12 次後要按「更新」或等隔天。
- GitHub 分鐘數最壞約每月 390 分鐘（（12＋1）次 × 30 天）加按「更新」和推程式時的同步（#329 調整前是 30 次、約 900 分鐘）。
- K 要手動設 Apps Script 觸發器和專用密碼（步驟另外給）。
