# 0008 同步只寫差異，D1 每天有寫入預算

日期：2026-10-16（K 決定，#302）

> 已由 [ADR 0018](0018-today-walks-d1-event-sync.md) 修訂：試算表抄到 D1 的整批同步已退役（#501、#512），「差異同步」這段只留作歷史。寫入預算還在用：網站登記寫回試算表前照 `SYNC_MAX_ROWS`、`SYNC_DAILY_BUDGET` 檢查（`worker/src/today-walks/budget.js` 的 `reserve`；#746 起保留量依要寫的表自動算），超過時回 503，不再讓 GitHub Action 失敗。

## 背景

2026-10-16 Cloudflare D1 免費寫入額度（整個帳號每天 10 萬列，台灣時間早上 8:00 重置）用完了。同步每次都把 D1 刪光重寫，一次大約 4,500 列，其中大部分是溜狗紀錄。#245 只要求整份換掉試算表的四張複本表，#251 卻連累積的溜狗紀錄也一起刪光重寫。當天同步跑了 34 次。

額度用完後，按溜了（登記）仍然會寫進試算表，但網站上要等到隔天才看得到。常溜、開卡、第一次輸入名字等直接寫 D1 的功能也會失敗。

## 決定

- **差異同步**：同步照主鍵比對 D1 現況和試算表算出來的樣子，只寫有變的列。試算表沒變就一列都不寫。不再有「DELETE FROM 整張表」。
- **寫入預算**：寫之前先算這次要寫幾列。以下任一種情況，這次就整次不寫，D1 保留上一次的內容，讓 GitHub Action 失敗，並把原因寫在執行頁的摘要：
  - 單次要寫的列數超過門檻（先訂 500 列）
  - 今天整個帳號的 D1 寫入量，加上這次要寫的量，超過每天的預算（額度的 20%，也就是 2 萬列）
- 門檻放在 Actions 的 Variables（`SYNC_MAX_ROWS`、`SYNC_DAILY_BUDGET`），等量到平常的寫入量後再調整。寫入量突然變大，通常代表程式又變回整份重寫，或試算表被大量改動；確認原因前不要調高門檻。
- 查不到今天的寫入量（API token 沒有 Account Analytics 讀取權限、網路錯誤）時不擋同步，只檢查單次門檻，並在執行頁顯示警告。
- **通知**：K 在手機的 GitHub App 開啟 Actions 失敗推播，不另外接 Slack。
- **不做止血**：不放慢排程，推程式時照樣觸發，也不限制按「更新」。改成差異同步後，同步次數不再影響額度。

## 考慮過但沒選

- **先止血（放慢排程等）再修**：差異同步本身就能解決問題，止血只是多一次改動。
- **寫了才通知**：等快到上限才通知就太晚了，所以改成寫之前先算，有異常就不寫。
- **Worker 直接同步（#301）**：Worker 上 CPU 要 64–152 ms，超過免費方案的 10 ms，另外處理。

## 影響

- 之後新增會寫 D1 的功能，要估算一天會寫多少列，算進這份預算。ADR 0007 的今日溜狗紀錄上線後，每按一次溜了，也會寫進 D1。
- 同步程式的測試要涵蓋「試算表沒變時寫 0 列」，以及「差異寫完的結果跟整份重建一樣」。

## 後續（#591，K 2026-10-26）

- 「查今天整個帳號的寫入量」拿掉：正式 Worker 從沒設 `CLOUDFLARE_API_TOKEN`，這段一直查不到，每次登記只多記一行警告。
- 溜狗寫入預算只看單次門檻 `SYNC_MAX_ROWS`（沒設，用預設 500）與每日保留量 `SYNC_DAILY_BUDGET`（`wrangler.jsonc` 的 vars；`v3_walk_write_budget` 累計當天保留的上界）。
