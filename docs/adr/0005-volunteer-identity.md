# 0005 志工身分固定，登記名字可以更改與合併

日期：2026-10-16（K 於 #267 討論確認）

狀態：決策已確認；PR #282 已補本機資料模型、API、前端與銜接工具，正式碼對照、資料演練及上線尚未完成。0004 已由 Claude 的 #284／PR #287 使用，因此本決策使用 0005。

## 為什麼調整

目前有 `v3_volunteers.volunteer_id` 和名字算出的 `walker_code`，但常溜與開卡直接依代號持有資料，名字換了就變成另一組收藏，沒有接回固定志工身分。K 決定以「同一位志工」持有資料，接受維護名字對照與既有資料銜接的成本，讓更名不再造成資料分裂；本決策取代 ADR 0001 中以代號直接持有資料的部分。

## 已確認的規則

- 一位志工只有一個固定身分；資料關聯使用 `volunteer_id`。登記名字、舊名字及名字代號都是找到這個身分的對照，不是另一套人的識別方式。`walker_code` 仍可供舊資料與既有介面銜接，不能再作為常溜、開卡等個人資料的擁有者。
- 前端「我是誰」提供更改登記名字。未被使用的新名字沿用原本身分，常溜、開卡與溜狗紀錄保留；換手機輸入新名字能找回。
- 不同志工同名時，使用可區分的登記名字，例如「小明（王）」與「小明（陳）」。系統不能只因名字相近或相同，就自行推定兩人是同一位志工。
- 新名字已屬於另一個身分時，先提示「這個名字已有人使用，請換一個」。如果使用者要合併，須顯示兩個身分與合併後會保留的資料，再由使用者明確確認「這兩個身分都是我」；不需 K 代為確認，不因輸入名字就直接合併。
- 合併保留兩邊資料：常溜取聯集、已開的卡保留、溜狗紀錄歸到同一位志工；同一筆紀錄不能因身分合併重複計算。不得把不同次的溜狗紀錄僅因日期與狗相同就當成重複資料刪掉。
- 更名或合併後，舊名字仍能找到同一位志工，畫面顯示目前的登記名字；既有手機與歷史名字／代號也必須能對應回合併後的身分。
- 延續原有內部工具的身分選擇方式，不在這次引入密碼或身分驗證制度。使用者的確認是「宣告這是同一個人」，不是已驗證身分的證明。
- 不回寫試算表的歷史名字或其他欄位；透過身分對照讀取歷史資料。個人資料寫 D1，不產生使用者資料的 Git 提交。

## 與 #284 編輯紀錄銜接

沿用 #284 的 `v3_edit_log`、`GET /api/edits` 與編輯紀錄頁，不另建一套紀錄機制。新增「志工更名」「身分合併」種類，成功後紀錄必須出現在該頁，顯示操作者、時間、原來與後來的名字／身分及合併影響的資料摘要；沒有狗的操作不應顯示成改了某隻狗。

記錄當時的操作者名字與身分，日後更名不能改掉舊紀錄當時顯示的名字。#284 目前由 Claude 實作，實作本決策前需先確認其最終介面；不要同時修改 Claude 正在處理的檔案，也不能假設現有的狗資料編輯種類已能呈現志工身分操作。
