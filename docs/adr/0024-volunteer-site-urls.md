# 0024 志工網站的網址：每個分頁、資訊子頁、每隻狗都有自己的 hash

狀態：已確認，日期：2026-10-29。K 在電腦版 critique（2026-10-29）決定「每隻狗、每個資訊子頁都要有自己的網址」，排進 P2，並要求不能改到手機版的畫面與操作手感；網址格式與歷史紀錄的做法由 Claude 決定，記在這裡。

起因：電腦版的狗名、頁籤都是 `<button>`，不能 Ctrl＋點開新分頁、右鍵複製連結、存書籤；網址只認 `#mine`、`#find`、`#groups`，詳細資訊等浮層用 `history.pushState(…, '')` 不改網址。志工想要的是：Ctrl＋點「豆花」在新分頁看詳細資訊，原分頁繼續勾別的狗；把某隻狗的連結貼到 LINE 給其他志工。

## 網址格式

| 網址 | 畫面 |
|---|---|
| `#walk`（或沒有 hash） | 溜狗表 |
| `#groups`、`#mine`、`#find` | 常溜狗群、我溜過、找狗 |
| `#info` | 資訊首頁 |
| `#info/<子頁>` | 資訊子頁，子頁名稱就是 `INFO_PAGES` 的鍵：`stay`、`departures`、`activities`、`quality`、`updates` |
| `#dog/<編號>` | 那隻狗的詳細資訊，疊在目前分頁上；直接打開時疊在溜狗表上 |

- **用 hash，不用路徑**：網站是 Worker 給的靜態檔，hash 不會送到伺服器，不用改 Worker 路由，也不會多算 Worker 請求（ADR 0023 不讓每次開頁經過 Worker 的理由相同）。
- **編號是 `dog.id`**（試算表的編號），用 `encodeURIComponent` 包起來。沒有編號的狗、已離所的狗（不在 `appState.allDogs`）不給網址，詳細資訊開著時網址留在原本那一頁。
- **看不懂就安靜退回**：hash 認不得、子頁名稱不對時開溜狗表或資訊首頁；`#dog/<編號>` 找不到這隻狗時只顯示溜狗表，不跳錯誤（PRODUCT.md「資料抓不到時安靜退回預設」）。狗的資料讀取失敗時記著這個編號，按「重新讀取」成功後照樣打開。
- 第一次開網站、開頭畫面（名字設定）或操作教學還開著時，`#dog/<編號>` 不打開詳細資訊：兩個都會蓋住整個畫面、操作教學自己也會開詳細資訊示範，疊在一起會搶焦點。

## 歷史紀錄與返回鍵

沿用 `overlays.js` 原本的規則：開一層覆蓋層多一筆歷史紀錄，返回鍵先關最上面那層；都沒開才換分頁。改的只有每一筆歷史紀錄多帶網址：

- **分頁、資訊子頁**：`pushPage(current, next)` 照兩筆的狀態算出各自的網址（`bindOverlays` 收一個 `pageUrl(state)`），先把目前這筆的網址補正，再多一筆新網址。
- **詳細資訊**：`pushOverlay('detail', '#dog/<編號>')`，多一筆帶狗網址的紀錄；在詳細資訊裡換看別隻（可以一起溜、回到 ○○）不多一筆，只用 `replaceState` 換網址。按返回或 ✕ 就是回上一筆，網址自然回到原本的分頁。燈箱、裁切、在哪面板、平面圖放大不帶網址，網址維持底下那一頁。
- **打開網頁的那一筆**（landing）標成 `bqLanding`，狀態照網址填好。網站裡的「回資訊」「回溜狗表」走 `backFrom`：目前這筆是 landing 時不按瀏覽器上一頁（那會離開網站），改成直接換畫面。直接打開 `#dog/<編號>` 時先把這一筆換成 `#walk`，再多一筆狗的紀錄，所以按返回是關掉詳細資訊、留在溜狗表，再按一次才離開網站。
- **網址跟著畫面**：每次 `render()` 完，最上面不是覆蓋層時，用 `replaceState` 把網址改成目前的分頁（不多一筆）。這處理「沒有走歷史紀錄就換畫面」的路徑，例如 landing 那筆的「回資訊」。
- **自己改網址**：在網址列手動改 hash，或從瀏覽器的「上一頁」回到一筆沒有狀態的紀錄時，照 hash 換畫面。往前回到一筆詳細資訊的紀錄時重新打開那隻狗，不再多疊一筆。

## 真連結

- **電腦版（≥1100px）**：溜狗表全表的狗名、頁首頁籤、資訊首頁的子頁入口改成 `<a href>`。document 上有一個捕獲階段（capture）的 click 處理：一般左鍵點擊（含 Enter）`preventDefault`，交給原本的處理在原頁打開；Ctrl、⌘、Shift、Alt 加點擊 `stopPropagation`、不 `preventDefault`，讓瀏覽器開新分頁或新視窗，原頁什麼都不做。中鍵與右鍵選單本來就不會觸發 click，交給瀏覽器。
- **手機版維持 `<button>`**：手機沒有 Ctrl＋點與中鍵，長按連結反而會跳出 iOS 的連結預覽、Android 的連結選單，改變長按與點擊的手感。手機的網址列照樣跟著換，志工要分享可以用瀏覽器的分享。
- 樣式：只把 CSS 選擇器從 `button` 改成 `:is(button, a)`（權重一樣），連結另外拿掉底線，畫面不變。

## 鍵盤

`/` 跳到搜尋框並選起原本的字。正在輸入框、文字框、下拉選單裡打字時，有覆蓋層、開頭畫面或操作教學開著時，或這一頁沒有搜尋框（資訊）時不觸發。

## 考慮過的做法

- **用路徑（`/dog/123`）**：網址比較好看，但 Worker 要把每條路徑都回 `index.html`，相對路徑的 `js/`、`css/` 也要改成絕對路徑，`groups.html`、`cards.html` 等頁面跟著動。不選。
- **`#dog/<編號>` 帶上底下的分頁（`#info/stay/dog/123`）**：關掉後可以回到原分頁，但貼給別人時對方通常只想看那隻狗。現在打開就是溜狗表加詳細資訊。不選。
- **手機也改成連結、用 CSS `-webkit-touch-callout: none` 擋長按**：Android Chrome 不吃這個屬性，還要另外攔 `contextmenu`，一樣會改到長按。不選。
- **把網址寫進 `overlays.js`**：它要讓主頁和圖鑑都能匯入，所以只收呼叫的人算好的網址；網址格式放在新的 `js/routes.js`，不依賴其他模組。

## 後果

- 志工網站的網址從此是公開介面：改 hash 格式或 `INFO_PAGES` 的鍵，舊連結會退回預設畫面，要改這份 ADR。
- 圖鑑「去設定」連到 `index.html#mine` 照舊可用。
- 重新整理會留在原畫面：資訊子頁照樣開著，詳細資訊開著時重新打開同一隻狗。網頁測試要「重新打開網站」時改用去掉 hash 的 `goto`，不用 `reload`。
- 判斷電腦版只看寬度（跟 `desk.js` 同一個 1100px），橫放的大平板也算電腦版，長按頁籤、狗名會跳出連結選單。
- 嵌在 srcdoc 這類網址跟網站不同的文件裡（`tests/index.html`）寫不進網址，`writeHistory` 退回只記狀態，返回鍵照舊。
- 詳細資訊的狗如果在讀取新資料後不見了（離所），網址留著 `#dog/<編號>`，重新整理時安靜退回溜狗表。
