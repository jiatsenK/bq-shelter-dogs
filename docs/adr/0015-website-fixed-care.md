# 0015 有人固定照顧完全由網站設定

日期：2026-10-18。依據：#399，K 在 grill-with-docs 確認。狀態：已採用。K 已確認操作方式並要求以 implement 實作。

「有人固定照顧」完全以網站設定為準，所有志工共用；不再由試算表「誰遛的」內容判定，也不採網站尚未設定就沿用試算表的做法。這是網站的排序與天數統計設定，不修改試算表。現有程式將「誰遛的」任何非空值轉成 covered，不能拿來當固定照顧的初始設定。

功能上線時全部預設關閉，不匯入試算表既有 covered 值。開啟後排在一般待溜狗之後，排除「最久沒溜」與「超過 N 天沒溜」統計；即使有溜狗日期也適用。關閉後恢復一般天數排序與統計。

固定照顧不代表休養或禁止帶出，仍可登記及復原溜狗；同時休養時沿用既有休養規則。

K 確認的操作方式：志工先選好身分，即可在狗的詳細資訊切換，不用通關碼；依 ADR 0004 留下誰、何時、哪隻狗及開啟／關閉的編輯紀錄。儲存成功才顯示完成，失敗維持原狀。同一隻狗換編號或離所後再回來，保留原設定，需要時由志工手動關閉；設定以永久狗 ID 保存，不隨編號變動。

網站設定與試算表來源分開管理，不被試算表同步覆蓋，遵守 ADR 0006 的試算表寫入限制。保存與讀取實作須遵守既有編輯紀錄、寫入預算及資料包規則；本次實作不直接修改正式資料。

## 寫入預算與上線

設定存 D1 永久狗表的 `v3_dogs.fixed_care`，不另建表（K 在檢視 PR #413 後確認），只寫有變動的一隻狗，不掃全表重寫；相同設定不寫入、不新增編輯紀錄。每次實際變更的直接寫入為設定 1 列、在所資料包版本 1 列、編輯紀錄 1 列，索引成本另計；下一次讀狗清單時，另外重建在所資料包（刪舊段、寫新段，不重建歷史溜狗包）。若每天切換 100 次、在所包維持 1 段且每次都有人讀，約寫 500 列加索引成本，列入 ADR 0008 的每天 20,000 列共用預算；這是容量估算，不是正式用量實測，也不另加每日停寫門檻。沿用每個來源每分鐘 10 次、每小時 60 次的編輯限流。

既有正式狗表上線前先補 `fixed_care INTEGER NOT NULL DEFAULT 0 CHECK(fixed_care IN (0,1))` 欄位，再由既有 schema 同步流程補上 `packs_v3_dogs_INSERT／UPDATE／DELETE` 觸發器；不搬入試算表標記。`CREATE TABLE IF NOT EXISTS` 不會替既有表補欄位；本機遷移入口 `scripts/migrate-compact-db.mjs` 已能補欄位並可重跑，正式補欄位仍須擁有者另行確認。同步新增狗時沿用預設關閉，只更新狗名與性別；差異同步明確排除 `v3_dogs.fixed_care`，避免預演後網站才變更時被寫回舊值。新 Worker 第一次讀到舊格式資料包時重算一次，避免舊快取繼續使用試算表 covered。正式 schema、合併及部署由擁有者決定；本次實作不直接操作正式 D1。

## 存放方式的取捨

固定照顧是每隻狗的一個共用狀態，跟永久狗資料放在同一列即可。原 PR 使用獨立表來隔開來源，K 確認改為狗表欄位；來源隔離由同步欄位範圍保障，避免為單一布林值增加一張表。既有名字／性別同步不會觸發固定照顧的版本更新，只有欄位值真的改變才使在所資料包失效。本次未在正式環境建立獨立表，不執行刪表或資料搬遷。
