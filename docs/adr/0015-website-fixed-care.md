# 0015 有人固定照顧完全由網站設定

日期：2026-10-18。依據：#399，K 在 grill-with-docs 確認。狀態：已採用。K 已確認操作方式並要求以 implement 實作。

「有人固定照顧」完全以網站設定為準，所有志工共用；不再由試算表「誰遛的」內容判定，也不採網站尚未設定就沿用試算表的做法。這是網站的排序與天數統計設定，不修改試算表。現有程式將「誰遛的」任何非空值轉成 covered，不能拿來當固定照顧的初始設定。

功能上線時全部預設關閉，不匯入試算表既有 covered 值。開啟後排在一般待溜狗之後，排除「最久沒溜」與「超過 N 天沒溜」統計；即使有溜狗日期也適用。關閉後恢復一般天數排序與統計。

固定照顧不代表休養或禁止帶出，仍可登記及復原溜狗；同時休養時沿用既有休養規則。

K 確認的操作方式：志工先選好身分，即可在狗的詳細資訊切換，不用通關碼；依 ADR 0004 留下誰、何時、哪隻狗及開啟／關閉的編輯紀錄。儲存成功才顯示完成，失敗維持原狀。同一隻狗換編號或離所後再回來，保留原設定，需要時由志工手動關閉；設定以永久狗 ID 保存，不隨編號變動。

網站設定須獨立保存，不被試算表同步覆蓋，遵守 ADR 0006 的試算表寫入限制。保存與讀取實作須遵守既有編輯紀錄、寫入預算及資料包規則；不在這次設計階段修改功能或正式資料。

## 寫入預算與上線

設定存 D1 的 `v3_fixed_care`，只寫有變動的一隻狗，不掃全表重寫；相同設定不寫入、不新增編輯紀錄。每次實際變更的直接寫入為設定 1 列、在所資料包版本 1 列、編輯紀錄 1 列，索引成本另計；下一次讀狗清單時，另外重建在所資料包（刪舊段、寫新段，不重建歷史溜狗包）。若每天切換 100 次、在所包維持 1 段且每次都有人讀，約寫 500 列加索引成本，列入 ADR 0008 的每天 20,000 列共用預算；這是容量估算，不是正式用量實測，也不另加每日停寫門檻。沿用每個來源每分鐘 10 次、每小時 60 次的編輯限流。

上線前需由既有 schema 同步流程補建空表及 INSERT／UPDATE／DELETE 觸發器，不搬入試算表標記；同步資料差異清單不包含網站設定表。新 Worker 第一次讀到舊格式資料包時重算一次，避免舊快取繼續使用試算表 covered。正式 schema、合併及部署由擁有者決定；本次實作不直接操作正式 D1。
