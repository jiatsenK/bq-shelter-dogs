# 0027 顯示編號的規則只有一份

狀態：K 確認，2026-11-02（#802）。研究依據：[兩項架構整理的事實查核](../research/2026-11-02-architecture-deepening-facts.md)。

## 起因

各頁顯示一隻狗的編號時規則不一致。多數地方是主清單的編號優先，沒有才取最大，但活動名單（`worker/src/activities.js`）對在所的狗也取最大，同籠新建狗的配對修改紀錄（`worker/src/dog-pairs.js`）取最小。一隻狗有兩個編號時，不同頁面可能顯示不同編號。

## 決定

1. **顯示編號**：主清單上非空的編號優先。不在主清單的狗取 `v3_dog_numbers` 裡最大的編號。都沒有就是沒有編號。
2. 規則只寫在「狗的狀態」module（`worker/src/dog-standing.js` 的 `shownNumber`），其他地方引用，`worker/test/standards.test.mjs` 擋散落的 `MAX`、`MIN`。
3. 活動名單和配對修改紀錄改用這條規則。已經寫入的修改紀錄不回填。
4. 管理網站狗表和合併狗也改用同一條。差別只在同一隻狗有兩列主清單、第一列編號空白時：原本取最大，現在取有編號的那列，符合第 1 點。

## 已知前提

編號是 10 碼、前 8 碼是入所日期時，字串上的最大就是最新。試算表寫入的編號沒有格式檢查，合併狗搬編號也不比大小，所以不在主清單的狗取到的最大編號不一定最新。在主清單的狗不受影響。

## 考慮過的其他做法

- **一律取最大**：合併或打錯編號時，在所的狗會顯示主清單以外的編號，主清單才是準的。不採用。
- **各頁維持原樣，只搬程式**：同一隻狗在各頁顯示不同編號的問題留著。不採用。
