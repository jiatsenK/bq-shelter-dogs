# 0016 撤銷溜了改由伺服器找回上一次，不再限登記的那支手機

日期：2026-10-20（K 決定）

## 背景

K 2026-10-20 回報：電腦上看到老大的溜狗人只有「佳岑」（自己的名字），卻沒有 ×，按錯了改不回來。

2026-10-05（#141）K 說「按錯的人要能取消」，實作成「只有自己一個名字、而且是這支手機今天登記的」才有 ×；#397（`docs/design/397-today-walk-state.md`）再寫明「B 手機沒有本機復原證據，不能直接復原」。復原證據（登記前的上次溜日期與名單）只存在按「溜了」的那個瀏覽器，換裝置、換瀏覽器或清資料就沒有 ×。這和 K 的原意（是我的名字就能改）不同。

## 決定

- **上一次的日期由伺服器找**：撤銷時 Worker 從溜狗紀錄找這隻狗被撤銷那筆之前的最後一次；近期紀錄（0013）找不到就往年度資料包找；從沒溜過就留空白，畫面顯示「沒溜過」。不再依賴手機上的復原證據。
- **任何人都能撤銷**：名單只剩一個名字時，任何選好身分的志工都看得到 ×，不限名字本人、不限登記的裝置。依 0004 開放編輯，撤銷記一筆編輯紀錄（`v3_edit_log`：誰、哪隻狗、改前→改後）。名單兩人以上時沿用現有的逐個拿掉名字。
- **只限今天**：這隻狗最新一筆紀錄是今天才能撤銷；過了午夜就沒有 ×，要改請到試算表。（K 先選 3 天內，同日改為只限今天。）
- 撤銷後試算表的日期與「誰遛的」改回前一筆；「我溜過」、近期與年度資料包照現有同步規則跟著更新。
- 取代 #397 第 5 行「沒有本機復原證據不能直接復原」；該檔其餘規則（名單已被別人改過時停止撤銷、不取消對方紀錄）保留。

## 沒選的做法

- **其他裝置撤銷只清今天、上次溜留空白**：狗會跑到最久沒溜排最前面。
- **維持只有登記的裝置能撤銷**：就是這次回報的問題。
- **只限名字本人撤銷**：K 選開放給所有人，靠編輯紀錄事後追查。
- **3 天內**、**7 天**、**不限天數**：撤銷前幾天的紀錄要讓已同步的 D1 與資料包重算；K 選只限今天，符合「復原」是剛做完馬上取消。

## 後果

- 要改 Worker（新的撤銷 API 或擴充 `/api/walk`）、Apps Script 寫回、網頁的 × 判斷；依 `docs/agents/data-changes.md` 估寫入預算。
- 只撤銷今天的紀錄，不需要重算歷史資料包；今天的紀錄若已同步進 D1，照現有同步規則更新。
