# 0026 待核對的狗可以記成已出所

狀態：K 確認，2026-10-30。研究依據：[待核對裡的四隻已出所狗為什麼動不了](../research/2026-10-30-pending-review-discharged-dogs.md)。

重新開放三個既有說法：

- `GLOSSARY.md`「待核對不等於離所」：待核對也可能是出所沒記到。
- `docs/operations/dog-editing.md`「補登紀錄不改離所模型」：管理者可以替待核對的狗記一筆離所紀錄。手填出入所表照舊只存 `v3_stays`，不改狀態。
- [ADR 0025](0025-sheet-rows-missing-candidates.md)「已知限制」第 2 點「確認之後才把那隻狗貼到已出所，照現有規則不記離所，真的發生再處理」。

## 起因

待核對（不在主清單、沒有離所紀錄）原本只有合併一個出口。2026-10-30 資料頁待核對的四隻都是真的出所的狗（拉亞 2022121503 離世、芊芊 2026072401、豆花、2021100407），沒有「可能是同一隻」的配對，畫面上什麼都不能按。離所紀錄只有同步能寫，而且只在狗還在主清單複本上時寫。

另外，最常見的「先把狗複製到已出所、再刪主清單那列」會掉進同一個洞：主清單還有這隻時 GAS 不送已出所那列（2026-10-24 栗子、MINI 誤記離所後加的），等主清單那列確認消失，已出所那列才由保險掃描送到，主清單複本已經沒有這隻，同步略過、指紋照記，之後不會再補。

## 決定

1. **同步補記**：收到已出所那列，主清單複本找不到、也沒有這個編號的離所紀錄時，用 `v3_dog_numbers` 找到狗；那隻狗是待核對就照樣記離所（編號用已出所那列的，原因、日期照那列判讀，跟狗還在主清單時一樣）。在主清單上或已經有離所紀錄的狗不動，退養回來換新編號的狗不受影響。
2. **管理者記成已出所**：資料頁待核對的狗名下有「記成已出所」，開抽屜填離所日、選原因（認養、離世、其他），按兩次才寫。寫一列 `v3_dog_departures`，編號用這隻狗最新的編號，日期來源記成手動（`date_source='manual'`，之後試算表不蓋），修改紀錄記一筆「記成已出所」（`depart`，保留 14 天）。帶抽屜讀到的版本，狗已經不是待核對就 409。沒編號的狗照舊不能記離所。出入所表手填過出所日的，帶進來當預設、手填的原因列出來參考，不自動換成離所原因。
3. 兩種寫法共用一句 `INSERT…SELECT`（`worker/src/dog-depart.js`）。離開主清單前的樣子（`last_*`）主清單複本已經沒有：籠位抄確認消失時記的 `v3_sheet_gone`，最後溜狗日抄 `v3_walks`，性別、介紹、舊編號抄狗資料，試算表備註與常遛狗群空著。
4. 沒有新表、沒有 migration：離所紀錄既有的資料包與 revision 觸發器照舊讓資料包失效。

## 考慮過的其他做法

- **出入所表手填的出所日就算已出所**：只改狀態判斷、不寫離所紀錄，志工網站已出所名單仍看不到，也分不出手填的是不是真的離所。不採用。
- **撤銷記成已出所**：先不做。記錯時可在出入所表改離所日；要整筆拿掉再開票。
