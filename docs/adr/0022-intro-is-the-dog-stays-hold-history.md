# 0022 介紹只寫狗自己，出入所經過記在出入所紀錄

狀態：已確認，日期：2026-10-27，K 回答研究檔的問題（`docs/research/2026-10-27-intro-split-stays.md` 第 2 節「K 回覆」、`docs/research/2026-10-27-intro-split-rework-pages.md`）。

起因：合併狗時介紹只留「留下那隻」的（`docs/operations/dog-editing.md`「合併重複的狗」），被併那隻的入所經過跟著丟掉。查下去發現現在 127 份介紹全部在寫出入所經過、沒有一份寫狗本身（2026-10-10 改寫規則「只要看的出來入所時的狀況」，`docs/design/history/INTRO_REWRITE.md:3`）；志工網站再從介紹抓有日期的句子排進出入所紀錄（#285、#390）。K 想要介紹寫狗自己，之後才能做分享。

修訂 ADR 0021 的「原因是入所原因」（每筆手填、沒有可以自動帶的來源）：這次一次性從介紹搬進來，之後照舊手填。推翻 2026-10-10 的介紹改寫規則與 #285 的入所事件（逐次事件存在介紹表單、`v3_intake_events`）。ADR 0011「不從介紹文字自動抓日期」照舊：搬家的每一筆都由 K 確認。

- **介紹只寫狗自己**（個性、狀況），不寫入所、退回、離所的經過。新介紹的寫法規則還沒定。
- **出入所經過記在出入所紀錄**：每次入所的經過寫進那一筆的入所原因，離所的寫進離所原因（有離所紀錄的照離所紀錄，ADR 0021）。
- **入所原因手寫**，不做固定選單（#650 的選單問題就此結案）。
- **搬家寫法（甲）**：介紹裡那次入所的整句去掉日期，放進那一筆的入所原因（40 字上限）。地區名稱照留（例：「從板橋被拾獲入所」）；後面的捕獲地址、拾獲地點整句拿掉，不搬（例：「由政府捕捉入所，捕獲地址是○○路○○號。」→「由政府捕捉入所」）。原文留在修改紀錄。
- **離所狗一起搬**：離所時存下的介紹（`v3_dog_departures.last_intro`）照同樣規則搬。
- **怎麼確認**：一次性腳本產生核對表（CSV：每隻狗的原文 → 建議放哪一筆、寫什麼），K 用試算表軟體逐隻勾，照勾的結果用 migration 寫入。核對表含捕獲地址等原文，**不 commit、不貼 GitHub**（repo 公開）。日期跟編號對不上的那幾隻，照 ADR 0021 補一筆沒編號的出入所紀錄，一樣逐筆勾。
- **不加頁面**：核對表不做成管理網站頁面。改到的是既有畫面：介紹表單只剩一個文字框、圖鑑卡的「收容所的話」改取介紹、待補清單的「缺介紹」會一下變多（新介紹要重寫）。
- **合併狗**：經過搬進出入所紀錄後，合併時兩邊的出入所紀錄接在一起（ADR 0021），不會再丟；介紹照舊只留一份。

## 順序（先搬資料再刪程式，中間畫面都是對的）

1. 腳本產生核對表，K 勾。
2. migration 照勾的結果寫 `v3_stays`、清掉介紹裡搬走的句子；程式先不動。
3. 拿掉閱讀時從介紹抓句子（`intakePresentation`、`stayLines` 的事件）、介紹表單的入所事件區、圖鑑卡改取介紹。
4. 下一張 PR 才 DROP `v3_intake_events`（`docs/agents/data-changes.md`「先加後刪」）。

## 考慮過的做法

- **另開一個「狗的介紹」新欄位，舊介紹當經過保留**：兩份文字永遠並存，要加表、加觸發器、離所快照也要加欄。K 不選。
- **只在畫面上拆**（現況）：圖鑑卡會顯示捕獲地址、負面的入所原因，不能拿去分享；合併時經過還是會丟。K 不選。
