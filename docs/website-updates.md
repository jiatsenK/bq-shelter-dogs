# 資訊頁網站更新紀錄

`public/website-updates.json` 隨網站靜態檔一起提供，只放經確認已正式上線的志工版更新。資訊 → 更新紀錄 → 網站更新讀取此檔；資料編輯仍由 `edits.html`／`GET /api/edits` 提供，兩者不混存。

每次正式改版的發布準備，維護者在部署版本中加入版本號、日期與簡短說明，以新到舊排序。版本號用 release-please 的版本（`version.txt`），畫面顯示成「V9.2.0」（#421）：

```json
[{ "version": "9.2.0", "date": "2026-10-17", "text": "已正式上線的功能、介面調整或修正說明" }]
```

以上只是格式範例，不可直接當作發布紀錄。只寫志工看得懂的內容，不放原始 commit、內部開發筆記、個人資料或機密。未上線的草稿／預覽變更不得寫入；部署成功後應讀回正式紀錄核對。發布未成功就不能宣稱該版本已上線。此流程不建立排程、不自動匯出 Git 歷史。

本次以空陣列起始，因為沒有經確認的既有使用者版更新清單；不追溯編造歷史，也不把尚未部署的 #273 列為已發布。本文件和程式修改不授權部署。

讀取方式（#421）：資訊頁在同一次開著網頁期間記住讀過的內容，重開先顯示，距上次檢查超過 30 秒才用 `no-cache` 背景檢查（有 ETag 時是條件式請求，沒變只回 304）；檢查失敗保留先前內容並標示讀取時間。重新整理頁面後重新讀取。資料編輯每次打開都向 `GET /api/edits` 確認，期間先顯示同一次開著網頁時上次讀到的內容。`/api/edits` 回 `Cache-Control: private, no-cache` 與 `ETag`（`"edits-f1-<最新一筆 id>-<筆數>"`，編輯紀錄只增不刪）；瀏覽器帶 `If-None-Match`，沒有新編輯時 Worker 只查最新一筆 id 就回 304，App 重開也一樣。回傳欄位或類別名稱改了要把 `f1` 加 1。
