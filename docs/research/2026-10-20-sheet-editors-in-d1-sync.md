# 板收志工溜狗表：志工直接改試算表時，「今天溜狗以 D1 為準」怎麼不漏、不互蓋

- 日期：2026-10-20（台灣時間）。Agent：Claude Code 背景研究代理。
- 範圍：`bq-shelter-dogs-sync` 的原始碼、ADR、GLOSSARY 與官方文件。沒有操作瀏覽器、沒有改程式、沒有寫正式資料。
- 標示：**已確認**＝官方文件或程式碼直接寫的；**推測**＝邏輯上成立但要實測或再查證。
- 接續 `docs/research/2026-10-20-d1-single-source-sync.md`（新架構評估，以下簡稱「架構研究」）與 `docs/research/2026-10-20-sync-pitfalls.md`。

## 結論先講

1. **偵測用「Apps Script 可安裝的 onEdit 觸發器即時通知 ＋ Worker Cron 每 1–5 分鐘全表比對當保險」**。onEdit 不會被網站寫入（Apps Script／API）觸發，剛好只抓人手改；但它會漏掉部分操作（例如排序、某些貼上），所以 Cron 比對不能省。Drive push 只說「檔案變了」、要自己的網域與每天續約，不建議。
2. **合併以「名字集合」為單位，試算表手改要尊重（含清空），但網站剛寫、還沒寫回的名字在寬限期內保留**。
3. **列對狗一律用「編號」，沒有編號才用「犬名」，絕不用列號**；排序、插入列都不會對錯。暫住列「(狗名)」與重複編號要另外處理。
4. **名字不一致不自動修**：照 ADR 0005「不能只因名字相近就推定同一人」，D1 存原文，對不上身分的名字標「未對應」，交給更名／合併流程。
5. 試算表保護（資料驗證、保護範圍、說明列）**都屬於改試算表設定，ADR 0006 沒開放，網站程式不能做，只能由 K 手動決定要不要加**。

## 1. 偵測方式比較

| 方式 | 會不會抓到人手改 | 會不會被網站寫入誤觸發 | 延遲 | 免費額度 | 授權／設定 | 官方文件 |
|---|---|---|---|---|---|---|
| **A. Worker Cron 讀 gviz 比對** | 會（任何變動，含排序、貼上、刪列），但抓不到「是誰改的」 | 會讀到自己寫的結果，要靠「待寫回＋寬限期」分辨 | Cron 間隔＋gviz 快取（推測幾十秒到幾分鐘） | Cron 每帳號 5 個、每次 CPU 10 ms（免費）；gviz 沒公布額度 | 不用新授權（現在已用 gviz 讀） | https://developers.cloudflare.com/workers/configuration/cron-triggers/ 、https://developers.cloudflare.com/workers/platform/limits/ |
| **B. Apps Script 簡單觸發器 `onEdit(e)`** | 會，限「使用者在介面上改值」 | **不會**：官方寫明程式執行與 API 請求不會觸發 | 幾秒 | 簡單觸發器最多執行 30 秒 | **不能**呼叫需要授權的服務 → 不能用 `UrlFetchApp` 通知 Worker，**不適用** | https://developers.google.com/apps-script/guides/triggers （Restrictions 段） |
| **C. Apps Script 可安裝觸發器（installable onEdit／onChange）** | onEdit：改值時；onChange：插入／刪除列欄、改格式等結構變動也會觸發 | 不會（同上，官方：script executions and API requests do not cause triggers to run） | 幾秒 | `UrlFetchApp` 一般帳號 20,000 次／天；觸發器總執行時間一般帳號 90 分鐘／天 | 要用 K 的帳號安裝一次並授權外部連線（`script.external_request`）；以安裝者身分執行 | https://developers.google.com/apps-script/guides/triggers/installable 、https://developers.google.com/apps-script/guides/services/quotas |
| **D. Drive API push notifications（`files.watch`）** | 只告訴你「檔案變了」，不給哪一格 | 會（網站寫入也算檔案變動） | 推測數秒到數分鐘，官方不保證 | 免費，但頻道會過期（檔案頻道最長約 1 天），要定時續約 | 要 OAuth／服務帳號、可公開 HTTPS 接收端（Worker 可以） | https://developers.google.com/workspace/drive/api/guides/push |
| E. Sheets API 本身 | **沒有**變更通知；只能輪詢 `spreadsheets.values.get` | — | 輪詢間隔 | 讀 300 次／分鐘／專案、60 次／分鐘／使用者 | 要服務帳號並把試算表分享給它 | https://developers.google.com/workspace/sheets/api/limits |

重點限制（已確認，官方 triggers 文件）：
- onEdit 的 `e.range`／`e.value`／`e.oldValue` 只在**單格**改值時有 `value`／`oldValue`，多格貼上只有 range（https://developers.google.com/apps-script/guides/triggers/events ）。
- 推測（要實測）：資料→排序範圍、篩選檢視、Undo（Ctrl+Z）不一定觸發 onEdit；插入／刪除列觸發的是 onChange 不是 onEdit。所以觸發器只當「加速器」，正確性靠 Cron 全表比對。

**建議**：C（installable onEdit＋onChange，只送「有變動，請馬上比對」給 Worker，不送內容）＋ A（Cron 定時全表比對）。觸發器送通知時 Worker 做的事跟 Cron 一樣（讀 gviz、全表比對），所以只有一套比對邏輯；觸發器壞了或沒授權，最多變慢不會錯。
- 這是**新增 Apps Script 觸發器**，不是改試算表內容；ADR 0006 管的是「寫入哪些格子」，觸發器本身不寫格子 → 不違反 0006，但屬於改外部服務設定，**要 K 確認並由 K 用自己的帳號授權**（推測：觸發器以安裝者身分執行，跟現在 `sheet-write.gs` 部署方式相同，`worker/src/index.js:764`）。
- Cron 頻率：K 說只要符合免費方案都行。架構研究已估額度夠，但 Cron CPU 10 ms 要實測（架構研究 §2 坑 4）。有觸發器加速後，Cron 可放寬到每 5 分鐘，風險更低。
- 不選 D：只多一個「變了」的訊號、要續約、會被網站自己的寫入觸發，跟 C 比沒有好處。

## 2. 合併規則（試算表手改 vs 網站寫入）

D1 每隻狗今天一列，建議欄位（推測設計）：`names`（名字集合原文）、`sheet_seen`（上次 Cron 看到的試算表原文）、`pending`（已寫 D1、還沒確認寫回試算表的名字）、`pending_at`。

比對時用**三方比較**：上次看到的試算表（base）、現在的試算表（sheet）、D1。

| 情況 | 規則 | 理由 |
|---|---|---|
| 試算表這格跟 base 一樣 | 什麼都不做（D1 的新名字可能還在寫回途中） | 試算表沒人動 → 不能拿舊值蓋 D1（架構研究坑 1） |
| 試算表新增名字（填名字、填別人名字、貼上） | D1 名字集合 ∪ 新名字 | 符合 K「兩人都登記」 |
| 試算表刪掉某個名字或整格清空 | **尊重**：從 D1 移除那些名字；但 `pending` 裡、寬限期內（建議 2–3 分鐘或「直到寫回成功」）的名字保留，並重新寫回 | 手動清空通常是「登記錯」，要尊重（ADR 0006 也說寫錯到試算表手動改，`docs/adr/0006-sheet-write-scope.md:13`）；但剛按的名字可能是 Apps Script 還沒寫進去，不是被刪 |
| 改錯字（「小名」→「小明」） | 視為刪一個加一個；D1 跟著試算表 | 不猜，見第 4 節 |
| 日期改成不是今天 / 清空日期 | 該狗 D1 今天紀錄全部視為取消（walked=0，不刪列） | 架構研究坑 3 |
| 網站按溜了，試算表同時有人手改同一格 | Apps Script 本來就是「先讀格子再接上去」並上鎖（`sheet-write.gs:39-40`、`:159-169`），手改的名字會保留；之後 Cron 用集合合併收斂 | 頂多慢一輪，不會掉名字 |
| 網站 undo 與手改衝突 | 沿用現行：格子不是我們寫的樣子就不動（`sheet-write.gs:176-183`），D1 照試算表 | 已有做法 |

寫回試算表時一律「讀現值 → 集合合併 → 用 `、` 接起來」，不整格覆蓋（沿用 `planSheetWrites`）。

## 3. 試算表的列怎麼對到 D1 的狗

| 方法 | 排序後 | 插入列後 | 結論 |
|---|---|---|---|
| 列號 | 錯 | 錯 | **不可用** |
| 編號 | 對 | 對 | 主鍵（現行 `findDogRow`、`parseWalkers` 都是） |
| 犬名（沒編號時） | 對 | 對 | 備援，key＝`名:犬名`（`worker/src/index.js:833`） |

坑：
- **整列複製貼上**：會出現兩列同編號。現行 `findDogRow` 取第一列（`sheet-write.gs:124-127`），`parseWalkers` 後面的列會蓋前面的（`index.js:837` 直接 `walkers[key] = text`）→ 兩邊選的列不同。對策：Cron 偵測到重複 key 就**不更新那隻狗、記一筆警告**給 K，並把兩列名字聯集當結果（推測設計）。
- **暫住列**「(狗名)」沒有編號、名字加括號（`GLOSSARY.md:94`）：要沿用同步時的合併規則，不要當成新狗或 `名:(狗名)`。
- **表尾提示文字**：現行要有犬名＋籠位才算狗（`index.js:830`），維持。
- **欄位被移動或表頭改名**：現在用表頭文字找欄（`sheet-write.gs:108-120`、`index.js:788-801`），移欄沒事；表頭改名會整個失敗 → 要報錯不要猜。
- 編號被手改：會變成「舊狗消失、新狗出現」。推測罕見；Cron 遇到今天 D1 有紀錄、試算表卻找不到那個 key 時，先保留 D1、標「找不到列」，不刪。

## 4. 名字不一致與志工身分（ADR 0005、GLOSSARY）

- ADR 0005：「系統不能只因名字相近或相同，就自行推定兩人是同一位志工」（`docs/adr/0005-volunteer-identity.md`「已確認的規則」第 3 點）；「不回寫試算表的歷史名字」（同段最後）。GLOSSARY：不同名字本身不是合併的證據（`GLOSSARY.md:170`）。
- 因此：
  - **只做無損正規化**：去前後空白、全形半形空白、重複分隔符。這跟現行拆名字一致（`NAME_SEP` 含空白，`sheet-write.gs:15`）。注意：空白也是分隔符，「王 小明」會被拆成兩個名字（已確認，程式行為），手填習慣有空白時要提醒。
  - **不做模糊比對、不自動改錯字、不自動把暱稱對到某位志工**。
  - D1 存試算表原文名字；能對到既有登記名字／舊名字就掛 `volunteer_id`，對不到就標「未對應名字」，進入 ADR 0005 的更名／合併流程，由志工本人確認。
  - 網站不回寫修正後的名字到試算表（ADR 0005＋0006）。
- 影響：錯字名字會出現在「誰溜過」與名字清單（`/walkers` 會把它當新名字，`index.js:838-842`），直到有人在試算表改掉。這是可接受的，因為改掉後下一輪就消失。

## 5. 試算表保護與 ADR 0006

ADR 0006 規定網站**寫入**的範圍（`docs/adr/0006-sheet-write-scope.md:7-19`），沒有授權網站或程式改試算表的設定。下列保護都要 **K 手動**做或明確批准，程式不能自己加：

| 保護 | 作用 | 會不會擋到現有志工 | 0006 |
|---|---|---|---|
| 「遛狗日期」欄資料驗證（必須是日期） | 防止日期打成文字讀不懂 | 會跳警告；設「顯示警告」而非「拒絕」較溫和 | 程式不能加（改設定）；K 手動可以 |
| 「誰遛的」下拉清單 | 防錯字 | 志工名單會變，要常維護；多名字一格不適用下拉 → **不建議** | 同上 |
| 保護範圍（編號、犬名、籠位欄只給所方改） | 防排序／貼上弄壞主鍵 | 會擋到現在會改這些欄的人 | 同上 |
| 表頭上方說明列「溜狗請盡量用網站；手填用『、』隔開名字」 | 降低格式錯 | 插入一列會改變表頭位置；程式找表頭是用文字掃描（`sheet-write.gs:108`、`index.js:800`），應不受影響（推測，要測） | **網站寫入違反 0006**；K 手動加可以 |
| 用「附註」（儲存格 note）而非插列放說明 | 不動列結構 | 不影響 | 同上 |
| 版本記錄 | 出錯可還原 | 不影響，Google 內建 | 不需要做事 |

Apps Script 觸發器屬於「在 K 的帳號加程式」，不寫格子，見第 1 節。

## 6. 坑一覽

嚴重度：高＝會掉紀錄或互蓋；中＝短暫錯、會自己修好；低＝體驗或維護。

| # | 坑 | 情境 | 影響 | 對策 | 嚴重度 |
|---|---|---|---|---|---|
| 1 | Cron 讀到還沒寫回的試算表，把網站剛按的蓋掉 | 按溜了後 Apps Script 尚未完成，Cron 讀到空格 | 狗閃回未溜 | 三方比較＋`pending` 寬限期（第 2 節） | 高 |
| 2 | 手動清空被當成「還沒寫回」而忽略 | 志工清空登記錯的名字，剛好在寬限期內 | 清不掉，名字又被寫回 | 寬限期只保護 `pending` 名字、且寫回成功後就結束；寬限期要短 | 中 |
| 3 | 整列複製貼上→同編號兩列 | 志工複製別隻狗的列改內容 | 兩邊選不同列，名字對錯狗 | 偵測重複 key 不更新＋警告 K | 高 |
| 4 | 排序／插入列 | 所方整理表格 | 若用列號會全部對錯 | 只用編號／犬名（現行已如此） | 低（遵守即可） |
| 5 | onEdit 漏抓排序、多格貼上、Undo | 志工用排序或 Ctrl+Z | 觸發器沒通知 | Cron 全表比對保底 | 中 |
| 6 | 觸發器授權過期或 K 帳號問題 | 一段時間沒人維護 | 退化成只有 Cron | 每次觸發器呼叫記時間，太久沒來就提示 K | 低 |
| 7 | 錯字／暱稱產生「新志工名字」 | 手填「小名」 | 名字清單多一個，不會錯掛身分 | 不自動合併（ADR 0005），標未對應 | 低 |
| 8 | 名字中間有空白被拆成兩人 | 手填「王 小明」 | 計成兩個名字 | 說明列提醒；不改拆分規則（會影響既有資料） | 低 |
| 9 | 填別人的名字 | 幫朋友登記 | 照登，與網站行為一致 | 不處理（沒有身分驗證，ADR 0005） | 低 |
| 10 | 日期打成文字（「10/20」或「今天」） | 手填 | 讀不懂；現行讀不懂就不回日期（`index.js:832-834`） | Cron 讀不懂時保留 D1 不動、記警告；K 可加日期驗證 | 中 |
| 11 | 跨日 | 台灣 00:00 前後手改 | 算成昨天 | 一律台灣日（架構研究坑 5） | 中 |
| 12 | 暫住列「(狗名)」被當新狗 | 搬籠 | 今天紀錄掛錯 | 沿用同步的暫住合併規則 | 中 |
| 13 | 表頭被改名 | 所方改欄名 | 讀寫都失敗 | 報錯、Cron 不更新 D1 | 中 |
| 14 | 兩人同時：一人網站、一人手填同格 | 尖峰時段 | 手填者送出時若覆蓋整格，網站的名字會掉 | Apps Script 無法擋人手覆蓋；Cron 看到網站名字從試算表消失時，若仍在 `pending` 寬限期就補回，否則尊重刪除 | 中 |

## 7. 建議方案

1. Cron（頻率視 CPU 實測，1–5 分鐘）＋ installable onEdit／onChange 通知 Worker「請比對」。
2. 比對單位：每隻狗（編號／`名:犬名`）今天的名字集合；三方比較＋`pending` 寬限期；清空要尊重。
3. 寫回試算表沿用現行 Apps Script「讀現值→集合合併→`、`連接」，維持 ADR 0006 範圍。
4. 名字只做無損正規化，不自動對身分；未對應名字走 ADR 0005 流程。
5. 重複編號、讀不懂的日期、表頭不見：Cron 不動 D1、留警告。
6. 試算表保護由 K 手動決定，網站不改設定。

## 8. 需要 K 決定的事

1. 要不要加 Apps Script 觸發器（要 K 用自己帳號授權外部連線）？還是只用 Cron？
2. 手動清空寬限期多長（建議 2–3 分鐘）？寬限期內被清掉的網站名字要補回嗎？
