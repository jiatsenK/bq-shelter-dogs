# 板收遛狗 — 專案目標（第一版定版）

## 背景

志工到板橋收容所遛狗，原本要在 Google 試算表裡切分頁、找資料，手機上操作不便且容易誤觸編輯。目標是做一個唯讀網頁，一次解決三件事：誰很久沒遛、牠的備註、牠能跟誰同籠一起遛。

---

## 前端目標

**性質**：純前端、唯讀、手機瀏覽器優先的單頁網站，無登入、無資料庫、無伺服器。

**三個分頁**（隻數顯示在分頁標籤上）：
1. **待巡房** — 依「幾天沒遛」由久到近排序，色標＋天數同時顯示（0～6 天綠、第 7 天起黃、第 30 天起紅；2026-09-24 K 定案剛好 7 天算黃、剛好 30 天算紅）
2. **近期已遛** — 7 天內已遛過的狗，避免志工重複帶同一隻
3. **依籠位** — 列出所有籠位代碼，點進去看該籠位目前有哪些狗

**其他功能**：
- 搜尋框（比對犬名，即時篩選，所有分頁共用）
- 備註含「勿溜」（含勿遛等異體字）的狗，卡片加紅色驚嘆號徽章並把字眼標紅；狗照樣留在待巡房，由志工看備註決定（2026-09-24 K 定案：取消「特殊狀況」分頁，住院區只是籠位、那裡的狗照常遛）
- 同籠可一起遛的狗名，直接顯示在卡片內文字裡，不需要多點一次或跳頁
- 卡片可顯示照片與志工寫的介紹文字（來源見下方後端），抓不到就用預設圖示／略過，不報錯、不留白版面
- 畫面上不能有任何看起來能編輯的元素，避免志工誤以為能改到原始試算表

**明確不做（v1 排除）**：
- 任何寫入功能（改遛狗日、備註、同籠關係）
- 完整送養介紹頁面（詳情頁），全部資訊都在卡片內看完

---

## 後端目標（資料層，無傳統伺服器）

**架構**：兩個獨立資料源，由前端在瀏覽器端即時讀取、合併顯示，沒有中介伺服器、沒有資料庫。

### 資料源一：Google 試算表（唯讀，即時）
- 志工非管理者，無編輯權限，只能讀。
- 透過 Google Visualization API（gviz）讀取，免金鑰：
  `https://docs.google.com/spreadsheets/d/{sheetId}/gviz/tq?tqx=out:json&sheet={分頁名稱}`
- 讀取兩個分頁：
  - **主清單**：籠位、編號、犬名、遛狗日期、誰遛的、備註 → 目前在所名冊與即時狀態的唯一真相來源
  - **常遛狗群**：每欄一組可同籠的狗 → 同籠關係的唯一真相來源
- 試算表需設定「知道連結的人可檢視」。
- 狗是否離所／死亡，完全由試算表（已出所分頁）決定，前端只認主清單，不在別處另外維護在所狀態。

### 資料源二：GitHub Repository（`jiatsenK/bq-shelter-dogs`，靜態內容）
- 志工自行維護，Public repo，flat-file 結構，一隻狗一個檔案，比照 Obsidian 筆記慣例：
  ```
  dogs/{編號}.md    ← YAML frontmatter + 自由文字介紹
  photos/{編號}.jpg  ← 照片
  ```
- 一律用「編號」比對，不用犬名——編號入所即固定、終身不變，籠位變動不影響對應。
- 沒有的檔案（404）視為無資料，前端安靜略過，不需要另外維護「哪些狗有資料」的清單。
- 網站本身也用 GitHub Pages 部署在同一個 repo，圖片/內容一律用相對路徑讀取，不需要 CDN 或外部網址。

**v1 明確排除**：試算表寫入。若未來要做，需要試算表管理者另外架設 Google Apps Script Web App 作為寫入入口（涉及編輯權限，非前端工程問題），現階段不預留相關程式碼。
