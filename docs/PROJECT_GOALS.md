## V3 重點

**網站名稱**：板收志工溜狗表

**主分類**（依序）：
1. **溜狗表** — 沿用原「待巡房」：所有狗依幾天沒遛由久到近排序，色標＋天數
2. **今天已溜** — 這台裝置、這個瀏覽器的使用者今天自己溜過的狗（純本機個人紀錄，不是所有志工的紀錄）
3. **我溜過** — 試算表「誰遛的」是我的遛狗紀錄（V6 起每個志工在這頁輸入名字、換成代號，看 `data/walks.json` 的 `walkers` 有沒有自己的代號，#94–#96），每次到所一張卡（照片排一排、第一次遛的標「第一次」），新到舊一路往下排，上方是這個月小計；不選日期（K 2026-09-25）；點狗開詳細資訊（V5，#58 取代原本編輯中的「相關資訊」）

原本的「近期已遛」「依籠位」分頁在 V3 移除。

**切換**：點分類名稱，或在內容區左右滑動（向左到下一個、向右到上一個；頭尾不循環），上方分類標籤同步顯示目前分類。

**搜尋**：犬名即時搜尋，只篩目前分類；有字時右側出現 `X`，點了清空並恢復目前分類，不切換分類。

**今天已溜**：
- 溜狗表狗卡向右滑 → 加入今天已溜，畫面立即更新。
- 詳細資訊「可以一起溜」長按狗狗照片 → 先跳確認，確認後才加入。
- 今天已溜的狗卡向左滑 → 移回溜狗表。
- 只存瀏覽器 `localStorage`，紀錄基礎是「本地日期＋狗狗編號」；不寫 Google 試算表、不寫 GitHub、不傳到任何共用資料來源、不需要登入。
- 同一天重新整理或關掉再開都保留；到隔天自動視為全部未勾選（新日期不讀前一天的紀錄即可，不用刪歷史）。

**資料載入**：

```text
Google 試算表 → GitHub Action 定期同步 → data/dogs.json → Cloudflare Worker（V8 起；之前是 GitHub Pages）
```

- GitHub Action 定期讀試算表，整理成 `data/dogs.json` 推回 repo；也可以在 Actions 頁手動執行。
- 狗卡資訊（`dogs/{編號}.md`）與性別也由同一個 Action 整理成純文字寫進 `dogs.json`（2026-09-25 K 選定），前端不再逐隻抓 `.md`；`dogs/` 有變動推到 main 時會馬上同步一次。
- 歷史（V5，#56）：每次同步另存當天快照 `data/history/YYYY-MM-DD.json`（同一天覆蓋成最後一次），並把「遛狗日期比上次同步新」的狗追加進 `data/walks.json`（`{ id, name, date }`，只追加）。歷史從上線那天開始累積；第一次建立時以每隻狗目前的最後一次遛狗日期當起點。兩次同步之間被遛兩次只記一筆；公開檔案不含志工名字。#251 起溜狗紀錄存在 D1 的 `v3_walks`（網站讀 `/api/walks`），不再存每日快照和 `data/walks.json`。
- 是不是我遛的（V5，#57）：比對用的名字放 Actions Secret `MY_NAME`（不寫在程式或任何公開檔案）。`dogs.json` 每隻狗加 `myWalked`（最後一次是不是我遛的）與 `myWalkedDate`（我最後一次遛的日期，看遛狗紀錄）；`walks.json` 新紀錄加 `mine`，同一天從別人換成我（或反過來）也會追加一筆。#57 之前的舊紀錄沒有 `mine`，原樣保留。沒設定 `MY_NAME` 時同步照常，`myWalked` 都是 false。
- 前端只讀 `data/dogs.json`，不直接連 Google 試算表；維持免費靜態部署，不加後端伺服器、不加登入。
- `dogs.json` 至少保留籠位、編號、犬名、遛狗日期、誰遛的、備註、可以一起溜的關係，以及前端實際用到的其他欄位。改資料來源後，排序、最近遛狗判斷、照片、狗卡資訊、同籠關係與各種 fallback 行為都不能退化。
- 開啟網站時標題、搜尋框、分類列先出現，內容區再背景載入資料；載入失敗時這些都還在，內容區顯示「資料載入失敗，請稍後重新整理。」，不白屏。

**檔案結構**：

```text
public/index.html        ← 只有頁面基本結構
public/css/app.css       ← 主要樣式
public/js/app.js         ← 分類、搜尋、滑動、localStorage、資料載入與渲染
data/dogs.json    ← 試算表同步後的狗狗資料
dogs/{編號}.md     ← 狗卡資訊
photos/{編號}.jpg  ← 照片
```

狗狗清單資料不寫死在 HTML。

## 電腦版溜狗表（2026-10-10）

所有志工在家用電腦看整體狀況、盤點（以前大家看試算表），也可以一次勾好幾隻登記溜了。寬螢幕（≥1100px）的溜狗表換成電腦版（`public/js/desk.js`），手機照舊。K 看過三種真資料原型後選「簡報＋全表，可切最近 30 天」。

- 頁首：分類變成頁首的分頁，搜尋框靠右，頁首不收起。
- 上方簡報：紅（5 天以上）、黃（3–4 天）、綠（0–2 天）、沒紀錄、休養中各幾隻；各區色條、紅黃隻數、最久沒溜的那隻，點一區只看那一區。
- 全表：勾選｜天數｜狗名（點了開詳細資訊）｜籠位（點了開平面圖）｜上次溜｜誰遛的｜備註（試算表原文，一行，滑過看全文，警示字紅色）；可排序、分區。切「最近 30 天」換成 30 格，那天有溜就塗綠（溜狗紀錄 data/walks.json）。
- 勾了就跳出「已勾 N 隻・今天 溜了」，一次登記；照舊只寫試算表「遛狗日期」「誰遛的」兩欄，可以復原。
- 右欄：異動紀錄（試算表主清單狗清單下面那段：籠位欄「備註1」…、編號欄寫內容，同步時從第一個「備註」讀到底，存進 dogs.json 的 `sheetNotes`，只讀不寫；新的在上面）、休養中。
- 我溜過、找狗、分析在電腦上暫時照舊窄欄置中。頁首最右邊「圖鑑」連到 `public/cards.html`（見下一段）。

## 前端目標

**性質**：純前端、唯讀、手機瀏覽器優先的單頁網站，無登入、無資料庫、無伺服器。

**三個分頁**（隻數顯示在分頁標籤上；V3 改為溜狗表／今天已溜／相關資訊）：
1. **待巡房** — 依「幾天沒遛」由久到近排序，色標＋天數同時顯示（0～6 天綠、第 7 天起黃、第 30 天起紅；2026-09-24 K 定案剛好 7 天算黃、剛好 30 天算紅）
2. **近期已遛** — 7 天內已遛過的狗，避免志工重複帶同一隻
3. **依籠位** — 列出所有籠位代碼，點進去看該籠位目前有哪些狗

**其他功能**：
- 搜尋框（比對犬名，即時篩選，所有分頁共用）
- 卡片高密度化（#28，2026-09-24 K 定）：手機一個畫面約 6～8 隻。卡片第一層只放照片（約 56 px）、犬名、性別（預留，之後用符號補）、天數徽章、「籠位｜編號」同一行
- 備註含警示關鍵字 **勿溜（含勿遛、勿蹓）、不要、攻擊、不親狗、不親** 任一個，就把**備註原文**直接顯示在卡片第一層（不改寫、不摘要、不轉成固定標籤，命中多個也只顯示一次），字眼標紅；狗照樣留在待巡房，由志工看備註決定（取消「特殊狀況」分頁，住院區只是籠位、那裡的狗照常遛）
- 點狗卡開啟**詳細資訊**，分三區：**備註**（試算表備註欄，志工後續補充的個性、互動、觀察）／**可以一起溜的狗**（照片＋犬名，可點開那隻）／**狗卡資訊**（`dogs/{編號}.md`，入所時的原始狗卡）
- 卡片與詳細資訊可顯示照片與介紹文字（來源見下方後端），抓不到就用預設圖示／略過，不報錯、不留白版面
- 畫面上不能有任何看起來能編輯的元素，避免志工誤以為能改到原始試算表

**明確不做（v1 排除）**：
- 任何寫入試算表或 GitHub 的功能（改遛狗日、備註、同籠關係）；V3 的「今天已溜」只存在使用者自己的瀏覽器
