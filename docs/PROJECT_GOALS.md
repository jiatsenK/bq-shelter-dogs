# 板收志工溜狗表 — 專案目標（第三版 V3 定版）

> V3 規格：K 2026-09-24「板收志工溜狗表｜開發規格 20260924 V3」，工作分票見 GitHub Issues 標籤 `v3`（#30–#35）。
> V3 跟舊版不同的地方以 V3 為準；v1／v2 的內容保留在本文後段供參考，已被取代的地方有標註。

## 背景

志工到板橋收容所遛狗，原本要在 Google 試算表裡切分頁、找資料，手機上操作不便且容易誤觸編輯。目標是做一個網頁，一次解決三件事：誰很久沒遛、牠的備註、牠能跟誰同籠一起遛。

## V3 重點

**網站名稱**：板收志工溜狗表

**主分類**（依序）：
1. **溜狗表** — 沿用原「待巡房」：所有狗依幾天沒遛由久到近排序，色標＋天數
2. **今天已溜** — 這台裝置、這個瀏覽器的使用者今天自己溜過的狗（純本機個人紀錄，不是所有志工的紀錄）
3. **相關資訊** — 編輯中

原本的「近期已遛」「依籠位」分頁在 V3 移除。

**切換**：點分類名稱，或在內容區左右滑動（向左到下一個、向右到上一個；頭尾不循環），上方分類標籤同步顯示目前分類。

**搜尋**：犬名即時搜尋，只篩目前分類；有字時右側出現 `X`，點了清空並恢復目前分類，不切換分類。

**今天已溜**：
- 溜狗表狗卡向右滑 → 加入今天已溜，畫面立即更新。
- 詳細資訊「可以一起溜」長按狗狗照片 → 先跳確認，確認後才加入。
- 今天已溜的狗卡向左滑 → 移回溜狗表。
- 只存瀏覽器 `localStorage`，紀錄基礎是「本地日期＋狗狗編號」；不寫 Google 試算表、不寫 GitHub、不傳到任何共用資料來源、不需要登入。
- 同一天重新整理或關掉再開都保留；到隔天自動視為全部未勾選（新日期不讀前一天的紀錄即可，不用刪歷史）。

**資料載入**：

```text
Google 試算表 → GitHub Action 定期同步 → data/dogs.json → GitHub Pages
```

- GitHub Action 定期讀試算表，整理成 `data/dogs.json` 推回 repo；也可以在 Actions 頁手動執行。
- 前端只讀 `data/dogs.json`，不直接連 Google 試算表；維持免費靜態部署，不加後端伺服器、不加登入。
- `dogs.json` 至少保留籠位、編號、犬名、遛狗日期、誰遛的、備註、可以一起溜的關係，以及前端實際用到的其他欄位。改資料來源後，排序、最近遛狗判斷、照片、狗卡資訊、同籠關係與各種 fallback 行為都不能退化。
- 開啟網站時標題、搜尋框、分類列先出現，內容區再背景載入資料；載入失敗時這些都還在，內容區顯示「資料載入失敗，請稍後重新整理。」，不白屏。

**檔案結構**：

```text
index.html        ← 只有頁面基本結構
css/app.css       ← 主要樣式
js/app.js         ← 分類、搜尋、滑動、localStorage、資料載入與渲染
data/dogs.json    ← 試算表同步後的狗狗資料
dogs/{編號}.md     ← 狗卡資訊
photos/{編號}.jpg  ← 照片
```

狗狗清單資料不寫死在 HTML。

## V4 照片功能（K 2026-09-24「溜狗表開發 20260924 v4｜照片功能」，Issues 標籤 `v4`：#46–#48）

- **照片放大（#46）**：狗卡照片、詳細資訊上方照片點了用燈箱顯示大圖，不裁切、盡量用滿畫面；點關閉、點背景、Esc、手機返回都能關。沒照片（腳掌圖示）照舊開詳細資訊；「可以一起溜」的小照片維持點了換看那隻。
- **上傳／更換照片（#48）**：詳細資訊照片下方「上傳照片」（已有照片時是「更換照片」）→ 選照片 → 預覽 → 「確認上傳」。依編號存成 `photos/{編號}.jpg`（沒編號的狗不能上傳）；手機端先壓成長邊 1280px 的 JPEG；成功後畫面立刻換新照片，失敗顯示錯誤、原照片不動。不用登入。
- **上傳層（#47）**：`GitHub Pages → Cloudflare Worker（worker/）→ GitHub API → photos/{編號}.jpg`。GitHub token 只存在 Worker 的 Secret，前端與 repo 都沒有。Worker 只收網站網域、dogs.json 裡的編號、JPEG、2 MB 以內，並有簡單頻率限制。設定步驟：`docs/PHOTO_UPLOAD_SETUP.md`。
- 不在 V4 範圍：狗卡版型、資料欄位、排序、篩選、試算表同步、狗卡介紹／備註。

## 前端目標

**性質**：純前端、唯讀、手機瀏覽器優先的單頁網站，無登入、無資料庫、無伺服器。

**三個分頁**（隻數顯示在分頁標籤上；V3 改為溜狗表／今天已溜／相關資訊）：
1. **待巡房** — 依「幾天沒遛」由久到近排序，色標＋天數同時顯示（0～6 天綠、第 7 天起黃、第 30 天起紅；2026-09-24 K 定案剛好 7 天算黃、剛好 30 天算紅）
2. **近期已遛** — 7 天內已遛過的狗，避免志工重複帶同一隻
3. **依籠位** — 列出所有籠位代碼，點進去看該籠位目前有哪些狗

**其他功能**：
- 搜尋框（比對犬名，即時篩選，所有分頁共用）
- 卡片高密度化（#28，2026-09-24 K 定）：手機一個畫面約 6～8 隻。卡片第一層只放照片（約 56 px）、犬名、性別（預留，之後用符號補）、天數徽章、「籠位｜編號」同一行
- 備註含警示關鍵字 **勿溜（含勿遛、勿蹓）、不要、攻擊、不親狗、不親** 任一個，就把**備註原文**直接顯示在卡片第一層（不改寫、不摘要、不轉成固定標籤，命中多個也只顯示一次），字眼標紅；狗照樣留在待巡房，由志工看備註決定（取消「特殊狀況」分頁，住院區只是籠位、那裡的狗照常遛）
- 點狗卡開啟**詳細資訊**，分三區：**備註**（試算表備註欄，志工後續補充的個性、互動、觀察）／**可以一起溜的狗**（照片＋犬名，可點開那隻）／**狗卡資訊**（`dogs/{編號}.md`，入所時的原始狗卡）
- 卡片與詳細資訊可顯示照片與介紹文字（來源見下方後端），抓不到就用預設圖示／略過，不報錯、不留白版面
- 畫面上不能有任何看起來能編輯的元素，避免志工誤以為能改到原始試算表

**明確不做（v1 排除）**：
- 任何寫入試算表或 GitHub 的功能（改遛狗日、備註、同籠關係）；V3 的「今天已溜」只存在使用者自己的瀏覽器
- 完整送養介紹頁面（v1 原本不做詳情頁；#28 起改為點卡片開詳細資訊，但不是另一個網頁）

## 後端目標（資料層，無傳統伺服器）

**架構**：兩個獨立資料源，沒有中介伺服器、沒有資料庫。（V3 起試算表改由 GitHub Action 同步成 `data/dogs.json`，前端不再即時讀試算表。）

### 資料源一：Google 試算表（唯讀）
- 志工非管理者，無編輯權限，只能讀。
- 透過 Google Visualization API（gviz）讀取，免金鑰（V3 起由 GitHub Action 讀）：
  `https://docs.google.com/spreadsheets/d/{sheetId}/gviz/tq?tqx=out:json&sheet={分頁名稱}`
- 讀取兩個分頁：
  - **主清單**：籠位、編號、犬名、遛狗日期、誰遛的、備註 → 目前在所名冊與即時狀態的唯一真相來源
  - **常遛狗群**：每欄一組可同籠的狗 → 同籠關係的唯一真相來源
- 試算表需設定「知道連結的人可檢視」。
- 狗是否離所／死亡，完全由試算表（已出所分頁）決定，前端只認主清單，不在別處另外維護在所狀態。

### 資料源二：GitHub Repository（`jiatsenK/bq-shelter-dogs`，靜態內容）
- 志工自行維護，Public repo，flat-file 結構，一隻狗一個檔案，比照 Obsidian 筆記慣例：
  ```
  dogs/{編號}.md    ← YAML frontmatter + 自由文字介紹
  photos/{編號}.jpg  ← 照片
  ```
- 一律用「編號」比對，不用犬名——編號入所即固定、終身不變，籠位變動不影響對應。
- 沒有的檔案（404）視為無資料，前端安靜略過，不需要另外維護「哪些狗有資料」的清單。
- 網站本身也用 GitHub Pages 部署在同一個 repo，圖片/內容一律用相對路徑讀取，不需要 CDN 或外部網址。

**v1 明確排除**：試算表寫入。若未來要做，需要試算表管理者另外架設 Google Apps Script Web App 作為寫入入口（涉及編輯權限，非前端工程問題），現階段不預留相關程式碼。
