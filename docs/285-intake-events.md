## 已確認

- A 版：日期與事件在同一列的簡單條列，不增加時間軸裝飾。
- 前端可以編輯；缺事件留空，不補「待補」或猜原因。
- 2026-10-16 提供的黑森林、墨西哥、蘇打、錢錢與 JOJO 圖卡顯示介紹日期與編號日期不一致。事件日期與編號分開儲存，不從編號覆寫實際日期、不推定每次換號都是再入所。
- 原介紹保留，未確認對應的資料不拆解、不遺失；沒有確定編號或日期的紀錄允許留空。沒有自動匯入圖卡資料，JOJO 退回年份仍未確認。
- 同一隻狗的所有編號只是關聯參考；資料跟永久狗 ID，換號不換狗。
- 不寫試算表、不調整入所多久算法、不遷移或更改正式資料。

## 介面與儲存

- 狗卡「入所介紹」保留原本的整段點擊編輯，新增日期、事件、對應編號的逐列欄位，可新增／移除一列。每個已知編號在編輯時提供一個空白日期／事件列，不自動從編號帶入日期。
- `PUT /api/intro/{編號}` 延伸為 `{ editor, text, events?: [{ number, date, event }] }`；date 為 `YYYY-MM-DD` 或空白，number 為同狗編號或空白；最多 30 列，事件合計最多 1000 字。原介紹維持 1000 字限制。
- 回傳 `intakeEvents`，重新讀 `GET /api/dogs` 時，同狗主清單項目也帶此欄位；沒有紀錄則省略。舊版只寫 text 的客戶端保留 events。
- 新增 `v3_intake_events`，依永久狗 ID 和列序儲存，原介紹仍在 `v3_intros`。原介紹與事件以同一個 D1 batch 儲存；編輯紀錄沿用 intro 類型，保存原文與事件的改前／改後。
- 新表列入 `db/compact-schema.sql`，既有同步流程會補建；本次不觸發同步或部署。建表前讀狗清單會退回原介紹；事件寫入會失敗且不更動原文，不在請求中偷偷建表。
