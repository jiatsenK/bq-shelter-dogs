# 2026-10-30 大照片先用縮圖（#791）

- Agent：Claude Code（Opus 5.5），分支 `claude/issue-791-hero-photo`
- 依據：#791，K 10/30 回報「卡片彈出來了，照片空白很久」，同意先放縮圖、原圖到了再換。

## 做了什麼

- `public/js/app.js`：
  - `preloadSharp`：開始下載原圖，已在快取就回 true。
  - `whenSharp`：原圖下載完才換上。
  - `sharpenPhotos`：把畫好的 `img[data-sharp]` 換成原圖。
  - `photoThumb` 的大照片（big）：原圖不在快取時先放縮圖並標 `data-sharp`。
  - `showLightboxPhoto`：放大照片同樣先放縮圖，縮圖讀不到就改回原圖，換別隻或關掉後不會再換。
- `public/js/detail.js` `renderDetail`：畫完呼叫 `sharpenPhotos`。
- `tests/index/photo.js`：原有的「大照片用原圖」改成先用縮圖。新增 #791 測試，用假的 Image 驗三件事：原圖還沒到先放縮圖、載好換上、已在快取直接用原圖。放大照片也驗一樣的行為。

## 例外與要注意的

- 縮圖放大到 480px 會模糊一下，原圖到了就清楚。
- 剛上傳的照片（本機圖片）跟沒有縮圖的照片照舊。
- `tests/index/photo.js` 設計檢查標出的 broken-image 是既有的測試 DOM（空 src 的 img），不是這次加的，沒有加忽略設定。

- 限制：`preloadSharp` 用 `complete` 判斷快取，只認得這一頁已經載過的原圖。重新整理後或隔天再開同一隻狗時，原圖在手機的磁碟快取裡，還是會先閃一下縮圖再換，只是換得很快。同一頁裡重畫不會閃。

  - Spec：補放大照片縮圖讀不到時退回原圖的測試，並記下上面的磁碟快取限制。
