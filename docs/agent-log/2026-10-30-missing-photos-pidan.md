# 2026-10-30 皮蛋照片「消失」：搬籠清舊列不再多建一隻狗

- Agent：Claude Code（Opus 5.5），分支 `claude/missing-photos-37a5b5`
- 依據：K 回報「皮蛋的照片消失了」；判斷條件「同名且備註相同」由 K 決定（2026-10-30）

## 診斷

- 正式 D1 只送 SELECT。照片沒有遺失：`v3_photos` 主照片與 R2 原圖、縮圖都在。
- 12:59:14 試算表出現一列「皮蛋」，沒編號、在舊A13，備註跟有編號的皮蛋（2019120501）一字不差。系統照規則建了一隻新狗（`838ae83f…`），沒有照片。25 秒後這列不見，變成候選，13:17:56 確認移出主清單，進了待核對。
- 試算表現況：皮蛋在新A08、有編號。前後順序是：皮蛋原本在舊A13，暫住列「(皮蛋）」在新A08（11:58 暫住結束）。正式搬過去時，舊列先清掉編號，接著才清名字。
- 重現：一隻有編號、有照片的狗，再送一列同名、沒編號的列，網站資料包就多出一隻沒照片的同名狗。

## 做了什麼

- `worker/src/dog-list.js` `applyMain`：沒編號的列，犬名和備註都跟主清單上一隻有編號的狗相同（備註不是空白），就不建狗、不寫資料，照樣 ack。
- `worker/test/dog-list.test.mjs`：新增回歸測試，先確認修正前是紅的。同名同備註不建狗，網站資料包上只有一隻、照片照舊。備註不同時照樣建狗。
- ADR 0025 補上這條規則。
