## 例外與要注意的

- 「合併」不另開配對 API：照票的「合併走現有合併規則」，資料頁按合併開抽屜用現有合併狗，`mergeDogs` 同一批把配對記成 merged（從抽屜手動選同一組合併也算）。
- 一小時、7 天是推測值，寫在 ADR 0025；錯配可以按「不是同一隻」。
- 配對建立時沒有記修改紀錄（票只要求不是同一隻記一筆）；#775 的「系統自動判斷」列表可以讀 `v3_dog_pairs.created_at`，或到時候再補。
- `/api/manage/data-checks` 與 `readSheetGaps` 拿掉，保險掃描不再寫 `dog_list_extra`（D1 有、試算表沒有的單位照舊回給 Apps Script 記在執行紀錄）。正式庫舊的那一列留著，要清另開 migration（先加後刪）。
- 合併時把被併那隻的 `v3_sheet_gone` 一起刪，取消合併拆回來後不會再跟同籠新狗配對。`v3_sheet_gone` 其他列不清（只有確認消失才寫，一次一列，量很小）。
- 給 #775：`v3_dog_pairs` 只存兩隻狗的 ID 與 `created_at`，沒存當時的列內容；「哪一列消失、哪一列出現」要顯示的話，#775 要決定是在建立配對時多記一筆修改紀錄，或從狗的現況組出來。
- 擁有者要做：套用 D1 migration（`0021`）、部署志工 Worker 與管理網站 Worker。Apps Script 不用重新部署。
