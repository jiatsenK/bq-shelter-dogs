# 遛狗清單 — 前端設計需求

## 背景與痛點

志工每次到收容所要做三件事：看誰很久沒遛、看牠的備註、看牠能跟誰同籠一起遛。目前資料放在 Google 試算表，問題是：
- 要先進雲端硬碟才能打開，多一層點擊
- 資料分散在不同分頁（主清單、常遛狗群），要切來切去
- 試算表不是為「看」設計的介面，手機上容易誤觸到編輯模式

目標：做一個手機瀏覽器打開即用的**唯讀**網頁，把上述三件事在一個畫面內解決。

## 資料來源與限制

- 資料來源是 Google 試算表，志工**不是管理者**，無法修改、無法加欄位、無法用 Apps Script。
- 讀取方式：試算表需設定為「知道連結的人可檢視」，前端透過 Google Visualization API 讀取：
  `https://docs.google.com/spreadsheets/d/{sheetId}/gviz/tq?tqx=out:json`
  不需要 API Key，純前端 fetch 即可。
- 因為後端（試算表結構）不可能更動，前端必須完全照現有欄位設計，不能假設資料會為了介面而調整格式。

### 分頁一：主清單
欄位：籠位、編號、犬名、遛狗日期、誰遛的、備註、（部分列有）疫苗註記。
- 「遛狗日期」用來算「幾天沒遛」。
- 「備註」是自由文字，長短不一，內容包含行為觀察、醫療紀錄、洗澡紀錄等混雜資訊。

### 分頁二：常遛狗群
- 每一「欄」代表一組「可以互相同籠一起遛」的狗，欄位本身沒有標題文字說明用途，但同一欄內狗名即為同group。
- 原本的顏色標示只代表「同一實體籠位」，這個資訊主清單的「籠位」欄已經有，前端不需要另外處理顏色。

### 勿溜標示
沒有獨立欄位標記，從「備註」欄位比對關鍵字：目前只有 **勿溜**（含勿遛、勿蹓等異體字；志工端如發現其他慣用字眼，之後會再補充）。符合的狗**仍留在待巡房排序中**，卡片在天數旁加紅色驚嘆號徽章，備註中的字眼以紅色粗體標出。
（2026-09-24 K 定案：取消原本的「特殊狀況」分頁與「暫緩、住院」關鍵字。住院區只是籠位，那裡的狗照常會遛。）

### 分頁三（新）：狗狗詳細內容
志工自行維護在自己的 GitHub repository（`jiatsenK/bq-shelter-dogs`），與 Google 試算表是**兩個獨立資料源**，前端分別讀取後再合併顯示。網站本身也託管在同一個 repo（GitHub Pages），所以圖片與內容檔案一律用**相對路徑**讀取，不需要 CDN 或外部網址。

**目錄結構**（flat-file，比照 Obsidian 筆記慣例，一隻狗一個檔案）：
```
dogs/
  {編號}.md      ← 狗狗介紹，YAML frontmatter + 自由文字內文
photos/
  {編號}.jpg     ← 狗狗照片
```
`{編號}.md` 範例：
```markdown
---
name: 苗斯
id: 202201678
---
2025 年從街頭救援進來，個性親人，怕鞭炮聲……
```

- 比對鍵一律用「編號」，不要用「犬名」——犬名不保證唯一，且**編號是入所時就固定、終身不變的**，籠位變動、換籠都不影響對應；哪些狗還在所內，一律以 Google 試算表「主清單」為準，Git 端不需要另外維護「在所/離所」狀態，避免兩邊要互相同步。
- 不是每隻狗都會有資料，前端對每個編號嘗試抓取 `dogs/{編號}.md` 與 `photos/{編號}.jpg`，抓不到（404）就視為沒有資料：照片用固定預設圖示頂替、介紹文字略過不顯示，不能因為抓不到而報錯或版面跑掉。不需要另外維護一份「有資料的狗清單」，因為試算表本身就是完整名冊。
- GitHub repo 需設為 **Public**，前端才能直接讀取，不需要 API 金鑰或授權機制。
- 目前僅唯讀顯示，寫入功能（志工直接在網頁上編輯介紹文字）不在第一版範圍內。

## 使用者流程

1. 志工到收容所，打開網頁（手機瀏覽器，理想上加到主畫面圖示，一鍵開啟，不經過雲端硬碟畫面）。
2. 首頁預設停在「待巡房」分頁，依「幾天沒遛」由久到近排序（越久沒遛排越前面）。
3. 所有狗都在「待巡房」排序中；備註寫「勿溜」的狗卡片有紅色驚嘆號，志工核對備註原文再決定要不要遛。
4. 志工選定一隻要遛的狗後，直接在同一張卡片上看到牠的照片（若有）、備註內容、以及可以跟牠一起同籠遛的狗名清單，**不需要跳頁或點開才看到**。
5. 另有「近期已遛」分頁，列出近期（例如 7 天內）已經遛過的狗，方便志工避免重複帶同一隻。
6. 志工也可以用兩種方式直接找狗，不用照排序滑：
   - **搜尋**：輸入犬名文字查詢。
   - **依籠位查看**：列出所有籠位代碼，點進去看目前該籠位有哪些狗，籠位對應完全照主清單「籠位」欄位，不用另外維護。

分頁：**待巡房 ／ 近期已遛 ／ 依籠位**，前兩個分頁各自的隻數以數字顯示在分頁標籤上；搜尋框放在所有分頁最上方，任何分頁都能用。

## 前端設計需求（已定案）

### 「久沒遛」呈現方式：顏色 ＋ 天數
每隻狗顯示明確天數數字（例如「12 天前」），同時用顏色標示緊急程度：
- 綠色／安全：近期已遛（建議 7 天內）
- 黃色／注意：超過 7 天沒遛
- 紅色／緊急：超過 30 天沒遛

顏色與天數同時呈現在同一個標籤上，不要分開放，志工要一眼同時看到「多久」跟「嚴重程度」。

### 「同籠可一起遛」呈現方式：卡片內直接顯示
不需要另外點擊或跳出視窗，也**不需要獨立的狗狗詳情頁**，同籠狗名直接列在該隻狗的卡片內文字裡（例如：「可一起遛：小白、小黑、小黃」）。若無同籠狗，則不顯示此欄。志工滑清單就要能看完所有資訊，不用多一層點擊。

### 搜尋與依籠位瀏覽
- 搜尋框比對犬名，即時篩選，不用按送出。
- 「依籠位」分頁：先列出所有籠位代碼（例如母幼A、住院區、新獨01、新A01…），點一個籠位，顯示目前該籠位內的狗，卡片樣式跟其他分頁一致（照片、備註、同籠狗名）。籠位清單直接從主清單「籠位」欄位去重取得，不用手動維護對照表。

### 照片呈現方式
每張卡片可放一張小尺寸縮圖（非全螢幕大圖），來源見上方「分頁三：狗狗詳細內容」。查無照片時顯示預設圖示，不留空白、不報錯。

### 版面與使用情境
- 手機瀏覽器單欄版面，現場邊走邊看，字要夠大、行距要夠鬆，避免誤觸。
- 純唯讀，畫面上不能有任何看起來像「可以編輯」的元素（輸入框、可勾選框等），避免志工誤以為能修改試算表本身。
- 資料每次打開重新抓取即可，不需要離線或即時同步機制。

## 目前不在範圍內
