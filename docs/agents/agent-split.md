# 把票分給 Claude 和 Codex

1. **依檔案分工**：同一個檔案只交給一方改。一張票同時碰到兩方的檔案時，先拆票，讓每張票只落在一方。目前的分法是 Worker 和網站給 Claude，`scripts/` 底下獨立的腳本給 Codex。
2. **地基給握有決策脈絡的一方**：資料表結構、API 介面這類後面每張票都依賴的工作，交給參與過決策討論的那一方。已經交出去的話，合併前由握有脈絡的一方跑 `/code-review`，對照規格和決策檢查。
3. 在票上寫「負責」，並在規格上列出分工，讓兩邊都看得到。
4. **審查依風險分級**：
   - 只動 `scripts/` 獨立腳本、文件、測試的票：照樣做規範＋規格兩面審查，但在同一個對話裡自己對照，不開審查代理人。
   - 碰正式資料、部署、表結構、API 介面的票：跑完整 `/code-review`（兩個代理人平行審）。
   - 不分級的：全部測試要過；合併、部署、手動觸發同步等影響正式環境的事，先問 K。
   - 每張票做完就結束對話，下一張從票開始，不在同一個對話連做好幾張。
5. **照範例改寫大量檔案交給子代理**（K 2026-10-29 授權，不用每次再問）：同一種改寫要套到好幾個彼此獨立的檔（例如一批測試改用新的 fixture）時，主對話先做共用的部分和一個範例檔，測試跑過，其餘每個檔各交一個子代理。交辦內容是範例檔、要改的那個檔、驗收方式（那個檔的測試全過），子代理只回改了什麼和測試結果。全部收回後，主對話再跑一次完整測試。
