# 資料庫（第 2 步，進行中）

K 2026-10-10 同意：資料從「repo 裡的 JSON 檔＋每天一整份快照」搬到 Cloudflare 的資料庫（D1），改成**現況＋異動紀錄**。
**試算表還是主人**；不做管控，重點是每次改動都有紀錄、可以恢復（像 Notion、Google 試算表的版本紀錄）。整體順序見 `docs/SITE_CONFIG.md` 最後一段。

## 四張表（`db/schema.sql`）

| 表 | 一列是什麼 | 說明 |
|---|---|---|
| `dogs` | 一隻狗的現況 | 編號、名字、性別、籠位、備註、入所介紹、有人固定照顧、上次溜、在所／已離所（日期、原因）、休養到哪天 |
| `walks` | 某天某隻狗被溜 | 一隻一天一筆；誰溜的只存代號，不存名字 |
| `changes` | 某一欄被改了一次 | 時間、哪隻狗、哪一欄、改之前、改之後、誰改的、從哪裡改的（`sheet` 試算表同步／`site` 網站／`import` 舊快照轉的） |
| `kv` | 其他零散的 | 可以一起溜的分組、試算表下面那段異動備註、上次同步時間 |

沒有編號的狗（還沒建檔、暫住標記）用「名:犬名」當 key，跟網站的 `walkKey` 一樣。

## 為什麼不再每天存一整份

每天一份快照約 65 KB、一年約 24 MB，要查「哪天改了什麼」得一份一份打開比。改成只記有變的欄位後，現有 16 天的快照變成 53 筆異動紀錄。
救災用的整份備份交給 D1 自己的 Time Travel（可以回到 30 天內任一時間點），不拿來查歷史。

## 分幾個 PR 做（每一步都可以退回）

1. **建表、轉舊資料的程式和測試**（這個 PR）：`db/schema.sql`、`scripts/build-db.mjs`、`scripts/build-db.test.mjs`。只有程式，不動正式網站、還沒建資料庫。
2. 在 Cloudflare 建資料庫、部署時自動套 `schema.sql`、把現有資料匯進去（`node scripts/build-db.mjs > seed.sql` 再 `wrangler d1 execute`）。Worker 多一個資料庫的 binding，但網站還是讀原本的檔案。
3. 同步試算表時也寫進資料庫：跟資料庫比對，只更新有變的欄位，同時在 `changes` 記一筆（`source = sheet`）；網站上的溜了、改介紹、休養也各記一筆（`source = site`）。這段期間 JSON 檔照舊產生，兩邊並行、可以互相核對。
4. 網站改讀資料庫（Worker 的 `/api`），確認一陣子沒問題後停掉每日快照、刪掉 `data/history/`。
5. （第 3 步）異動紀錄畫面和還原；全部匯出成試算表檔。

## 本機試跑

```
node scripts/build-db.mjs > seed.sql      # 印出 INSERT，最後一行（stderr）是各表幾筆
node --test scripts/build-db.test.mjs     # 有 node:sqlite 的 Node 會真的建表、匯入兩次確認不重複
```

## 還原在試算表當主人時的限制

有人在試算表改錯：網站查得到原本是什麼（`changes.old`），但不能寫回試算表（`AGENTS.md`：網站只能改「遛狗日期」「誰遛的」兩欄），要人到試算表改回來。主人換成網站之後才是一鍵還原。
