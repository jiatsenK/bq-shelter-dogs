# 歷史溜狗與離所遷移（#217）

入口 `migrateHistory(db, input)`，先套版本化結構與 #216 身分對應。只操作傳入的隔離 D1，不由部署或 Worker 呼叫。`0002_history_sources.sql` 增加來源追溯表；既有 17 張模型表不改欄位。

## 歷史與證據

- 2026-09-25 前的溜狗 evidence 為 legacy；以入所＋日期 upsert。志工代號去重、已確認別名連原 walker，不從姓名猜配。同狗跨入所同日仍保留各次入所紀錄，統計以狗＋日期去重。
- 09-25 起用每個台灣日期最後一次成功快照；failed 不取代成功快照。當天尚未結束為 provisional，已結束為 final。重建同日快照可 superseded 舊的當日推定；隔天的新日期不取消昨日 final。
- 同一日期後來看到名單改變可更新參與者。參與者關聯是當下名單投影，更新時替換；每份原始來源名單保留於來源表。
- 快照缺少當日證據的舊 walks 不直接刪除，也不當作有效紀錄。`historyDecisions` 以 `編號或名:正規化名字|日期` 指定 retain／exclude，必須有 K 的證據。未決保持 pending；排除用 cancelled 保存紀錄，不刪原始來源。
- 來源鍵由來源路徑、資料內容與重複序號組成；同筆來源重跑 upsert。重複 walks 每筆都有來源，來源重排也不因陣列位置覆蓋另一筆。

`v2_history_sources` 有 source_kind、source_key、raw_json、處理狀態／原因、對應入所與溜狗 ID；外鍵 RESTRICT。imported／pending／ignored 都保留原文，不將快照缺席視為從未溜狗。檢核來源總筆數、重跑筆數、外鍵，以及各來源的去處。

## 離所來源

已出所每個有合法編號的來源列是實際離所來源，能補快照前離所；編號認既有入所，沒有既有編號則依分頁建立實際狗／入所，不由狗卡猜配。狗仍在主清單同次入所時標矛盾待確認，不改在所狀態。再入所狗的舊入所離所不影響新入所。

原因沿用現有關鍵字分類，每次演練重新判讀。沒有／退養／互相矛盾的原因為 pending。日期優先採離所原因附近的明確備註日期；分頁 D 表頭仍是「遛狗日期」，不把它一律當離所日。缺明確日期的離所保留空日期及原文待確認。芊芊 9/18、豆花 10/2 已有 K 在 #212 的明確日期與 #213 讀回證據，允許使用相符的分頁日期。

資料庫 departed_date_source 依現有模型存 note（明確分頁事實）；來源表另保存 note／sheet_date_column／ambiguous_walk_date_column 的細分。repo departures.json 的消失觀察保存為 seen 的原始來源，不能冒充新的已確認離所；分頁事實已有對應時標為被分頁取代。

重複分頁列各保存一筆來源，編號不重建狗。未編號、混合名字與編號的儲存格、未來日期、仍在所衝突、原因或日期無法確認，全部保留待確認。私密分頁原文只讀入作業系統暫存及演練 SQLite，不加入 repo／PR。
