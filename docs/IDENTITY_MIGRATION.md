# 狗與入所身分遷移（#216）

入口 `migrateIdentities(db, input)` 在 `scripts/migrate-identities.mjs`。套用 #215 結構後明確呼叫才寫傳入的 D1；不連正式服務、不寫試算表、不切換 Worker。

## 來源與可靠關係

- `dogs`：主清單的狗名、編號、籠位、有人固定照顧、試算表備註。狗名以此為準，狗卡名字不覆蓋。
- `cards`：編號與 `formerIds`，可附原文保存。沒有可靠編號對應的狗卡不建立新狗。
- `sources`：`{ source, rows }` 的舊資料檔或每日快照；每個來源鍵都有對照或待確認紀錄。
- `confirmedMappings`：`{ sourceKey, targetNumber, relation, evidence }`。relation 是 `same_admission`（補編號／更正）或 `readmission`（另次入所），必須有確認證據；不能只因同名推測。

有編號以編號認身分；無編號的來源鍵為 `名:` 加 NFKC、去全部空白的狗名。編號更正併同次入所，再入所另建入所，永久狗 ID 不變。狗卡明載 formerIds 即可建立可靠再入所關係；舊入所先 unknown。編號前 8 碼較新的入所目前在所；試算表若寫舊號，主清單對到同狗現行入所，舊快照則仍對原本入所。

暫住須同時符合無編號、括號名、主清單唯一同名狗。全形括號先 NFKC；有編號的括號名只以編號處理。兩隻同名、或括號沒有唯一對象，保留待確認。未有證據的歷史無編號補編號不自動合併。

`v2_source_bindings` 保存來源路徑、來源鍵、原始資料及判斷原因。binding_id 是來源路徑＋正規化鍵的雜湊；這只是來源 ID，永久狗 ID 為隨機值。已確認來源連入所，候選來源保留原文且入所空白。回傳 mapping／pending 可供後續 CSV 封存與遷移核對。

來源內若有重複編號或 NFKC 正規化後撞鍵，在任何寫入前停止並報來源位置，不以後筆覆蓋前筆原文。經主清單唯一同名判定的暫住來源（含快照）對目前入所，與主清單暫住相同。

每隻狗及主清單對應在同一個 batch 保存，避免半途失敗後無編號狗重建。以既有編號／來源對應讀回 ID，重跑 upsert 不增筆。涉及兩個已建立狗 ID 或兩次既有入所的錯誤合併直接停止，不偷偷刪除或重綁；錯誤修正需另有已確認決策。批次失敗回復，先前已完成的狗可安全重跑。

入所來源、原因留空，不解析介紹。介紹來源、原文、休養、照片與開卡的實際搬遷留 #218；離所與歷史溜狗留 #217。重跑身分遷移保留舊入所已確認的離所狀態、籠位、備註。
