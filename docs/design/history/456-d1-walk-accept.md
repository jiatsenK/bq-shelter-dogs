# #456 單狗 D1 接受與一次試算表派送

依據：#456；固定規格 `444c33e:docs/design/441-d1-walk-sync-spec.md`、同版 ADR 0017 與 ADR 0016，ADR 0006／0008。這些固定文件仍在 `prototype/d1-walk-sync`，本票不帶入原型程式或合併該分支。

## 本票入口與責任

- `POST /api/walk` 的單狗 `walk` 要求帶 `requestId`（8–100 位英數、底線、連字號）及台灣 `operationDate`。未帶識別的既有入口繼續服務尚未接管的狗；已接管則拒絕舊入口改寫。
- 成功回應含 `accepted`、原操作日期、單狗版本、有效日期／名單、前值、同步狀態及一致快照。`GET /api/walk/result?requestId=…` 可查回應遺失的結果，包含跨日查詢；過期原日期不允許當新登記重送。
- 前端共用 `walk-registration` 保存尚未查明的原要求；識別無法可靠存回手機時不送出。D1 接受前不更新為已溜。已接管的狀態不再接受舊 today、walkers、狗清單日期或本機已溜紀錄覆蓋。
- `GET /api/today?source=d1` 讀取獨立資料包一列，版本與內容同一快照；午夜只換今天判定。後續完整包分段與 CPU／帳號成本驗收留給最後子票。
- `SITE.d1WalkAccept` 預設 `false`。本票的本機整合測試覆寫為 `true` 驗證整條單狗路徑；正式所有入口切換是最後子票，不能單獨開啟這個設定部署。修改名單、復原、整群新協定由後續子票處理；本票不宣稱 #441 完成。

## 原子接受與持久工作

`v3_walk_state` 保存每狗最新有效日期／名單、固定志工身分、前次值、一致基準與單調版本。登記使用既有名字對應固定身分，不新建或合併人；名字中間空白照既有規則拆開。以版本 guard 重讀／重算聯集，最多八次，競爭不收斂回明確未接受。

同一 D1 batch 寫狀態、`v3_walk_requests` 去重結果、舊工作取代、新 `v3_walk_outbox`、讀取投影／版本與寫入預算。任一步失敗整筆回復。去重識別全域唯一，相同內容重送回原結果且不再寫資料；不同內容拒絕。識別目前不清除，涵蓋完整未完成生命週期及次日；清理策略留待後續維護，不提前刪除。

狀態／投影專表不在差異同步的可寫清單；舊同步仍可維護試算表複本及既有歷史，但不能回灌已接管的顯示路徑。所有新表、索引、預設列與觸發器都在 `db/compact-schema.sql`，沿用同步整份建表流程，handler 不建表。

## 一次派送與確認

API 只將派送掛在 `ctx.waitUntil`，不等待 Google 回應。缺少 context 時工作仍為 pending。每狗 `v3_walk_delivery` 以持久 guard 限制一位執行中的派送者；不以記憶體鎖協調。工作保存原操作日期、目標、版本、派送識別、狀態、下次嘗試時間與錯誤。Google 逾時／失敗保留 retry 與 D1 已接受內容；Cron、退避、執行中斷後 delivery 恢復留給後續子票，這裡不新增排程，也不把租約到期當 Google 已停止。

Apps Script 增加 `walkWake`。設定 `WRITE_KEY`（必填）與 `WALK_WORKER_URL`（Worker 的 HTTPS origin），沿用 `SHEET_ID`。機器端點用對應 `SHEET_WRITE_KEY` 驗證；預覽版禁止寫回。這是程式碼與設定說明，未改線上指令碼屬性或部署。

同一 script lock 內：直接讀表、按編號（無編號才唯一且無編號的狗名）定位 → Worker 比對一致基準並以原子版本 guard 授予目前 D1 目標／版本／派送識別 → 再讀表重新定位，值有變立即停寫 → 只整格替換主清單日期與名單 → flush 後直接讀回 → 版本／派送識別／值全部吻合才確認。目前目標的可信讀值可確認回應遺失；可信舊回執只記 `readback_seen`，不清除目前工作，下一輪可從該已知中間值補正最新目標。未取得可信回執的模糊中間值及其他可見衝突停寫並留 retry，完整人工三方比較／納入 D1 由人工通知子票延伸，不把舊快照強制當人工值。後續派送仍須走同一入口和鎖。

設定新 Worker URL 後，舊 walk/edit/undo 在鎖內也詢問 `legacy-check`；已接管或不能確認即停寫。延遲喚醒不攜帶整格目標，Worker 永遠取目前版本；逆序回執不能清除較新工作。人工剛好在最後核對與寫入間隙改格仍可能被蓋掉，這是已確認方案 A 的限制。

## 本機預演與驗證

`node worker/test/walk-cost-preview.mjs` 使用記憶體 SQLite 與失敗 adapter，不呼叫正式服務。

| 情境 | SQLite 寫列（含 guard／預算／版本與投影觸發器） | 保守保留量（含索引成本） |
|---|---:|---:|
| 接受一次 | 9 | 32 |
| 同請求重送 | 0 | 0 |
| 取得派送者、失敗留存、釋放派送者 | 14 | 32 |
| 接收端取得目標／讀回確認 | 由 API adapter 測試驗證 | 各 16 |

每個交易遵守 `SYNC_MAX_ROWS`（預設 500）與 `SYNC_DAILY_BUDGET`（預設 20,000），以 UTC 日期累計此路徑的保守保留量。若 Worker 有帳號 ID／Analytics token，沿用既有帳號查詢；查不到則警告並套單次門檻與本路徑持久保留量，不把缺值當零。這不是全帳號跨服務的原子預算，也不是正式 CPU／整日用量驗收。量測型帳號分析本身仍有延遲；最終免費方案驗收依母票要求進行。

新 schema 的空資料包初始列只在建表時新增一次，不是心跳。同步既有預演會帶入整份 schema；正常同步不更新此包或工作。機器端點無工作或重複已確認回執不更新狀態。待處理索引只含 pending／retry／unconfirmed，不掃描全部已完成歷史。

驗證接縫依票內約定：Worker API／真 SQLite D1、GAS sheet adapter、共用 registration 狀態及 headless Playwright。涵蓋原子失敗、並行、去重、回應遺失、逆序回執與舊中間值補正、授予前版本競爭、冷讀一列、跨日、舊同步隔離、排序／歧義／移走與寫前人工修改。依 #408 補十倍歷史工作資料的固定 API 讀寫量及 active 索引 query plan 檢查。完整 Node 360／360、網頁 261／261 與全部互動套件通過（含新 `walk-accept` 套件）。沒有獨立 TypeScript typecheck 設定，改動 JS 語法檢查通過；GAS 由 VM adapter 執行驗證。未做正式資料遷移、部署或額外線上實測，測試服務保持停用。
