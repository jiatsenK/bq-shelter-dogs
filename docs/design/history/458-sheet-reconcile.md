# #458 人工改表的可信比對

依據 #458、#441 固定規格 `444c33e:docs/design/441-d1-walk-sync-spec.md`、同版 ADR 0017，及 ADR 0006／0008。產品已接受方案 A 的最後讀寫間隙風險；不能因此忽略已觀測修改。本票不搬入原型程式，不新增排程或線上驗證。

## 入口與部署邊界

`POST /api/sheet-changed` 沿用 `SHEET_NOTIFY_KEY`，驗證後保留既有 `v3_sync_state.changed` 供非溜狗資料同步。請求內容一律不作格子值；預覽版拒絕。

新增 Worker 變數 `D1_WALK_NOTIFY=1` 才立即執行可信比較，預設未啟用。這沿用 #456 的漸進切換界線：`SITE.d1WalkAccept` 仍關閉，#441 最後入口整合完成前不能單獨啟用通知接管，否則舊登記入口會被已接管狀態擋下。本票沒有改正式變數或部署 GAS／Worker。

啟用後，Worker 用 `SHEET_WRITE_URL`／`SHEET_WRITE_KEY` 呼叫 GAS `walkCompare`。GAS 沿用 `WRITE_KEY`、`WALK_WORKER_URL`、`SHEET_ID` 及同一個 script lock，直接讀主清單，再由機器驗證的 `POST /api/walk-writeback/observe` 接受最多十隻的觀測。沒有從 gviz 接收人工修正的入口。通知不是完成承諾；成功回應另外區分 `comparison.compared`、`merged`、`pending` 或未啟用的 `deferred`。

GAS 以編號對應，無編號才取唯一且無編號犬名；排序只影響本次讀取的列位置。Worker 傳目前主清單的四欄一致基準，GAS 沿用 #459 的四欄直接掃描，只送不同的日期／名單，不下載備註等完整內容。新狗仍待既有清單同步建立 canonical dog；狗消失或對應不唯一留待處理，不猜測。每輪最多處理五隻有差異的狗；超出留下 pending，由已合併 #459 排程分批補完，已接受的每狗交易不回復。

固定規格「主清單比對可用單份快照與按主鍵的差異查詢，不逐狗發出遠端請求」是本次背景通知同步的依據；此處一次讀取必要主清單基準，與單狗 API 不整張讀的規則分開計量。查詢上限 501 列，超過 500 隻即停留 pending，不發出 GAS 呼叫；不能將這份背景同步成本宣稱為單狗固定讀取成本。十倍測試驗證單狗 observe／target 的讀寫量固定、歷史查詢用索引；通知則不讀 outbox 歷史，主清單由 1 列變 10 列只增加必要的 9 列，控制寫入量不增加。

## 比較與版本

以最後一致值 B、D1 現況 D、同鎖直接讀表值 S 比較：

- S=B：保留 D 及未完成工作，不把舊基準蓋回。
- 可信 S 與目前派送目標吻合：條件式確認目前版本。舊可信回執只在最新一致／人工觀測界線之後且已 superseded，才作已知中間值；更早歷史相同名單不得授權覆寫，不結清新工作。
- D=B 且 S 改變：接受 S；同日期的並行改動依相對 B 的增刪合併。例如 B=甲丙、D=甲丙乙、S=丙，結果為丙乙。
- 確認的清空名單／整筆清空或改日期：接受人工修正為新版本，舊 pending 取代。日期可改早，後續新登記由新狀態開始。
- 可能是未確認舊派送、或日期與名單只寫完一欄的中間結果：停寫並保存診斷，不以秒數推斷完成。

接受人工修改時，一次 D1 batch 比較版本並更新有效狀態、固定身分名單、B、前值、被取代工作、新工作、讀取投影、版本與預算。S 即最終值則工作為 synced；需要把並行合併結果寫回才為 pending。自由改表的新名字保留來源文字，不建立、猜測或合併志工身分。

整合 #457：同日人工改名單保留原復原前值，不將今天被刪掉的人當作上次溜。可信前次名單中的未註冊名字可按原文還原；操作者及外部請求仍須經既有嚴格身分驗證。已知且在因果界線內的程式中間值，即使新復原目標剛好等於 B，也不能誤接為新人工修改。

`v3_walk_baselines` 與目前版本的可信確認／人工修正同交易更新因果界線；舊庫缺這列時，以按狗索引的最新 synced 版本為基線。未確認及已知中間值查詢都有對應的部分複合索引，不掃同狗全部完成歷史；歷史名單恰巧等於新的人工刪名結果，仍進入正常三方比較。

所有手機仍由 D1 讀取投影：日期與名單共同換版，`walkedDate` 同時決定今日判定及最新有效日期。沒有加入手機讀 Google 或另一套前端合併流程；所有入口的正式切換與前端驗收留給其子票。

GAS `walkWake` 在寫前再次定位／讀取後，若發現值改變，先將新觀測送回 `observe`，停止該次寫入；即使新觀測已被 D1 接受也不在同一喚醒繼續寫。人工在最後核對與寫入之間改格仍可能被蓋掉，這是已接受的方案 A 限制。

## 持久待處理與排程子票交接

`v3_walk_compare` 單列保存通知狀態、owner、重送 again、開始時間及錯誤。D1 條件更新只授予一位比較者，並行通知合併為一次補讀；單個要求最多兩輪。失敗或仍有新通知時保留 pending，不將 HTTP 200／單獨 ok 當作完成；完成須核對 GAS `walkCompare-v1` 回應及完整比較結果。

`v3_walk_conflicts` 按狗保存無法分類的觀測與原因；相同診斷不重寫，之後可信比較成功才清除。這兩張表都在正式 schema，同步依原有整份補建規則處理，不在 handler 建表。

整合已合併 #459：啟用兩個既有開關後，`retryWalks` 會先補 pending／因執行中斷超過一分鐘的 running 通知。owner 與 started_at 僅讓新的讀表者取得重新比較資格，不當作 Google 已停止或同步成功；仍在同一 GAS 鎖取得新觀測，並經版本 guard。舊 owner 完成不能清掉新 owner 的工作。本票沒有更改排程頻率或啟用正式開關；完整通知遺失仍由 #459 的保險掃描及新 target 比較補漏。

## 本機預演與驗證

`node worker/test/walk-reconcile-cost-preview.mjs` 使用合成資料及記憶體 SQLite；`total_changes()` 含 guard、預算、資料包與版本觸發器，索引另以保守保留量計入：

| 情境 | 實際變動列 |
|---|---:|
| 舊一致基準，不動網站 pending | 0 |
| 人工刪名＋網站加名 | 11 |
| 同觀測重送 | 0 |
| 人工清空取代 pending | 12 |
| 人工改早日期 | 11 |
| 通知控制 claim／完成，資料無差異 | 8 |
| 通知失敗保留 pending | 8 |

每狗比較保留 32 列，診斷／清除另外最多 8 列，控制轉移每次 8 列。通知最多兩輪、每輪五隻，加最多五次控制轉移，保守上界 440 列；機器批次十隻上界 400 列。重送要求的控制轉移各自計量。既有 `SYNC_MAX_ROWS`、`SYNC_DAILY_BUDGET` 與帳號分析檢查沿用；帳號分析不可用警告，不視為零。通知的控制轉移有實際事件才寫，不新增定時心跳。

假設一天 N 次通知（不含合併及失敗重試），只有無差異控制的部分為 8N 實際列、最多 16N 保留列；最壞比較量另外依上述上界累計，與網站操作、既有同步及其他服務共用每日預算。這是本機模型，不是正式一天用量、CPU、觸發器送達時間或免費額度驗收；無新增線上實測授權。

測試邊界已經 K 確認：通知 API；可信讀表／寫表介面的同步協調器。使用真實記憶體 SQLite 與 GAS VM adapter，涵蓋人工刪名、清空、改早日期、pending、新登記、舊基準、未知／半格派送、偽造通知、重送合併、HTTP 假成功、排序、對狗歧義與寫前停寫回報。沒有聲稱測試已驗證 Google 安裝型觸發器、最後讀寫間隙競爭或完整線上管線。
