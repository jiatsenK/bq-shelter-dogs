# 主頁導覽、資訊與常遛狗群實作規格

日期：2026-10-17。整理：CODEX。K 已確認三項範圍、常遛狗群最後示意，以及三張票、一票一個新實作視窗。

## Problem Statement

手機需要已確認的四個主入口；資訊內容需要分組；常遛狗群需要迅速認狗、整群登記並排除少數例外。設計已定版，下一步是完成真實功能，不再重畫方向。

## Solution

依序完成「主頁底部導覽 → 資訊 #273 → 常遛狗群」；每張票有可獨立展示的實際行為、測試與審查。使用既有 API、活動核心與資料規則，不以靜態原型取代正式讀寫。

## User Stories

1. 志工可從底部依序進入遛狗表、常遛狗群、我溜過、資訊，快速找到工作內容。
2. 志工切換與返回後可辨認所在位置，主頁既有搜尋、照片／列表、常溜與登記能力保持。
3. 志工從狗的籠位仍可看位置，不因底部撤下找狗而失去定位。
4. 志工在資訊首頁看到五個分類與少量真實摘要，再進子頁看完整內容。
5. 志工可查在所統計、離所名冊、缺資料，以及網站／資料編輯更新紀錄。
6. 志工可直接看到每場活動的狗，並在手機、桌機新增、修改或刪除活動。
7. 志工左右滑動整個狗群，從較淡的後景得知還有其他群。
8. 志工用照片、狗名、籠號認狗；少數群與大群採同一種卡片規則。
9. 志工用白話讀懂最近溜過的對象與時間，需要時查看個別日期。
10. 志工通常一次登記整群，少數沒溜時才排除；仍可只登記一隻。
11. 志工在每群的「＋」卡加入狗，或由「＋狗群」建立新群。
12. 志工可分辨載入、空資料、休養、寫入中、失敗與成功，不把示意或未完成的動作當成已儲存。
13. 使用鍵盤或開啟減少動態效果的志工，同樣能切群、排除與登記。

## Implementation Decisions

### 共用界線

- 主頁內容與視覺已定版，只實作已確認的底部入口與切換，不重新設計頁首或狗卡。
- 定版主頁：[參考圖](../mobile-home-approved-2026-10-17.png)。定版狗群：[參考與原型](../common-walk-groups-approved-2026-10-17/README.md)。兩者用途不同，狗群原型的簡化頁首不得覆蓋主頁。
- 字體沿用系統繁中；沿用原站色票，不引入另一套介面或圖示庫。互動區至少 44×44px，支援安全區與 320／390px。
- 共用導覽的名稱、目前選取狀態、返回／關閉、手機返回與焦點恢復由第一票固定，後兩票承接。
- 第一票須讓四個入口可操作：狗群與資訊先接既有正式內容，後兩票再替換內容；不得以無回應按鈕、空面板或假成功算完成，也不提前包辦後兩票。
- 狗群內滑動只換狗群，不同時觸發外層主分類切換；上下捲動、點新增或點排除不可誤判成換群。

### 資訊

沿用 [#273 規格](273-info-page.md)，不建立第四張整理票。五類與順序為在所統計、離所紀錄、活動紀錄、資料檢查、更新紀錄。資訊頁不放已撤回的遛狗狀況圖表與久未溜分類。

活動核心由既有 #270 承接，#273 完整驗收須等核心能力；資訊架構可先做。離所讀取須核對同期 #362／#363 的最新資料契約，不依賴本工作樹的舊資料包形狀。網站更新只顯示正式已上線內容；資料編輯沿用既有紀錄來源。

### 常遛狗群：外觀與閱讀

- 一次一群、左右切換，其他群縮小、變淡浮在後景；後景不顯示「＋」新增卡。
- 密集交錯斜照片卡。籠號獨立放右上窄邊，淡灰綠底／深灰綠字；照片保持不被文字覆蓋；姓名在下緣，不在下方動作區重複姓名。
- 姓名比籠號／摘要更強，維持 12px 以上可讀字級；定版示意姓名 13px、籠號 12px。這是照片卡的密集標籤，不將主頁原本字級一併縮小。
- 卡片不常駐日期。群名下使用白話：同日「10 隻今天都溜過」；不同日「捷運站昨天溜過；甜甜前天溜過」。正式文字隨真實數量、日期、今日暫存更新，不固定兩群或今天／昨天／前天三種值。
- 多日期必須明確對應到狗；長摘要可收合／展開，但不能退回只有天數與隻數的難讀統計。未知日期、讀取失敗、無紀錄分開呈現，個別狗的正確日期可查閱。
- 全群同日不代表曾同一次整群出勤，不新增此推論或群出勤資料模型。
- 十隻／兩隻用同一套卡片與舞台規則；少數群不靠放大照片填空。全量群均可到達，不把 11 個非空群快照寫死成總數。

### 常遛狗群：操作

- 預設不逐張勾選，主要按鈕是「整群溜了 · N 隻」；同旁提供較低強度的「有狗沒溜」。
- 點「有狗沒溜」進排除模式，在原本卡片切換本次未溜者；顯示排除狀態與「登記其餘 N 隻」。可恢復、可取消；全部排除時不可送出。
- 排除只改本次登記名單，不把狗永久移出群、不改休養狀態；切群或取消後不把上一群的排除誤套下一群。
- 真正送出的狗、志工身分、台灣日期、成功與失敗均沿用既有溜狗流程。休養中與其他不可帶出者沿用現有規則，不可盲目把所有成員當可登記。
- 每群的空白「＋」卡加入成員，另有「＋狗群」；沿用既有狗群欄與群名資料、寫入限制。群成員與「可以一起溜」關係並非可任意互換的資料模型；不要從名稱或圖形推論相容性。
- 保留既有狗群管理能力與舊入口的可用性，不因換排版漏掉移出成員等既有操作。既有移出確認與寫入流程繼續遵守。
- 動態只解釋前後群的空間關係、觸碰放大及選取回饋；沒有自動漂浮循環。可中斷或反向拖動，減少動態效果時仍可操作，不加動態套件。

### 資料契約

先讀相關 ADR，沿用既有讀取與寫入端點，不因介面定版另建後端、改表或搬資料。狗群來源是具群名／欄位的既有群資料，不把狗的鄰接關係任意當成群。

ADR 0006 限制試算表寫入範圍；0004 規範編輯身分與紀錄；0007 規範今日溜過更新。個人身分與資料沿用 0001／0005；活動沿用 0002。涉及新 D1 寫入／同步／版本資料包時再核對 0008／0009，不能自行擴增正式資料操作。

## Testing Decisions

- 優先沿用現有的瀏覽器使用流程測試，以 DOM 可見行為、真實形狀的 fixture 與 mock API 驗證，不測私有函式拼法。
- 共用導覽：四個入口、目前選取、往返與焦點；主頁搜尋、常溜、照片／列表、定位、我溜過與桌機回歸。
- 資訊：五類往返、既有名單／篩選、活動新增修改刪除與編輯紀錄整合；失敗不得冒充零或成功。
- 狗群：全量群逐一到達、兩隻／十隻／空群、缺照片／長名字、單一與不同最後日期、未知紀錄；日期不回填成卡片常駐欄位。
- 登記：整群、排除／恢復／取消、只留一隻、全排除、切群後重設；用 mock 捕捉實際送出名單，檢查身分、成功、部分／全部失敗與重試，不在驗收時寫正式資料。
- 群編輯：加入既有狗、重複加入、建立群與既有移出流程；遵循既有 API 及 ADR，成功重新讀回，失敗保留可重試內容。
- 觸控與鍵盤：滑動中斷、反向、外層不跟著切分類、觸碰放大、鍵盤及減少動態效果；檢查 320／390px 與桌機、文字不裁切、安全區與點擊目標。
- 每票執行 AGENTS.md 的 Node／網頁檢查及適當 code-review，記錄執行版本與結果。設計原型的檢查結果不能替代正式程式的驗收。

## Out of Scope

本輪整理不包含開始實作、新增實作視窗、commit／push／PR、合併、部署、執行同步或正式資料寫入。後續實作票依既有流程逐票執行；合併與部署仍另待 K 確認。

不重做主頁、不重開視覺探索、不新增群相容性推論或另一套活動／編輯後端、不自動匯入舊資料、不改其他未提交工作。
