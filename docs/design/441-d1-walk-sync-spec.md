# #441 今日溜狗 D1 正本與試算表寫回規格

日期：2026-10-21。狀態：產品規則與人工同時寫入方案 A 已確認，方案收斂／規格整理完成，可據此提出拆票清單；不是實作／部署授權。依據 [ADR 0017](../adr/0017-today-walks-d1-source.md)；工程方案的實作與驗收尚未完成。

## 問題

志工按溜了、改名單或復原後，不同手機與試算表可能顯示不同結果。取消未反映到試算表是 K 提供的驗收案例；黑寶／MINI 名字不同步是另一回報，尚不能認定為同一已查明根因。

## 使用者可見結果

1. 志工登記後，D1 接受才顯示今天已溜及名字，不等待試算表。
2. 同狗同日甲、乙同時登記，兩名都保留；重送同一要求不多加一次。
3. D1 拒絕或尚未確認時，不顯示已完成；網路中斷後用原請求識別查詢／重送，避免重複操作。
4. D1 接受後，試算表未完成顯示「試算表同步中」；失敗顯示「試算表尚未同步，會自動重試」，不要求重按，也不退回已溜狀態。
5. 同步小字放在該狗現有登記／名單控制區下方，狗卡、詳細資訊及狗群同一筆狀態一致；不跳 toast、不增加主要按鈕、不改既有顏色與排序規則。具體版面在實作時依現行設計規格檢核。
6. 完成只在目前版本的目標日期與名單取得可信讀回、且 D1 已記下確認後成立；單純收到 HTTP 200 或舊版本成功回應不能收起小字。
7. 前景每分鐘檢查版本；切回前景距上次讀取超過 30 秒即讀。一般正常讀取下其他手機下一輪可看到，不承諾網路故障時仍在一分鐘內成功。
8. 人工刪名或清空，經通知或保險比對確認並存入 D1 後，所有手機跟著刪，不被本機紀錄或舊待寫回工作加回。
9. 人工改日期同時更新今天是否已溜及上次溜，不只更新名字。
10. 名單只剩一人且最新紀錄是今天，任何選好身分的志工都可復原；換手機仍可用，由伺服器取得前一筆日期與名單，從未溜過則空白。
11. 復原前別人已改名單即停止，回目前狀態；多人時沿用逐名移除，不能刪掉他人較新登記。
12. 復原留誰、何時、哪隻狗、改前與改後的編輯紀錄；一般登記不因此新增編輯紀錄。
13. 午夜後不能復原昨天；午夜前已接受的工作仍以原日期重試，不誤記今天。
14. 讀取失敗保留最後一次 D1 確認內容，下次再試；首次沒有資料就保留載入／未取得狀態，不把未知顯示成沒人溜。
15. 「更新」重新讀 D1 並沿用既有重排；若需讀表，由伺服器比對後再回 D1 結果，手機不直接混入試算表資料。
16. **每隻狗只呈現最新一次**（K 本輪確認）：網站最新狀態與試算表主清單顯示相同的最新有效日期／名單。昨天甲未同步，今天乙已登記，就顯示今天乙；舊工作不能改回昨天甲。本項不刪既有歷史資料、不新增兩天紀錄並列展示，也不取代同狗同日保留多人名單的規則。
17. **保留自由手改，接受方案 A 的同時寫入限制**（K 本輪選 A）：程式寫入前核對，觀測到人工修改先納入 D1，衝突時停止該次覆寫並重新比對；人工恰好在最後核對與寫入之間改格，仍可能被蓋掉。這項剩餘風險已接受，不要求志工改成只能從網站修改。已觀測到的刪名／清空仍必須處理，不能拿本項當作無條件覆寫的理由。

## 伺服器契約與資料責任

### 操作接受

沿用 walk／edit／undo 的入口與前端共用狀態介面，擴充請求識別、操作日期、狗識別及必要的預期版本。身分驗證沿用現有規則，不以名字字串創造或合併志工。單狗結果至少區分已接受、現況已改變、未接受、結果待查；整群回傳逐狗結果，不能把部分成功宣稱全部完成。

已接受回應包含請求識別、狗、原操作日期、目前版本、有效日期／名單、上次溜及試算表同步狀態。名單修改與復原須條件式更新；登記加名則基於當下版本計算去重聯集，競爭時重新讀當下狀態，不用舊整格覆蓋。請求識別相同但內容不同應拒絕。

一次原子提交包含有效狀態、去重結果、待寫回工作、必要編輯紀錄及版本／讀取投影；任一失敗都不能回已接受。新資料表、索引與觸發器納入正式 schema 與同步建表流程，不能在 request handler 臨時建表。具體 SQL 留到實作，不複製 bench441_ 表作正式結構。

### 寫回與確認

工作保存狗識別、原日期、目標日期／名單、工作版本、上次一致值、重試時間、派送識別、嘗試狀態及錯誤分類。已完成工作不列入待處理掃描；以到期時間及未完成狀態的索引分批取件，不能每分鐘掃完整歷史。

內部狀態為待派送、派送中、待確認、延後重試、已一致、已被較新版本取代。前四者映射為同步中或失敗重試；已一致才收起；被取代的工作不再派送，由目前版本決定畫面。同步狀態變化也必須使前端可讀版本改變。

同狗單一派送者以持久狀態取得工作，不依賴 isolate 記憶體鎖。接收端在同一 Apps Script 鎖內向 D1 重新取最新目標，舊請求只負責喚醒，不能直接攜舊整格值重放，詳見下方協定。逾時未決時不得把租約到期當成 Google 已停止執行；後續派送也走相同入口與鎖。不在試算表新增控制欄。此為工程提案，尚未實作或證實解決所有競爭。

Apps Script 寫入前直接讀主清單，按編號（無編號才按唯一狗名）重新定位，不沿用排序前列號；比對預期日期／名單，再整格替換兩欄並直接讀回。回應必須帶派送識別、工作版本及讀回值；未知回應先查明，不盲目附加或覆寫。人工修改不受 script lock 保護，依方案 A 做寫前再次核對與衝突停寫，不承諾最後讀寫間隙完全受保護，也不能宣稱該比較具有資料庫 CAS 保證。

### 人工修正與衝突

比對輸入為「最後確認一致值 B、目前 D1 值 D、可信試算表值 S」，日期與名單共同處理。僅 gviz 舊讀取不算可信人工修正證據。

| 情況 | 必須行為 |
|---|---|
| S = B，D 有未完成變更 | 保留 D 及工作，不拿舊值覆蓋 |
| S = 目前工作目標，讀回與派送版本可信 | 條件式記為一致；較舊回執不得清掉新工作 |
| D = B，確認 S 已改 | 接受 S 為 D1 新版本，不產生無意義反向寫回 |
| 同日期，網站加乙、人工刪甲 | 依相對 B 的增刪合併，結果移除甲並保留乙，不做整串聯集 |
| 確認人工清空／改日期與未完成網站操作衝突 | 人工整筆修正取代之前工作；其後新登記基於新版本接受 |
| 無法辨認快照先後、讀回不明或同狗對應不唯一 | 不自動覆寫格子，保留現況與診斷，重新取得可信讀值 |

人工刪名後再明確按溜了屬新操作，可重新加入；被取代的舊工作不得做到同樣效果。無法觀測到的「改後又改回」不能從相同字串推斷為新人工動作。方案 A 接受這項觀測限制及最後讀寫間隙風險，不要求測試證明任意人工同時操作皆不遺失；仍須驗證能觀測到的衝突確實會停止覆寫並重新比對。

### 通知、Cron 與預算

通知沿用專用驗證，不得接受外部請求直接指定格子值。收到通知立即啟動必要欄位比對，通知重送合併；失敗保留可供 Cron 發現的狀態。非今日欄位變化仍交給既有同步，不能因通知已處理今日狀態就漏掉狗清單修改。

提案 Cron 每分鐘執行，單輪最多派送 10 隻，讀表只選狗名、編號、日期、名單；主清單比對可用單份快照與按主鍵的差異查詢，不逐狗發出遠端請求。重試按 ADR 0017 的退避排程，不阻擋同輪其他到期工作。跨日工作保留到確認或被明確取代；完成狀態不能累積成每輪掃描負擔。請求去重至少涵蓋未完成工作的整個生命週期，已完成的識別需保留至原操作日期的次日結束；過期原日期請求拒絕，不能當新登記重放。

預演須把有效資料、待寫回狀態、投影、版本觸發器及索引成本算進去；遵守既有單次 500 列／帳號每日 20,000 列寫入預算及其設定方式。無變化不寫資料列或心跳列；必要派送狀態轉移另外計量。帳號分析不可用時沿用 ADR 0008 的單次門檻與警告，不把缺值當零。預算不足時維持待處理及小字，不先寫一半，不以重試繞過預算。

### 讀取與跨日

今日查詢使用包含有效日期、名單、必要上次溜覆寫及同步狀態的版本化資料包。版本、日期與內容一致，冷讀取不得逐狗掃 200 列；包超過分段門檻沿用既有分段。讀取中版本改變須重讀或回傳單一一致快照，不能拼接新舊分段。前端拒絕較舊版本回應，狗卡、詳細資訊、狗群與我溜過共用同一套接受規則。

今日有效狀態不能被狗清單舊日期／名單、localStorage 或舊 walkers 回應蓋回。既有端點若供其他功能使用，不整支刪除；移除的是手機拿它當今日正本的路徑。本機只記身分、偏好與送出中識別，不能自行認定已成功。

台灣午夜切換今天判定與讀取版本，不清空每隻狗的最新有效日期／名單，也不等待歷史交接才可正確顯示上次溜。前日未完成工作繼續保留；今天已有新版本就只派送目前目標。歷史資料仍依既有契約處理，但不得把試算表舊值回灌最新狀態。前次溜的復原資料由伺服器保存／查詢，不能要求手機保留昨天狀態才能跨日。

優先用既有 Worker API／D1 測試入口，替換試算表 adapter 控制讀回、延遲及失敗；從 API 結果、D1 有效狀態與試算表最後值驗收，不只驗內部旗標。前端沿用 today／registration 的狀態與整合測試，不另外建立平行狀態模型。

| 情境 | 驗收結果 |
|---|---|
| 原子提交中任一步失敗 | 無成功回應、無孤立工作或半份投影 |
| 同狗多人並行、重送、整群部分失敗 | 名單完整去重，逐狗成功／失敗可辨 |
| Google 失敗或回應遺失 | D1 已接受狀態保留；可查明、重試且不重複生效 |
| 登記後立即復原，舊寫回晚到 | D1 與試算表最終均為復原結果，舊版本不能復活名字 |
| 人工刪名／整格清空／改日期遇 pending | 符合三方比較；舊快照不蓋新操作，刪名不復活 |
| 人工修改發生在寫前再次核對之前 | 核對發現不同，該次不寫，將新觀測交給 Worker 重新比較 |
| 人工修改恰好發生在最後核對與寫入之間 | 屬方案 A 已接受的剩餘風險，不列「保證不遺失」斷言；仍驗證寫後讀回與結果記錄 |
| 他人剛改名單，另一人復原 | 復原拒絕，較新紀錄完整保留 |
| 跨裝置復原、從未溜過、午夜切換 | 符合 ADR 0016；日期、上次溜與歷史一致 |
| 昨天未寫回，今天已有新登記 | 網站與主清單只呈現今天的最新名單；昨天工作不能蓋回 |
| 人工把日期改早或網站復原 | 依新接受的版本顯示較早日期，不以日期最大值反駁修正 |
| 舊輪詢／舊 GAS 回應逆序抵達 | 不降低版本、不錯誤收起同步小字 |
| 通知遺失、重複或偽造 | Cron 補漏、重複不多寫、無效驗證拒絕 |
| 排序、同名狗、狗已移走 | 不寫錯列，不用模糊狗名猜測 |
| 無變動、預算不足、冷讀及資料包分段 | 無差異寫入為零；不半寫；計量含觸發器，讀取不依賴記憶體命中 |

既有實測只作證據基線：原型 CPU 最大分組 P99 10.591 ms，未通過完整正式管線門檻；不能把序列樣本 8.004 秒當人工改表上界。讀取方案若一包一段，手機每次最多版本一列＋包一列，30 人×15 小時×60 次＝27,000 次，手機部分設計推算為 54,000 列／日；不含通知、操作、分段、重試、Cron 及共用帳號基線，不能宣稱是整體實測上界。實作須列出這些項目的最壞工作量與停止條件，CPU 不合格先縮小單次工作，不追加開放式壓測。

## 派送順序、人工衝突與跨日

2026-10-21 接續 grill-with-docs：最新一次的可見行為與方案 A 已確認；下列為落實這些規則的工程方案，未實作、未補測，不將產品決策確認當成工程驗證。

### 同狗寫回由接收端取得最新目標

Worker 派送的是狗識別與可追查的派送識別，不能讓 Apps Script 直接使用延遲請求攜帶的舊整格目標。Apps Script 在 script lock 內向 Worker 的機器驗證端點取得 D1 當下最新的有效目標，再直接讀格子、比較、寫回及回傳讀值。取不到 D1 或存在未解衝突就不寫，留待重試。此端點只供既有 Apps Script 使用，不是新增通知服務。

協定順序：先取得鎖及直接讀值，再將讀值送交 Worker 比較一致基準、已派送但未確認的目標與最新 D1 狀態。Worker 以預期版本接受可辨識的人工修改，回傳目前版本、目標及一次派送識別。Apps Script 寫前再次讀取日期／名單；與這次比較輸入不同即停止寫入，回傳新觀測讓 Worker 再處理，不在同一呼叫無限重試。相同才寫入、讀回並報告。D1 只在派送識別、目前版本與讀回結果都吻合時記為一致。若前輪結果未知，且讀值可同時解釋為人工修改或前輪中間值，停止覆寫，先保留現況與未決狀態，不能任意選一種解釋。

已觀測到的人工改名單／日期納入 D1 後，所有還未執行的舊目標失效；不重送舊整格目標。例：表內甲被人工刪除，而網站另加乙，只合併可辨識的變更，最新結果保留乙、移除甲。人工清空整筆時沿用既定整筆修正規則，不因舊工作含甲而補回。若無法安全判斷，維持失敗重試小字並記可追查原因，不另造「成功」或假裝 Cron 重跑必然解決。

因此，「登記」的通知晚於「復原」通知到達，也只會取得當下的復原目標。所有程式派送使用同一 Apps Script 鎖與入口；不准舊版寫入端點繞過。若新操作恰好在接收端取目標後才被 D1 接受，先完成的舊目標只能視為中間狀態；版本不同的讀回不能標記目前版本同步完成，下一次仍取得最新目標補正。這保證的是程式寫回依序追上 D1，不承諾試算表完全沒有短暫中間值。

Apps Script 的鎖不阻擋人工改格。已直接觀測到的人工刪名／清空先提交 D1 新版本，才能取得後續寫回目標；比對不符時不盲寫。人工恰好在最後讀取與寫入之間改格，仍可能被覆蓋，僅靠現有鎖、讀回或 onChange 通知不能保證找回未被保存的人工值。K 在明確說明 A／B 差異後選 A：保留直接改表，接受此項剩餘風險。這次選擇不等於放棄衝突檢查或忽略人工修正；不新增試算表保護，也不再將絕對零遺失列為方案完成門檻。

結果未知的工作由下一輪先取同鎖直接讀值，不能照舊 payload 重送。讀到目前目標且版本一致則確認成功；讀到已知較舊派送結果則仍保留最新工作；辨認為新的人工變更則先接受修正、使舊目標失效；無法分類則保留待處理及原因，下輪重新比對，不用固定秒數把它強制判成人工值或允許覆寫。網路恢復或現況變得可辨識後才繼續，不假稱所有未知結果必然在固定時間內自動解決。

### 每隻狗保存最新狀態，午夜不搬移

在接受操作的原子交易中，保存每隻狗最新有效日期／名單、單調版本、必要的復原前值及待寫回目標。今日清單由最新日期是否為台灣今天判定；上次溜直接取最新有效日期，不等午夜搬資料。歷史依既有規則保留，不以「每次網站操作永久新增一份每日歷史」作為這次功能的額外前提。

午夜只切換今天判定，不刪最新狀態、不刪待寫回。前日工作重試時，先看這隻狗目前最新的有效版本：今天已有新登記，就只把今天的日期／名單寫到主清單；前日工作以被新版本取代結束，不能把主清單改回昨天，也不能假稱昨天的值曾在試算表確認成功。若今天尚無新登記，昨天仍是上次溜，照原日期寫回。「最新」以被接受的版本判斷；人工改早日期與復原可產生較新版本但較早日期，不能用日期最大值阻止它。

K 本輪已確認「網站只要有最新的」：最新狀態只呈現最新一次，不額外並列昨天甲與今天乙，不以此刪除既有歷史，也不新增歷史分頁或突破 ADR 0006 寫入範圍。既有歷史資料不回填、不重建。正式 schema 與歷史同步需明列各自擁有的欄位與日期，舊同步不得寫回本路徑已接管的最新狀態。
