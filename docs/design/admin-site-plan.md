## 已確認的邊界

- 同一 repo，獨立管理 Worker 與網址，共用既有 D1、必要 R2 與資料操作模組；不建第二套正式資料庫、不新增 Cron。
- 使用 Cloudflare Access，第一版單一管理者角色。ADMIN_KEY 維持機器用途，不能送到管理站前端。
- Tabler 免費 Bootstrap 後台樣式，原生 ES module、左側導覽、可搜尋／篩選／排序的表格，逐筆或逐隻狗儲存。
- 「功能顯示」與「志工可編輯」分開。志工編輯權限各項獨立，初始沿用現況；管理者不受志工編輯開關限制。
- 試算表送入的欄位第一版只讀。不做任意 SQL、通用資料表編輯、批次修改、自動復原。
- 網站更新沿用靜態版本紀錄唯讀；資料編輯可查改前／改後。經驗證的管理者登入識別只在後台讀取。
- 第一批功能顯示開關：活動紀錄、資料檢查、更新紀錄，各自控制。不擴大成整個分析頁、圖鑑或找狗的顯示開關（K 回答 Q2）。
- 首批狗資料編輯：介紹、休養、固定照顧、舊編號、出入所紀錄、照片、性別補正。性別補正為新增管理者能力，第一版不新增志工性別編輯入口；既有七項志工編輯開關維持已確認範圍。

## 最小架構

管理瀏覽器 → Access → 管理 Worker（專屬 assets、同 origin `/api/manage/*`）→ 共用資料操作模組 → 既有 D1／必要 R2。

志工 Worker 維持既有 API／GAS／Cron；兩個 Worker 共用同一份欄位驗證、版本比對、稽核及設定讀寫程式，沒有複製的第二套業務規則。管理前端不跨 origin 呼叫志工公開 API 來冒充管理者，也不直接連 D1。管理 Worker 不公開機器用的搬遷、任意同步或寫回重試入口。

管理站獨立部署，必要共用前端檔由同一份來源產出到管理 assets；不靠 import 志工 app 啟動整站。共用模組改動需測兩個入口。

Access 驗證採伺服器驗證簽章、issuer、audience、期限的 JWT。不能只信 email 標頭；必測無 token、過期、錯 audience、偽造及替代網址繞過。管理入口不向志工 host 洩露；workers.dev／版本預覽網址同樣受保護或關閉。寫入檢查同 origin／CSRF、方法、內容型別、欄位白名單及大小。Access 設定缺失時拒絕管理存取。

官方 Workers 文件指出 Static Assets 的內部 router 不傳遞 `ctx.access`，因此本案不能只依賴它。設定與測試說明須對齊實作時支援的 runtime。

首批範圍已依 Q8 確認。D1 是資料保存正本，不等於所有欄位都能任意人工改；欄位寫入權仍依表中來源限制。網站獨有欄位不送回試算表；GAS 更新不得覆蓋介紹、休養、固定照顧、性別等資料。舊編號涉及兩個寫入來源，要測 GAS 再入所與人工拆除競爭。

性別補正的資料契約：目前在所讀取仍取 `v3_sheet_main.sex`（`worker/src/compact.js`），GAS 新增主清單列會從 `v3_dogs.sex` 帶值、既有列更新不含性別（`worker/src/dog-list.js`）。實作前先列兩處舊值差異，不自動以空白覆蓋有效值、不憑名稱猜性別；不一致由管理者逐隻確認。將目前性別的在所／離所／圖鑑等讀取統一取狗正本，離所 `last_sex` 僅保留當時快照、不批次重寫歷史；沒有已確認正本時顯示待確認。新增性別 API 以永久 ID、白名單值、條件寫入與同交易紀錄保護；包含無編號狗，禁止用修改編號冒充修改性別。資料包觸發器／失效需覆蓋在所與離所，承接 #548／#549 的最新結構，不平行另做 schema 精簡。

## 設定與修改一致性

- 最小 D1 設定是一份白名單設定＋revision；只接受已知 boolean，無分群、實驗或 Statsig。保留原本 `SITE.d1WalkAccept` 與 Worker 同步／重試開關，不放進人用顯示控制。
- 七項志工編輯開關：介紹、照片、休養、活動、固定照顧、出入所紀錄、舊編號。初始化沿用原有開放狀態；設定結構與遷移方式要和 #521 的 schema 套用路徑對齊。
- 顯示關閉只控制畫面，API 讀取與後端照常；編輯關閉由志工寫入 API 檢查，舊頁直接送出也拒絕。管理站可繼續編輯。不得攔截登記、復原、GAS 機器輸入、同步或重試。
- 活動紀錄、資料檢查、更新紀錄關閉時，隱藏各自志工入口；直接開啟既有連結顯示未開放。管理網站仍可使用各項功能。其他分析資訊與圖鑑、找狗維持現況；更新紀錄開關涵蓋志工端的網站更新與資料編輯兩個分頁。
- 新修改在伺服器接受時核對編輯開關，不靠前端快取授權；已接受的操作不因後來關閉而取消。設定讀取失敗時不猜測授權，拒絕新的可選編輯並提供重試；核心操作照常。
- 設定讀取併入既有初始化／更新節點、使用版本／快取；不新增固定輪詢／Cron，不在每一列或每隻狗迴圈查設定。下次讀取設定後更新畫面，舊畫面送出仍由伺服器攔截。
- 每次資料寫入都帶 expected revision 或改前值，使用有條件寫入；多人先後儲存或 GAS 剛換編號／離所時，後送者回 409、保留草稿並顯示差異，不能默默覆蓋。
- 可直接 D1 交易的修改：欄位變更、revision、改前／改後、操作者來源、時間、請求識別與紀錄在同一交易完成。不能先成功再盡力補紀錄；無實際差異不產生資料與紀錄寫入。
- 管理者身分從 Access 取得；志工沿用自行選名字，紀錄必須分辨兩種可信程度，不假稱志工已登入。管理身分資料只由受保護的查詢回傳，公開紀錄使用不洩露登入資訊的標示。
- R2 與 D1 不能跨資源原子交易。照片替換先保留舊照片、完成新物件儲存，再以版本比對提交 D1 引用與紀錄；失敗保留可重試／追查狀態，不顯示成功或留下新舊版本混配。沿用既有垃圾桶規則，不新增清理排程。
- 首批支援的寫入全部走共用服務，包含仍開放的志工 API，避免後台有衝突保護、志工入口卻仍可蓋掉資料。遷移可分 PR，但某類管理編輯啟用前兩入口都須符合契約。

## 活動與資料檢查

- 使用現有活動 ID，不匯入第二份。實作前讀既有活動，核對使用者所指四場的日期／類型／狗名；本次 repo、Issue 與紀錄未能證實實際四場，測試 fixture 不是證據。若不足四場或重複，先列差異，不自動新增或合併。
- 活動維持目前日期、兩種類型、出席狗及未對應名字，沿用 revision；不擴大為報名／通知系統。
- 資料檢查共用現有缺照片、缺介紹、缺編號、缺性別、缺日期等規則；加 #518 的「網站有、試算表沒有」及掃描時間。過期與無法讀取分開標示，不誤報為缺資料。
- 優先用已載入資料與照片中繼資料檢查，不對每張表格每列額外查 D1／HEAD R2；照片實物檢查須明確按需、限量，不背景巡掃。
- 問題清單不自動刪狗、記離所、合併或修正。#173 的人工確認處置另評估，不能沿用其舊 repo JSON／通關碼方案。

## 分期與驗收

每期獨立 PR，先草稿；檢查完成由 K 決定合併。正式環境設定、schema 套用及部署另行授權。

| 階段 | 可獨立交付內容 | 必要驗收 |
|---|---|---|
| 1 管理網站框架 | 獨立 Worker／assets、Access、共用模組接縫、唯讀狗清單、左側導覽與空／錯誤狀態 | 無憑證或錯 token 全拒絕；靜態頁／API／替代網址無繞過；搜尋篩選排序正確；只連既有資料，不增加 Cron |
| 2 功能開關 | D1 設定、revision、後台切換、志工 UI 顯示與七項編輯 gate、設定編輯紀錄 | 預設行為一致；關閉後舊頁請求遭拒；管理者仍能改；直接網址正確；兩人改設定回 409；登記／復原／同步／重試不受影響 |
| 3 狗資料編輯 | 介紹、休養、固定照顧、舊編號、出入所紀錄、照片、性別補正；共用驗證、條件寫入與可靠紀錄 | 非白名單／無效欄位拒絕；多管理者／志工競爭、GAS 更新、換編號／離所、紀錄失敗、照片中途失敗測試；性別舊值差異、無編號狗、在所／離所／圖鑑讀取與版本失效；修改可追查且網站資料包可見 |
| 4 其他功能搬移 | 活動、資料檢查、更新紀錄；承接 #518 | 四場核對後沿用同 ID；活動 revision 衝突；未對應名字保留；讀取失敗不當缺資料；紀錄可分頁搜尋篩選，管理身分不出現在公開 API |
| 5 清理 | 逐項清理被取代的志工管理入口／重複 UI，文件與 ADR 對齊 | 每一項清理先列前後對照；仍開放的志工編輯有入口；舊連結／本機資料／登記復原不退化；不刪正式資料或後端服務 |

測試僅使用本機／隔離測試資料，走 `scripts/check-local.ps1`；每張實作 PR 跑適切測試及必要完整檢查。不用唯讀 PR 預覽驗收管理寫入，不重置共用測試站或觸發正式同步。測試 D1 的使用須先協調，不能拿正式 D1 當可寫測試庫。

效能驗收：列出一次載入／搜尋／儲存的 D1 查詢與讀寫列數，含版本觸發器；表格不逐列請求、搜尋節流且有界分頁、不新增 Cron；設定無變動與資料無差異不寫。沿用 ADR 0008 寫入預算，不另立已取消的 CPU 10 ms 門檻。

- #474、#550：狗群只能由試算表維護與結構變動驗證；不恢復管理站狗群寫入。
- #173：人工確認機制後續評估，不自動變成本次已核准功能；#143 舊後台不重開、不原樣搬用。
- 依 `docs/agents/agent-split.md`：Worker／網站實作預設 Claude，scripts 獨立腳本才給 Codex。地基契約由參與決策者把關；不在開票時自動指派帳號或啟動實作。
- ADR 0020 記錄重新開放獨立管理網站、保留可控制的志工協作編輯，修訂 ADR 0004 的「不做後台」與無條件開放範圍；不撤銷既有資料與機器金鑰規則。這是已確認的目標設計，現有程式尚未套用。
