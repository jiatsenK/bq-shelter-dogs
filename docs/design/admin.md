## Overview

Operate 模式。K 已選定 Tabler 免費後台、左側導覽、原生 ES module 及唯讀狗表；採直接實作，不另開視覺提案或產生 mock。品質基準為 Tabler 的成熟表格與原生表單：資訊可掃讀、來源清楚、錯誤可重試。#564 做唯讀狗表，#565 加功能管理頁（`settings.html`），#566 加逐隻狗編輯；活動、資料檢查、更新紀錄在 #567。#624 改成右側編輯抽屜、側欄分兩組（見最後一節，與前面各節衝突時以 #624 為準）。

## Colors

白色導覽與表格、淺灰頁底；單一藍色用於當前導覽、排序、焦點與主要按鈕。文字／placeholder 維持可讀對比，狀態用文字表達，不只靠顏色。

## Typography

沿用 Tabler 系統無襯線字體及固定 rem 字級；不載外部字型。表格使用等寬數字，永久 ID 可換行；狗名和編號優先掃讀。

## Layout

桌面 216px 左側導覽，分「資料」「志工網站」兩組（#624），內容留白 32px。標題在左、重新讀取（次要按鈕）與志工開關標記在右；來源說明、搜尋／篩選、結果數、資料表、分頁依操作順序排列。900px 以下導覽移到上方橫向捲動，表格在獨立容器水平捲動，不能讓整頁橫向溢出。

## Shapes

使用 Tabler 原生表單與按鈕，照片 56px、圓角 4px。簡潔邊框區分欄列，不加裝飾圖示或背景動畫。

## Components

表頭按鈕排序、`aria-sort`、搜尋標籤、狀態 live region、鍵盤焦點、跳到內容及可聚焦捲動區。介紹以原生 details 展開全文；試算表備註以文字顯示。支援讀取、無資料、無符合條件、格式錯誤、權限失效、照片讀不到、重試與停用按鈕。

## Do's and Don'ts

試算表來源的目前編號、狗名、籠位與備註保持唯讀；網站維護欄位依已開放範圍逐隻編輯，不提供任意 SQL 或批次操作。狀態以主清單與離所紀錄判斷，待核對不等於離所；照片 metadata 不等於檔案存在。保留志工站的既有設計與行為。

## 功能管理（#565）

`admin/public/settings.html` 延用同一側欄、字體及原生 Tabler 表單，分成功能顯示與志工可編輯兩組。checkbox 僅改草稿，按「儲存設定」才送出；無差異停用。重新讀取、載入中、儲存中、失敗與版本衝突都有文字狀態；衝突保留草稿，重新讀取後才可再存。狗資料仍唯讀，管理狗資料編輯不在本階段。功能契約與正式步驟見 [操作說明](../operations/feature-settings.md)。

## 狗資料編輯（#566）

延伸既有狗表，在單隻狗的編輯區逐項處理介紹、休養、固定照顧、出入所紀錄（含編號，#639）、照片與性別補正。一次只儲存一項，先顯示改前／改後；沒有差異時不送出。照片顯示新舊圖，垃圾桶先預覽再確認復原，每筆寫台灣時間的換掉時間和哪一天清理會刪掉；#566 以前用編號（含舊編號）記的備份也列出來；出入所紀錄是一張表單：每列編號（查不到留空）、入所日、出所日、原因，不讓使用者編輯 JSON。

（#624 起不再用項目選單切換，見最後一節。）儲存中停用編輯，失敗與 409 保留草稿；重新讀取取得最新版本後，保留輸入並要求重新預覽。成功只在伺服器確認交易後顯示。

性別使用公／母／待確認，說明舊試算表副本已停止維護，供管理者以狗正本逐隻核對；不依名字推測。試算表欄位仍只讀；管理者不受志工編輯開關限制。既有 Tabler 色彩、字體、側欄、手機配置保持不變；操作與正式步驟見 [狗編輯說明](../operations/dog-editing.md)。

## 狀態分頁與合併重複的狗（K 2026-10-26）

狗表上方四顆分頁按鈕「在所／已出所／待核對／全部」，各帶數量，預設在所；用 `aria-pressed` 標目前分頁、選中的用主色。清除條件不換分頁。不在所的狗在編號欄顯示最新的舊編號並標「舊編號」，狗名下寫離所日期與原因或「待核對」。

編輯抽屜欄位下方「合併重複的狗」（不算進抽屜的草稿與儲存）：下拉選另一隻（同名排最前）→「預覽合併」顯示留下／併掉／搬過去／兩邊都有的筆數，以及不採用的介紹、休養、出入所內容→紅框「合併」→再按一次實心深紅「確定合併：刪掉…」才送。失敗收起預覽、要求重新預覽。成功後關抽屜、重讀狗表，狀態列寫併到哪一隻。修改紀錄頁 merge 列有同樣兩次確認的「取消合併」。狀態分頁存在網址 `status`（預設在所不帶），取代舊的 `presence`。待補清單加「可能重複」卡片，連到狗資料表並帶 `query`、`status=all`、`dog`（直接開不在所那隻的抽屜）。

## 活動紀錄、資料檢查、更新紀錄（#567）

側欄各項都可進入，沿用同一 Tabler 版面、表格、狀態文字與 390px 不整頁溢出。志工網站目前的顯示／編輯開關原本是頁首下方一行說明，#624 改成頁首右側小標記。

活動頁：清單在上方可搜尋、依類型篩選；編輯區一次一場，日期、類型、出席狗逐隻加入或移除，未對應名字以「未對應」標籤保留。改前／改後即時顯示，沒差異不能存；409 保留草稿並要求重新讀取，讀到最新版本後再確認。刪除要按兩次（刪除這場→確定刪除），刪除按鈕用深紅以符合 AA 對比。

資料檢查：三張卡片各自讀取。#518 清單顯示記錄時間與最後掃描時間，過期、讀取失敗用紅字，文字明說「不代表沒有差異」。完整度項目用原生 details 展開狗名，0 隻的項目淡色顯示。「排程」卡片（稽核第 5 項）一張小表列寫回重試、保險掃描、照片垃圾桶的頻率、最後一次跑完的時間與狀況；最近失敗、過期、讀不懂用紅字，讀取失敗明說「不代表排程有在跑」。

更新紀錄：資料編輯的篩選列放在表格上方，任何條件都交給伺服器查全部紀錄，文字輸入節流；改前／改後以預先換行的淺灰區塊顯示，管理網站來源顯示登入帳號。網站更新列在下方，唯讀。契約見 [操作說明](../operations/admin-records.md)。

## 編輯抽屜與兩組側欄（#624）

依 2026-10-26 `/impeccable critique`（23/40）與 K 選定的方向。原則：不管控，只要可還原（修改紀錄看得到改前）。

**側欄**：六頁同一份，分兩組。「資料」：狗資料、活動紀錄、待補清單（原資料檢查）。「志工網站」：志工網站設定（原功能管理）、修改紀錄（只剩資料編輯）、網站更新（`releases.html`）。組名是小字灰色標題，目前頁用藍底＋`aria-current`。拿掉 sidebar-note。900px 以下兩組橫排在同一條可捲動列。各頁「重新讀取」一律次要按鈕，主色只留給新增活動、儲存。

**志工開關標記**：活動紀錄、待補清單、修改紀錄、網站更新的頁首右側一顆膠囊連結，寫「志工網站：…顯示中／已隱藏…」，連到志工網站設定。圓點綠＝全開、橘＝有關閉、灰＝讀不到，狀態一定寫成文字。和 `.source-note`（來源說明）分開。

**修改紀錄隱藏測試紀錄（#671）**：每列第一欄勾選框，表頭勾選框選這頁全部。狀態列下面一排：「隱藏所選（N 筆）」、開關「顯示已隱藏（共 N 筆）」，開關打開時多一顆「取消隱藏所選」。被藏的列打開開關後淺灰底、時間下面「已隱藏」標籤，「取消合併」照常可用。只存這台電腦的瀏覽器（localStorage `bq-admin-hidden-edits`），後端不知道；畫面上過濾，某頁可能少於每頁筆數，不從下一頁補。瀏覽器儲存不能用時照常顯示，提示記不住。

**狗資料表**：「編輯」在第一欄，水平捲動時黏在左邊，手機不用橫捲就按得到。抽屜開著的那一列淺藍底，按鈕變實心藍。維護狀態篩選分組：待補（有待補資料、缺介紹、缺照片、缺編號、性別待確認）、試算表（編號看不出入所日期、缺溜狗日期）、照顧（休養中、固定照顧）。篩選條件寫進網址；`?dog=永久ID` 進頁就開那隻的抽屜。

**抽屜**：右側固定、480px 寬；1200px 以上內容區右邊讓出抽屜寬度，表格留在原位。不是 modal：表格仍可點，換狗前若有沒存的修改，第一次只提醒、再按一次才放棄（關閉、Esc 同樣）。由上而下：
- 頭：照片 72px、狗名（開抽屜時焦點在這）、編號 · 籠位、永久 ID、「關閉」。
- 狀態列（淺灰底）：讀取中、儲存中、成功、失敗都在這，打開就看得到；409／失敗時旁邊出現「讀取最新資料並保留草稿」。
- 六個欄位全部展開：介紹、休養、固定照顧、性別補正、出入所紀錄、照片（#639 起「所有編號」併進出入所紀錄）。欄名右邊是現值（字數、休養至、有／沒有、出入所筆數與編號），缺的顯示紅字「待補」（出入所紀錄沒有任何編號＝缺編號）；改過的欄名後面加藍字「・已改」。
- 低風險（介紹、休養、固定照顧、性別）改完直接可存，下面灰底一行「改前→改後」：介紹只標改動那段（刪掉的紅底刪除線、加的綠底），前後各留 16 字上下文；其他欄位是舊值→新值。
- 高風險（出入所紀錄、照片）要按「預覽改前／改後」；預覽後再改就要重新預覽。照片預覽左右並排舊新圖。
- 底部固定：「改了 N 項：…」與還缺什麼（例如「編號要先按預覽」、休養日期範圍），「儲存」（主要）與「存並開下一隻」（沒改時叫「下一隻」）。
- 休養日期 min＝今天、max＝今天＋180 天；勾「結束休養／不設定休養」時日期與原因停用。介紹 maxLength 1000，下面即時字數。

**儲存**：照欄位順序一欄一筆送出，每欄帶上一筆回應的 revision；後端契約不變。成功後只換那一列，不重讀整張表。中途失敗或 409 就停：已存的寫明、失敗的寫原因，還沒存的草稿全部保留。「存並開下一隻」依目前篩選與排序找下一隻（跨頁會換頁），成功訊息帶到下一隻的狀態列；最後一隻時關閉並在表格狀態寫明。關閉後焦點回原列的「編輯」。

**手機（900px 以下）**：抽屜全寬全高、背景頁不捲動，底部按鈕各占一半、至少 44px 高。

**待補清單**：主清單完整度放第一張卡，用語和狗資料表一致（缺編號、編號看不出入所日期、缺溜狗日期、性別待確認、缺介紹、缺照片）。展開後有「在狗資料表看這 N 隻」連到已篩選的表，狗名直接連到那隻的抽屜。

### 第二輪評審修正（2026-10-26，評審 27/40）

- **存並開下一隻照開抽屜時的順序**：開抽屜時記下當時篩選＋排序的清單，存完從這隻的位置往後找，跳過已經不符合目前篩選的狗。剛補完介紹的狗掉出「缺介紹」也不會跳回第一隻。清單走完就關抽屜，表格狀態寫「這份清單處理完了」。
- **抽屜開著時表格切精簡欄**：只留編輯、照片、編號、狗名、維護狀態；籠位、性別、介紹／備註、永久 ID 隱藏，表格不再撐到 1160px。1200px 以上篩選列固定一行（各欄等比縮，不換行）。開抽屜時會補捲動，讓被點的列留在原本的螢幕位置，看不到時才捲進來（含 `?dog=` 進頁）。901–1199px 內容也讓位，至少編輯到狗名看得到，維護狀態在表格自己的捲動區裡。
- **焦點與 Esc**：存完（成功或失敗）焦點移到抽屜狀態列（可聚焦），不會掉到 body。Esc 監聽掛在 document，焦點在表格也關得掉；頁面有其他對話框開著時不搶。
- **出入所表**（#639，ADR 0021）：一個編號一列，有編號的入所日跟著編號（唯讀）；欄位順序：編號、入所日、入所原因、離所日、離所原因。有離所紀錄的那列離所日唯讀、沒有離所原因欄，註明「離所日和離所原因照離所紀錄（認養）」；入所原因每列都能填（K 2026-10-26）。目前編號那列、有離所紀錄那列沒有刪除鈕。「新增一列」填編號就是補舊編號。原值和草稿都只比編號、日期、兩個原因，後端帶的離所旗標不算改了。
- **選取列對比**：被選列的「編輯」實心藍白字，hover／focus 一樣，並關掉 Tabler 的 0.3 秒顏色過場（剛選取時停在淺色，評審量到 2.1:1）。淺藍底上的次要小字改用 `--admin-muted`（約 5.5:1）。測試逐一量被選列文字的實際底色對比，都要 ≥ 4.5。

## 網站連結（K 2026-10-26）

側欄「志工網站」組最後一項「網站連結」（`links.html`）：一張卡片、一張表，列是正式版／測試版（測試版旁淡紫「測試資料」標籤），欄是志工網站、試算表、Apps Script（GAS）。有網址就顯示主機名稱連結（新分頁開）、下面小字完整網址；沒設寫灰字「還沒設定」與要設哪個 GitHub Secret。900px 以下表格改直排，欄名寫在網址上面，不靠橫捲。網址不寫在 repo（公開），部署時由 `deploy-admin.yml` 帶入：網站網址用 `WORKERS_SUBDOMAIN` 組，試算表是 Secret `SHEET_URL`、`TEST_SHEET_URL`，GAS 是 Secret `GAS_URL`、`TEST_GAS_URL`；API `GET /api/manage/links` 只回 https，試算表只准 `docs.google.com`，GAS 只准 Google 網址。
