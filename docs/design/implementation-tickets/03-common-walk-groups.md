## What to build

將常遛狗群定版接上真實全量群、既有編輯與溜狗登記流程：一次一群，密集交錯斜照片卡；左右滑動整群，其他群縮小、較淡浮在後景。平常整群登記，少數沒溜才在原卡片上排除。

### 已鎖定的外觀

- 保留原站綠白／灰綠配色、系統繁中字體與第一票的共用導覽；主頁不重畫。
- 狗卡只有籠號、照片、姓名。籠號放右上獨立窄邊，淡灰綠底／深灰綠字，不再深綠實心，也不蓋照片；名字在下緣，不在底下重複姓名。
- 每群保留一張同形狀的「＋」空白卡加入狗；另有「＋狗群」。後景只顯示狗群輪廓，不顯示後景新增卡。
- 一群兩隻與十隻用同一套卡片尺寸與排列規則，少數群不放大填空；姓名比籠號更強，不靠縮成難讀小字塞內容。
- 日期不塞回卡片。群名下用白話，資料同日時如「10 隻今天都溜過」；資料不同時如「捷運站昨天溜過；甜甜前天溜過」。有明確對象，個別狗可查精確日期；長摘要可收合，但不能退回只有天數與隻數的統計。
- 觸碰放大、前後群交換有連貫動態，可中斷、反向；尊重減少動態效果，不做自動循環漂浮、不新增動態套件。

### 已鎖定的操作

- 主要動作是「整群溜了 · N 隻」，次要動作是「有狗沒溜」，不並列同權重的單隻按鈕。
- 例外模式在原狗卡排除本次未溜者，可恢復、取消；主要動作改「登記其餘 N 隻」，全排除時禁用。只留一隻也可登記。
- 本次排除不能永久移出群、修改休養設定或誤套到其他群。換群與取消重設本次排除。
- 每群「＋」加入成員、「＋狗群」建立群；沿用既有群欄位、身分與 API。不因換外觀漏掉原本移出成員等管理能力。
- 群內滑動不能連帶切主分類；點排除／新增、上下捲動不算換群。鍵盤也可操作。

## Acceptance criteria

- [ ] 由真實具群名的群資料讀取所有群；群識別不靠畫面索引或重複名稱。不得把狗的相鄰關係自行推成命名群，也不得把快照兩群或 11 群寫死。
- [ ] 每一群皆可到達，群名與數量正確；兩隻、十隻、空群、缺照片與長名字依同規則可用，沒有照片上文字遮擋、重複標題或無效新增卡。
- [ ] 群名下的白話時間依台灣日期、狗的真實最近紀錄與既有今日溜過資料更新；多日期明確對應到狗，未知／失敗／無紀錄不冒稱已溜。同日不推論同一次或同一人整群出勤。
- [ ] 整群、排除／恢復／取消、只留一隻、全排除、換群後重設皆能操作；mock API 捕捉到的送出名單與畫面完全相符。
- [ ] 真實登記沿用現有身分、休養／不可帶出、台灣日期、寫入中、成功／失敗、重試與今日溜過整合；不能沿用原型的假成功。部分失敗不得宣稱全部成功。
- [ ] 加狗、重複加入、建立新群與既有移出流程，沿用群 API 與 ADR 0006；成功以讀回結果更新，失敗保留可重試內容，不寫入未授權欄位／分頁。
- [ ] 觸控滑動、邊界、拖動取消／反向、鍵盤、減少動態效果與外層手勢隔離通過；照片辨識、焦點及排除狀態清楚。
- [ ] 手機 320／390px 與桌機回歸，互動區至少 44×44px、日期摘要不溢出、安全區正確；其他頁與舊狗群入口可用。
- [ ] 使用既有瀏覽器流程＋mock API 驗證整段流程，相關 Worker 契約測試按改動補齊；AGENTS Node／網頁測試、適當 code-review 通過。測試不寫正式資料。
