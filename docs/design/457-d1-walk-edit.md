# #457 名單修改與復原先存 D1

依據：#457、#456；固定規格 `444c33e:docs/design/441-d1-walk-sync-spec.md`、同版 ADR 0017 及 ADR 0016／0004／0006／0008。比較基準 `2701767`。

## 接受契約

- 沿用 `POST /api/walk` 單狗請求。`edit`／`undo` 和 `walk` 一樣帶 `requestId`、台灣 `operationDate`；修改與復原另帶 `dogs[0].expectedVersion`（非負安全整數，尚未接管為 0）。
- `edit.walker` 是完整目標名單，`edit.editor` 是手機選好的操作者；`undo.walker` 是操作者。均查既有固定身分，不建立或合併人。空名單不能當 edit，最後一人改走 undo。
- 只修改最新有效日期為台灣今天的紀錄；undo 另外要求目前只剩一人，任何選好身分的人皆可操作。多人沿用逐名移除，每次 edit 僅接受觀測到的版本。
- 前次日期／名單只取伺服器保存值；首次接管今天既有紀錄時依 ADR 0016 查 D1 歷史，從未溜過則空白。手機傳來的 prev／wrote 不作為新協定的依據。
- 衝突回 HTTP 409、`source:d1`、逐狗 `status:changed`、目前 `version/current` 與一致讀取快照；前端更新現況，不自動重放。預期版本在按下操作時取得，不因佇列等待或重試改用較新版本。
- 修改成功 status 為 written；復原為 restored。有效狀態、請求結果、舊工作取代、新待寫回、投影及 `v3_edit_log` 同一 batch 提交。編輯紀錄失敗整筆回復；一般登記維持不新增編輯紀錄。

## 顯示與寫回

沿用共用 `walk-registration`，單狗修改與復原使用 D1 路徑；D1 接受前保留原狀，接受後立即反映，狗卡、詳細資訊及狗群沿用同步小字，不宣稱試算表已寫入。資料包尚無該狗時，衝突結果仍可更新顯示。復原後上次溜可變早，不取日期最大值。

未查明請求保留原識別、原日期、版本及內容；重開與重試不製造新復原。若前次待查要求與本次動作不同，只查回前次結果並要求重新確認，不把前次登記成功誤報成本次復原成功。

寫回沿用 #456 的同鎖接收端取最新目標及版本條件回執。延遲喚醒只取得目前復原目標；可信舊回執最多記下中間值，不清除新工作、不復活名字。Google 未知結果與人工衝突沿用停寫／重新比對，方案 A 剩餘風險不變。

`SITE.d1WalkAccept` 仍預設 false；本票不切換正式入口、不改 schema 或 Apps Script 設定、不部署或遷移。整群新協定、Cron 重試及完整人工比對由對應子票延伸，本機 UI 測試覆寫設定驗證單狗路徑。

## 本機差異寫入預演

`node worker/test/walk-cost-preview.mjs` 使用合成資料與記憶體 SQLite，不呼叫正式服務。

| 情境 | SQLite 寫列（含 guard、預算及投影／版本觸發器） | 保守預算保留（含索引） |
|---|---:|---:|
| 修改名單 | 11 | 40 |
| 復原 | 11 | 40 |
| 同一修改／復原請求重送 | 0 | 0 |
| 舊版本衝突拒絕 | 0 | 0 |

整合主線 #459 後，一般登記仍為 9 列／保留 32，派送失敗及留存為 13 列，整條派送協定保留 96；獨立目標及回執取得各保留 16（同派送已預付則不重複保留）。無差異掃描及未到期重試為 0 列。若每日 100 次修改／復原，接受部分保守保留 4,000 列，另加實際派送／確認／重試與帳號其他工作；這是情境估算，不是正式日用量或 CPU 驗收。單次／每日預算沿用既有設定，查不到帳號分析會警告，不把缺值當零。

整合基準為 `07dbffd`，保留原始審查起點 `2701767`。#459 同日人工改名單時保留原本的復原基準，不能把今天被移除的名字當成前次；undo 亦只採用今天以前的保存日期，否則回查 D1 歷史。回歸測試經排程直接讀表納入人工修改，再呼叫復原 API，確認日期回到原先 10/1、名單空白，後續排程寫回一致。

測試邊界已由 K 確認：Worker 修改／復原 API、寫回目標／回執 API、前端操作流程。採真 SQLite 交易、可控時間及 HTTP 邊界；涵蓋跨裝置、從未溜過、歷史名單、多人移除、版本競爭、原子失敗、午夜、遺失回應、逆序派送／回執與手機／電腦操作入口。沒有獨立 TypeScript typecheck 設定，使用 JS 語法檢查與既有測試。
